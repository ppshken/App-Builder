# App Builder

เครื่องมือสร้างเว็บแอพแบบ No-code ภาษาไทย สำหรับใช้งานบนคอมพิวเตอร์ของคุณเอง เริ่มจากกำหนดตารางและคอลัมน์ แล้วสร้างหน้ารายการ ฟอร์ม และรายละเอียดจากข้อมูล

ข้อมูลและการตั้งค่าแอพเก็บในฐานข้อมูล SQLite ชื่อ `data.db` ส่วน GitHub เก็บเฉพาะโค้ด ไม่รวมข้อมูลจริง บัญชีผู้ใช้ ไฟล์สำรอง หรือรูปที่อัปโหลด

## สิ่งที่ต้องเตรียม

- Node.js พร้อม npm — สภาพแวดล้อมที่ใช้ทดสอบโปรเจกต์นี้คือ Node.js 22.12.0
- Git หากต้องการดาวน์โหลดและอัปเดตด้วยคำสั่ง หรือดาวน์โหลด ZIP จาก GitHub แทนได้
- อินเทอร์เน็ตสำหรับติดตั้งแพ็กเกจครั้งแรก

ตรวจว่าเครื่องมี Node.js และ npm แล้ว:

```powershell
node --version
npm.cmd --version
```

ตัวอย่างคำสั่งด้านล่างใช้ Windows PowerShell บน macOS หรือ Linux เปลี่ยน `npm.cmd` เป็น `npm`

## ติดตั้งครั้งแรก

### 1. ดาวน์โหลดโปรเจกต์

เปิด Terminal ในโฟลเดอร์ที่ต้องการเก็บโปรเจกต์ แล้วรัน:

```powershell
git clone https://github.com/ppshken/App-Builder.git
cd App-Builder
```

หรือกด **Code → Download ZIP** บน GitHub แตกไฟล์ แล้วเปิด Terminal ในโฟลเดอร์ที่มี `package.json`

### 2. ติดตั้งและเตรียมแอพ

```powershell
npm.cmd ci
npm.cmd run build
```

รอให้แต่ละคำสั่งเสร็จและไม่มีข้อผิดพลาดก่อนทำขั้นตอนถัดไป

### 3. เปิดใช้งาน

```powershell
npm.cmd start
```

เปิดเบราว์เซอร์ที่ **http://localhost:3000** และเปิด Terminal นี้ค้างไว้ระหว่างใช้งาน หากต้องการหยุดแอพ ให้กด **Ctrl+C** ใน Terminal

### 4. สร้างบัญชีเจ้าของแอพ

เมื่อเปิดครั้งแรกโดยไม่มีฐานข้อมูลเดิม ระบบจะให้สร้างบัญชีเจ้าของแอพ กรอกชื่อ อีเมล และรหัสผ่านความยาว 10–128 ตัวอักษร ขั้นตอนนี้ต้องทำผ่าน `localhost` บนเครื่องที่รันแอพ

ระบบสร้าง `data.db` ให้อัตโนมัติ ไม่ต้องติดตั้งเซิร์ฟเวอร์ฐานข้อมูลเพิ่มเติม

## เปิดใช้งานครั้งต่อไป

เปิด Terminal ในโฟลเดอร์โปรเจกต์ แล้วรัน:

```powershell
npm.cmd start
```

ไม่ต้องติดตั้งหรือ build ใหม่ทุกครั้ง เปิด **http://localhost:3000** เพื่อใช้งาน

## เริ่มสร้างแอพ

- **การตั้งค่าแอพ**: ชื่อ ไอคอน สี ฟอนต์ หน้าแรก และรูปแบบหน้าจอตั้งต้น
- **Data**: ตาราง คอลัมน์ สูตร ข้อมูล และข้อมูลจริงในฐานข้อมูล
- **View**: หน้ารายการ ตาราง ฟอร์ม รายละเอียด แผนที่ กราฟ ปฏิทิน และแดชบอร์ด
- **Action**: ปุ่มแก้ไขข้อมูล เปิดฟอร์ม เปิดรายละเอียด และเรียกการทำงานอื่น
- **ผู้ใช้และสิทธิ์**: บัญชี บทบาท สิทธิ์ระดับตาราง และเงื่อนไขระดับแถว

เปิด **http://localhost:3000/run** เพื่อใช้แอพที่สร้างไว้ ขณะนี้ตัวสร้างและแอพที่สร้างยังอยู่ในโปรเจกต์และเซิร์ฟเวอร์เดียวกัน

## สำรองข้อมูลและย้ายเครื่อง

**สำรองข้อมูลก่อนอัปเดตโค้ดหรือเปลี่ยนโครงสร้างฐานข้อมูลเสมอ**

ใช้เครื่องมือสำรองข้อมูลในแอพได้ หรือหากคัดลอกไฟล์ด้วยตนเอง:

1. ปิดแอพด้วย Ctrl+C และตรวจว่าไม่มีแอพอีกหน้าต่างใช้ฐานข้อมูลเดียวกัน
2. คัดลอก `data.db` เก็บไว้ หากยังมี `data.db-wal` ให้เก็บไฟล์นั้นด้วย ห้ามคัดลอกเฉพาะ `data.db` ขณะแอพเปิดอยู่ เพราะข้อมูลล่าสุดอาจยังอยู่ใน WAL
3. เก็บโฟลเดอร์ `uploads` ด้วย หากใช้การบันทึกรูปแยกเป็นไฟล์หรือกำหนดโฟลเดอร์รูปเอง

การย้ายเครื่อง: ติดตั้งโค้ดบนเครื่องใหม่ วางฐานข้อมูลที่สำรองไว้อย่างถูกต้องในโฟลเดอร์เดียวกับ `package.json` ก่อนเปิดแอพ แล้วเข้าสู่ระบบด้วยบัญชีเดิม ตาราง สูตร View Action และบัญชีผู้ใช้จะมาจากฐานข้อมูลนั้น

GitHub ไม่ใช่สำเนาข้อมูลแอพ เพราะ `data.db`, `uploads` และ `backups` ถูกตัดออกด้วย `.gitignore`

## อัปเดตโค้ดจาก GitHub

สำรองข้อมูลและหยุดแอพก่อน แล้วรันในโฟลเดอร์โปรเจกต์:

```powershell
git pull --ff-only
npm.cmd ci
npm.cmd run build
npm.cmd start
```

ฐานข้อมูลเดิมยังใช้ต่อได้ ระบบอาจปรับโครงสร้างข้อมูลเมื่อเปิดใช้งานครั้งแรกหลังอัปเดต หาก Git แจ้งว่ามีไฟล์โค้ดที่แก้ค้างไว้ ให้จัดการไฟล์เหล่านั้นก่อนดึงเวอร์ชันใหม่

หากดาวน์โหลดแบบ ZIP ให้ใช้โฟลเดอร์โค้ดเวอร์ชันใหม่และย้ายฐานข้อมูลที่สำรองไว้มา ห้ามลบโฟลเดอร์เดิมก่อนเก็บข้อมูลเรียบร้อย

## โหมดพัฒนาและทดสอบ

สำหรับแก้โค้ดและดูผลทันที:

```powershell
npm.cmd run dev
```

ใช้แทน `npm.cmd start` และหยุดเซิร์ฟเวอร์เดิมก่อน เพื่อไม่ให้แย่งพอร์ตกัน โหมดพัฒนาจะรวบรวมหน้าจอเมื่อเปิดครั้งแรก จึงอาจช้ากว่าโหมดใช้งานปกติ

คำสั่งตรวจสอบ:

```powershell
npm.cmd test
npm.cmd run test:api
npm.cmd run test:browser
npm.cmd run build
```

ชุดทดสอบใช้ฐานข้อมูลแยกจากข้อมูลจริง เทสต์เบราว์เซอร์ใช้ Microsoft Edge ที่ติดตั้งในเครื่อง ผลทดสอบและภาพหน้าจอจะไม่ถูกนำขึ้น Git

## ข้อความยาวและจำนวนตัวอักษร

ใน Data → คอลัมน์และการตั้งค่า เลือกชนิด **ข้อความยาว (Longtext)** เพื่อกรอกหลายบรรทัด สำหรับ Text และ Longtext กำหนด **จำนวนตัวอักษรสูงสุด** ได้ เว้นว่างหรือ 0 คือไม่จำกัด นับรวมช่องว่าง การขึ้นบรรทัดใหม่ และเครื่องหมายประกอบอักษรตามการนับของช่องกรอกในเบราว์เซอร์ (อีโมจิบางตัวนับมากกว่า 1) ตรวจทั้งฟอร์มและ API ไม่มีการตัดข้อความอัตโนมัติ หากข้อมูลเดิมยาวเกินค่าที่จะตั้ง ต้องแก้แถวนั้นหรือเพิ่มจำนวนก่อน ใช้ปุ่มแปลงชนิดข้อมูลสำหรับ Text ↔ Longtext ได้

สำรอง data.db ก่อนเริ่มเวอร์ชันนี้ ระบบเพิ่ม max_length ใน metadata โดยเก็บข้อมูลเดิมและตั้งต้นไม่จำกัด มีสำเนาฐานข้อมูลก่อน migration ใน backups เมื่อมีฐานข้อมูลเดิม ชุดทดสอบเฉพาะ: node scripts/integration.cjs longtext

## ชื่อ View และ Display Name

ชื่อ View ใช้จัดการหน้าจอในตัวสร้าง ต้องไม่ซ้ำกัน (ไม่แยกตัวพิมพ์ใหญ่เล็กและไม่นับช่องว่างหัวท้าย) ส่วนการแสดงผล → Display Name คือชื่อที่ผู้ใช้เห็นในแอพ ตั้งต่างจากชื่อ View และซ้ำกันได้ เว้นว่างใช้ชื่อ View ชื่อในระบบ เช่น view_1 ยังคงเดิม ลิงก์และ Action จึงใช้ต่อได้ ชื่อเดิมที่ซ้ำอยู่ก่อนอัปเดตยังแก้ตัวเลือกอื่นได้ แต่เมื่อเปลี่ยนชื่อใหม่ต้องไม่ซ้ำ Display Name เก็บใน display_json เดิม ไม่ต้องเปลี่ยนโครงสร้างฐานข้อมูล

## ตกแต่งค่าข้อมูลและระยะห่างตาราง

View → รูปแบบหน้าจอ: ตารางปรับระยะขอบบน–ล่างแถว (0–40 px) และระยะห่างบรรทัด (1–3 เท่า) ได้ ตั้งค่าตั้งต้นทุกตารางได้ในหน้าการตั้งค่าแอพ ส่วนรายการ ตาราง รายละเอียด และ Inline มี “ตกแต่งข้อมูล” เลือกคอลัมน์แล้วกำหนด badge แบบพื้นสี พื้นอ่อน หรือเส้นขอบ ขนาด ตัวหนา มุม ไอคอน ตำแหน่งไอคอน และสีข้อความ/พื้นหลัง/เส้นขอบ/ไอคอนด้วยโค้ดสีหรือกล่องเลือกสี

ใช้รูปแบบคงที่หรือเพิ่มกฎตามค่าได้ เช่น [_THIS] = "สำเร็จ" หรือ [amount] > 1000 กฎแรกที่ตรงจะใช้แทนตัวเลือกที่กำหนดในรูปแบบตั้งต้น เงื่อนไขอ่านข้อมูลแถวปัจจุบัน ไม่ดึงตารางอื่น มีตัวอย่างสำเร็จ/ยกเลิก/รอดำเนินการ เลื่อนลำดับและลบกฎได้ ไม่พบกฎที่ตรงใช้รูปแบบตั้งต้น เปลี่ยนค่าที่ตัวอย่างหรือดู Preview ก่อนบันทึกได้ การตกแต่งไม่เปลี่ยนค่าจริงใน data.db และใช้ display_json เดิม ชุดทดสอบ: node scripts/integration.cjs decoration

### หน้าซ้อนบนเดสก์ท็อป

เมื่อเปิดรายละเอียดหรือฟอร์ม ตารางต้นทางยังอยู่ด้านซ้ายพร้อมตัวกรองและสีเน้นแถวที่เปิด ด้านขวามีแถบชื่อข้อมูลที่เปิดซ้อนผ่าน Ref คลิกชื่อก่อนหน้าเพื่อย้อนกลับ หรือกด × เพื่อปิดหน้าซ้อนทั้งหมดกลับตารางต้นทาง ฟอร์มที่ยังไม่บันทึกจะถามก่อนออก บนมือถือยังใช้หน้าเต็มจอและปุ่มกลับ

ดูรายการปรับความเร็ว ผลวัด และวิธีทดสอบได้ที่ [การปรับประสิทธิภาพ](docs/performance.md)

### เมนูตกแต่งข้อมูล

เปิดเมนู “ตกแต่งข้อมูล” ทางซ้าย เลือกตาราง, View ที่จะใช้ และคอลัมน์ แล้วกำหนด Badge ไอคอน สี หรือกฎตามค่า พร้อมดูค่าตัวอย่าง ก่อนกด “บันทึกการตกแต่ง” การตั้งค่าเดิมแยกตาม View และยังใช้งานได้ครบ เมนูนี้แทนส่วนตกแต่งข้อมูลในรูปแบบหน้าจอของ View

หน้าตกแต่งมี Preview ของแอปด้านขวา ปรับไอคอน สี และกฎแล้วเห็นผลก่อนบันทึก บนมือถือสลับแท็บ “ตั้งค่าการตกแต่ง” กับ “ตัวอย่างแอป” ได้ และเลือกขนาดมือถือ แท็บเล็ต หรือคอมพิวเตอร์ใน Preview ได้

ชุดไอคอนมี 280 แบบ เลือกตามหมวดและค้นหาชื่อไทยหรืออังกฤษได้ เช่น คลังสินค้า/warehouse, ซ่อมบำรุง/wrench, รถจักรยานยนต์/motorcycle และเอกสารตรวจแล้ว/file-check ใช้ร่วมกันในไอคอนแอป View Action และการตกแต่งข้อมูล

### สำรองและกู้คืนข้อมูล

เจ้าของแอปเปิด Data → สำรองและกู้คืนข้อมูล กด “สำรองข้อมูลตอนนี้” แล้วดาวน์โหลดไฟล์ .db ไปเก็บอีกที่ได้ ระบบใช้ SQLite snapshot เพื่อรวมข้อมูลที่บันทึกอยู่ใน WAL ให้ครบ เลือกไฟล์เดิมในรายการหรืออัปโหลดไฟล์ .db เพื่อตรวจจำนวนตารางและข้อมูลก่อนกู้คืน พิมพ์ “กู้คืน” เพื่อยืนยัน ระบบสำรองข้อมูลปัจจุบันก่อนแทนข้อมูล เก็บบัญชีผู้ใช้เดิม และให้ทุกอุปกรณ์เข้าสู่ระบบใหม่ รายการตรวจไฟล์มีอายุ 15 นาที

### รายการลูกในฟอร์ม (Is a part of)

ในตารางลูก เลือกคอลัมน์ Ref ที่อ้างถึงตารางแม่ แล้วเปิด **Is a part of** ฟอร์มของตารางแม่จะแสดงส่วนรายการลูก เพิ่มและแก้ไขได้หลายรายการ รายการลูกจะบันทึกพร้อมตารางแม่ หากยกเลิกฟอร์มจะไม่บันทึกรายการลูกที่รออยู่

- จำกัดไม่เกิน 5 รายการ: ใส่ `COUNT([_THIS]) <= 5` ใน **รายการลูกต้องผ่านเงื่อนไข (Valid_If)** ระบบนับรวมรายการเดิมและรายการใหม่ และตรวจซ้ำฝั่ง API
- เงื่อนไขแสดงและเพิ่มรายการลูกอ้างคอลัมน์ตารางแม่ได้ เช่น `[status] = "เปิด"`
- ตารางลูกเลือก Is a part of ได้หนึ่ง Ref และห้ามอ้างอิงวนกัน
- การลบรายการแม่จะลบรายการลูกที่เป็นส่วนหนึ่งด้วย ทุกขั้นตอนยังตรวจสิทธิ์ผู้ใช้ หากรายการใดทำไม่ได้ จะย้อนกลับทั้งชุด
- สำรอง `data.db` ก่อนเปิดเวอร์ชันนี้ เพราะมีการเพิ่มช่องตั้งค่าใน metadata ระบบสำรองก่อน migration ด้วย

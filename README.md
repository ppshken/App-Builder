# No-code Builder

เครื่องมือสร้างแอปจากตารางข้อมูล ใช้บนคอมพิวเตอร์ส่วนตัว ข้อมูลอยู่ใน `data.db`

## เริ่มใช้งานหลังอัปเดต

1. ปิดแอป แล้วคัดลอก `data.db` ไปเก็บไว้เป็นไฟล์สำรองก่อน หากแอปยังเปิดอยู่ อย่าคัดลอกเฉพาะ `data.db` เพราะข้อมูลบางส่วนอาจอยู่ในไฟล์ WAL
2. เปิดด้วย `npm run dev` แล้วเข้า `http://localhost:3000` บน Windows PowerShell หากคำสั่ง npm ถูกปิดกั้น ให้ใช้ `npm.cmd run dev`
3. การเรียก API ครั้งแรกจะอัปเกรด metadata โดยอัตโนมัติ หากมีตารางเดิม ระบบสร้างไฟล์สำรองที่รวมข้อมูล WAL ใน `backups/data.before-expressions-<เวลา>.db` ก่อนอัปเกรดด้วย

การอัปเกรดเพิ่ม `is_virtual`, `virtual_expr`, `default_expr`, `show_if`, `valid_if`, `required_if` ใน `_columns` และนำ NOT NULL ที่เคยสร้างไว้ในตารางข้อมูลออก เพื่อให้ตรวจความจำเป็นด้วยกฎของแอปแทน ข้อมูลเดิม รหัสแถว ประวัติเลขรหัสที่เคยใช้ และ foreign key จะคงอยู่ หากตรวจข้อมูลอ้างอิงไม่ผ่าน จะยกเลิก transaction การอัปเกรด การรัน build อย่างเดียวไม่เปิดหรืออัปเกรดฐานข้อมูล

## Key, Label และ EnumList

เปิด **คอลัมน์และการตั้งค่า** แล้วเลือกคอลัมน์เพื่อเปิดสวิตช์ **Key** หรือ **Label** เลือกได้อย่างละหนึ่งช่องต่อตาราง เมื่อเลือกช่องใหม่ ระบบย้ายการกำหนดจากช่องเดิมให้อัตโนมัติ

- Key ต้องเป็นช่องข้อความ ตัวเลข หรือเลือกหนึ่งรายการ ไม่ใช่ช่องคำนวณ ต้องไม่ว่างและไม่ซ้ำ เปลี่ยนค่าในข้อมูลเดิมไม่ได้ หากข้อมูลเก่ามีช่องว่างหรือค่าซ้ำ ให้แก้ข้อมูลก่อนเปิด Key ถ้าไม่เลือก ระบบใช้ `id` ที่สร้างให้เอง ความสัมพันธ์ระหว่างตารางยังใช้ `id` เดิมเพื่อรักษาข้อมูลอ้างอิง สามารถใช้ค่าเริ่มต้น `UNIQUEID()` สำหรับ Key แบบข้อความได้
- Label คือชื่อที่ใช้แสดงรายการและตัวเลือกของช่องอ้างอิง ถ้าไม่เลือก ใช้ช่องข้อความแรกเหมือนเดิม
- ชนิด **เลือกได้หลายรายการ (EnumList)** กำหนดตัวเลือกคั่นด้วยจุลภาค ฟอร์มแสดงช่องติ๊กหลายค่า ค่าจะเก็บเป็น JSON array ใน SQLite และ API ส่งเป็นรายการ สามารถใช้ `LIST("ด่วน", "สำคัญ")` เป็นค่าเริ่มต้น, `COUNT([tags])` นับรายการ และ `IN("ด่วน", [tags])` ตรวจรายการที่เลือกได้

## จัดการ View และ Preview

เปิด **View** จากเมนูด้านซ้าย เลือกตาราง ชนิดหน้าจอ ไอคอน คอลัมน์ที่แสดง ลำดับคอลัมน์ การเรียงข้อมูล และ **จัดกลุ่มข้อมูล (Group By)** รองรับตาราง รายการ รายละเอียด และฟอร์ม

Group By เลือกคอลัมน์ได้หนึ่งช่องและกำหนดทิศทางเรียงกลุ่ม แสดงจำนวนรายการของแต่ละกลุ่ม ช่อง Ref แสดง Label ของแถวอ้างอิง โดยแยกกลุ่มตามรหัสแม้ Label เหมือนกัน ช่องว่างอยู่ในกลุ่ม “ไม่ระบุ” รายการในแต่ละกลุ่มใช้การเรียงข้อมูลที่ตั้งไว้

ฟอร์มและรายละเอียดในแอปหน้าบ้านเป็นหน้าเต็มจอ ปุ่มแก้ไข ลบ และปิดอยู่ด้านบนขวาเป็นไอคอน ฟอร์มมีปุ่มบันทึกด้านล่าง ถ้าปิดโดยยังไม่ได้บันทึก ระบบถามก่อนทิ้งข้อมูล

หน้าจอแบ่งเป็นรายการ View ทางซ้าย การตั้งค่าตรงกลาง และ Preview ทางขวา กดชื่อ View เพื่อแก้ในหน้าเดียว เลือกรูปแบบด้วยปุ่มไอคอน แล้วกด **บันทึก View** ที่แถบด้านบนเพื่ออัปเดตตัวอย่าง กด **แสดงใน Preview** เพื่อเปิด View ที่กำลังตั้งค่า หากสลับ View ขณะมีการแก้ไข ระบบถามก่อนทิ้งค่าที่ไม่ได้บันทึก บนมือถือสลับแท็บ **รายการ View / ตั้งค่า View / Preview** ได้

- **Primary Navigation** แสดงบนแถบนำทางหลักของแอป
- **Menu Navigation** แสดงในเมนูของแอป
- **Reference View** ไม่แสดงในเมนู ใช้ตอนเปิดรายละเอียด ฟอร์ม หรือข้อมูลจากช่องอ้างอิง หากมีหลาย View ชนิดเดียวกันของตารางเดียวกัน ใช้ View ลำดับน้อยที่สุดก่อน

ระบบสร้างรายการหลักและ Reference View รายละเอียด/ฟอร์มให้ตารางเดิมเมื่ออัปเกรด รวมถึงตารางที่สร้างใหม่ การลบ View ลบเฉพาะหน้าจอ ส่วนการลบตารางจะลบ View ของตารางด้วย การเปลี่ยนชื่อหรือลบคอลัมน์จะปรับการตั้งค่า View ตามไปด้วย

**Preview** เลือกมือถือ แท็บเล็ต หรือคอมพิวเตอร์ได้ ตัวอย่างมือถือขยายเต็มความสูงที่เหลือ และช่อง “View ที่เปิดใน Preview” เปลี่ยนตามหน้าที่กำลังเปิด ทั้งเมนู รายละเอียด และฟอร์ม ข้อมูล Preview ใช้ฐานข้อมูลจริง การเพิ่ม แก้ไข หรือลบจะบันทึกลงแอป

การอัปเกรด Key/Label เพิ่ม `is_key`, `is_label` และตาราง `_views` โดยสำรองฐานข้อมูลที่รวม WAL เป็น `backups/data.before-views-<เวลา>.db` ก่อนเปลี่ยนฐานข้อมูลเดิม และจะไม่สร้าง View หรือไฟล์สำรองซ้ำเมื่อเปิดครั้งต่อไป โปรดสำรอง `data.db` เองก่อนอัปเดตด้วย

การอัปเกรดตัวเลือก View เพิ่ม `icon`, `group_column`, `group_dir` ใน `_views` พร้อมสำรองฐานข้อมูลเดิมเป็น `backups/data.before-view-options-<เวลา>.db` ก่อนเปลี่ยน metadata โดยคงข้อมูลและการตั้งค่า View เดิม ทดสอบหน้า View รอบนี้ด้วย `node scripts/integration.cjs viewpages`

## วิธีใส่สูตร

เลือกตารางจากเมนูด้านซ้าย แล้วเปิด **คอลัมน์และการตั้งค่า** กดชื่อคอลัมน์เพื่อแก้ไขทีละช่อง ค่าเริ่มต้นและสูตรคำนวณอยู่ในส่วนค่าของช่อง ส่วนเงื่อนไขอยู่ในหัวข้อการแสดงผลและการตรวจข้อมูล

กดปุ่ม **ƒ** ข้างช่องสูตรเพื่อเปิดตัวช่วยเขียนสูตร เลือกชื่อคอลัมน์หรือตัวอย่างสูตร และใช้แท็บ **ลองคำนวณ** ทดสอบกับข้อมูลตัวอย่างก่อนกดใช้สูตร จากนั้นกด **บันทึกการแก้ไข** เพื่อบันทึกคอลัมน์ ใช้ชื่อในระบบ เช่น `[qty]` ไม่ใช่ชื่อที่แสดง เช่น `[จำนวน]` ใส่ข้อความในเครื่องหมายคำพูด สูตรไม่ต้องขึ้นต้นด้วย `=`

การสร้างตารางใหม่กรอกชื่อภาษาไทยและเลือกชนิดของช่องได้เลย ระบบตั้งชื่อในระบบให้โดยอัตโนมัติ หากต้องการกำหนดเองให้เปิดการตั้งค่าขั้นสูง หน้าข้อมูลสลับระหว่างตารางกับรายการได้ และกดชื่อรายการเพื่อดูรายละเอียด บนมือถือเริ่มต้นเป็นรายการที่กดได้สะดวก

| ใช้ทำอะไร | ตัวอย่าง |
| --- | --- |
| ช่องคำนวณชนิดตัวเลข | `[qty] * [price]` |
| ช่องคำนวณชนิดข้อความ | `IF([total] >= 1000, "ยอดสูง", "ทั่วไป")` |
| ค่าเริ่มต้นชนิดวันที่ | `TODAY()` |
| ค่าเริ่มต้นชนิดข้อความ | `NOW()` |
| Show_If ของหมายเหตุ | `[status] = "อื่น ๆ"` |
| Required_If ของหมายเหตุ | `[status] = "อื่น ๆ"` |
| Valid_If ของจำนวน | `AND(ISNOTBLANK([_THIS]), [_THIS] >= 0)` |
| รวมข้อความ | `CONCATENATE([first_name], " ", [last_name])` |
| ตรวจช่องใช่/ไม่ใช่ | `[active] = TRUE` |
| หลีกเลี่ยงหารด้วยศูนย์ | `IF([qty] = 0, 0, [total] / [qty])` |

- **ช่องคำนวณ:** เลือกเมื่อสร้างคอลัมน์ใหม่ แล้วกำหนดชนิดของผลลัพธ์ คำนวณตอนอ่านและขณะกรอกฟอร์ม ไม่เก็บค่าในตารางข้อมูล ไม่สลับช่องข้อมูลเดิมเป็นช่องคำนวณเพื่อป้องกันข้อมูลสูญหาย
- **ค่าเริ่มต้น:** คำนวณครั้งเดียวตอนเปิดฟอร์มเพิ่ม ไม่เปลี่ยนตามการกรอกช่องอื่นและไม่ใช้กับฟอร์มแก้ไข API POST ใช้ค่าเริ่มต้นเมื่อไม่ได้ส่งช่องนั้นมา แต่จะไม่แทนค่าที่ส่งมาเป็นค่าว่าง/null
- **Show_If:** ใช้กับฟอร์ม ตารางรายการยังแสดงทุกคอลัมน์ การซ่อนช่องไม่ลบค่าที่กรอกไว้ และไม่ใช่กฎสิทธิ์เข้าถึงข้อมูล
- **Required_If:** ใช้ร่วมกับ “จำเป็นเสมอ” หากเลือกจำเป็นเสมอ ช่องนั้นยังจำเป็นแม้ Required_If เป็น FALSE ช่องที่ซ่อนยังต้องผ่านกฎตรวจข้อมูล จึงควรตั้ง Show_If และ Required_If ให้สอดคล้องกัน
- **Valid_If:** ตรวจทั้งฟอร์มและ API สูตรต้องได้ TRUE/FALSE หรือให้รายการตัวเลือกสำหรับ EnumList ใช้ `[_THIS]` แทนค่าของช่องปัจจุบันได้ เงื่อนไขตรวจทั้งแถว รวมค่าคำนวณ ค่าว่างจะถูกตรวจด้วย หากอนุญาตค่าว่างให้ใช้ `OR(ISBLANK([_THIS]), ...เงื่อนไข...)`
- เปลี่ยนชื่อในระบบจะปรับการอ้างอิงในสูตรให้ตามไปด้วย โดยไม่แก้ข้อความในเครื่องหมายคำพูด ลบคอลัมน์ที่สูตรอื่นยังใช้อยู่ไม่ได้
- สูตรที่คำนวณไม่ได้ในข้อมูลเดิมจะแสดงข้อผิดพลาดรายช่อง โดยไม่แก้หรือลบข้อมูลเดิม

## ฟังก์ชันและรูปแบบที่รองรับในรอบนี้

`IF(condition, yes, no)`, `IFS(condition, value, ...)`, `AND(...)`, `OR(...)`, `NOT(value)`, `ISBLANK(value)`, `ISNOTBLANK(value)`, `CONCATENATE(...)`, `LEN(value)`, `TRIM(value)`, `UPPER(value)`, `LOWER(value)`, `TODAY()`, `NOW()`, `YEAR(date)`, `MONTH(date)`, `DAY(date)`, `ROUND(number)`, `ABS(number)`, `MIN(number, ...)`, `MAX(number, ...)`

รองรับตัวเลข ข้อความ `TRUE`, `FALSE`, `NULL` วงเล็บ ตัวดำเนินการ `+ - * / %` สำหรับตัวเลข `&` รวมข้อความ และ `= <> != < <= > >=` เปรียบเทียบ ชื่อฟังก์ชันใช้ตัวเล็กหรือตัวใหญ่ได้ ชื่อคอลัมน์ใช้ตัวเล็กตามชื่อในระบบ ช่องคำนวณอ้างช่องคำนวณอื่นได้ แต่ห้ามวนกลับมาหาตัวเอง

`IF`, `IFS`, `AND`, `OR` จะข้ามส่วนที่ไม่จำเป็นต้องคำนวณ ค่าว่างใช้เป็น 0 ในการคำนวณตัวเลข แต่ 0 และ FALSE ไม่ถือเป็นค่าว่าง เงื่อนไขยอมรับ TRUE/FALSE และ 1/0 ไม่แปลงข้อความอย่าง `"false"` เป็นเงื่อนไขโดยอัตโนมัติ

`TODAY`/`NOW` ใช้เวลาไทย วันที่เป็น `YYYY-MM-DD` และ NOW เป็นข้อความวันเวลาพร้อม `+07:00` หากใช้ NOW กับคอลัมน์ชนิดวันที่ จะเก็บเฉพาะวันที่ `ROUND` รับตัวเลขหนึ่งค่าและปัดเป็นจำนวนเต็ม ส่วน `MIN`/`MAX` รับตัวเลขหลายค่าคั่นด้วยจุลภาค

เป็นไวยากรณ์บางส่วนในแนว AppSheet รองรับสูตรข้ามตาราง `SELECT` และ `table[column]` แล้ว ยังไม่รองรับ `LOOKUP`, `SUM` การอ้าง Ref หลายระดับ และการบวก/ลบวันที่โดยตรง รายการรองรับตัวเลือกแบบข้อความผ่าน `LIST`, `COUNT` และ `IN` ตัวอ่านสูตรเขียนเอง ไม่ใช้ eval หรือ new Function มีขอบเขตความยาวและความซับซ้อนเพื่อกันสูตรที่ทำให้แอปค้าง

การค้นหาและเรียงรองรับช่องคำนวณด้วย โดยคำนวณแถวก่อนค้นหา/เรียง แล้วแสดงไม่เกิน 500 แถว เหมาะกับข้อมูลส่วนตัวในเฟสนี้ ยังไม่มีการแบ่งหน้าเพื่อรองรับตารางขนาดใหญ่

## ทดสอบ

```text
npm run test
npm run test:api
npm run test:browser
npm run test:features
npm run test:designer
npm run build
```

เทสต์ตัวคำนวณและ migration ใช้ฐานข้อมูลในหน่วยความจำ/โฟลเดอร์ `.test-data` เทสต์ API และเบราว์เซอร์เปิดเซิร์ฟเวอร์ชั่วคราวพร้อมฐานข้อมูลใหม่แยกทุกครั้ง ไม่ใช้ `data.db` จริง และใช้โฟลเดอร์ build `.next-tests` แยกจากแอปที่เปิดอยู่ ห้ามรันเทสต์ API/เบราว์เซอร์พร้อมกันเพราะใช้โฟลเดอร์ build สำหรับทดสอบร่วมกัน

เทสต์เบราว์เซอร์ใช้ Microsoft Edge ที่ติดตั้งอยู่ หากต้องการใช้ Chrome ตั้ง `NOCODE_BROWSER_CHANNEL=chrome` ภาพหน้าจออยู่ใน `artifacts/` ส่วน `NOCODE_DB_PATH` ใช้กำหนดตำแหน่งฐานข้อมูลสำหรับทดสอบหรือใช้งานแยกได้


## Slice และ Action

ก่อนอัปเกรด ปิดแอปและสำรอง data.db ระบบสำรองฐานข้อมูลเดิมที่รวม WAL เป็น backups/data.before-slices-actions-<เวลา>.db ก่อนเพิ่ม _slices, _actions และ slice_name ใน _views การเปิดครั้งถัดไปไม่อัปเกรดซ้ำ

- เปิด **จัดการ Slice** เลือกตาราง ตั้งชื่อ และกรอกเงื่อนไข เช่น [status] = "รอดำเนินการ" หรือ [owner] = USEREMAIL() เลือกคอลัมน์ที่ต้องการแสดงได้ ไม่เลือกหมายถึงทุกคอลัมน์ จากนั้นบันทึก แล้วเปิด **จัดการ View** เลือก Slice ใต้ตารางข้อมูล
- Slice เป็นชุดข้อมูลสำหรับแสดงผล ไม่ได้สร้างสำเนาตารางหรือระบบสิทธิ์ การเพิ่มและแก้ไขยังบันทึกตารางต้นทาง แถวที่ไม่ตรงเงื่อนไขหลังบันทึกจะหายจาก Slice ฟอร์มยังแสดงและตรวจช่องบังคับของตารางต้นทาง
- เปิด **จัดการ Action** เลือกเปลี่ยนค่าคอลัมน์หรือลบแถว กำหนดเงื่อนไขแสดงปุ่ม เช่น [status] = "รอดำเนินการ" และสูตรค่าใหม่ เช่น "เสร็จแล้ว" หรือ [amount] + 1 ใช้ **ตัวช่วยสูตร** เพื่อเลือกคอลัมน์และลองคำนวณได้
- Action แสดงในหน้ารายละเอียดของแถว เลือกเปลี่ยนหลายคอลัมน์ในครั้งเดียวได้ ทุกสูตรอ่านค่าก่อนเปลี่ยนของแถวเดียวกัน ปุ่มลบให้ยืนยันเสมอ ปุ่มเปลี่ยนค่าขอคำยืนยันเมื่อระบุข้อความไว้
- เซิร์ฟเวอร์ตรวจเงื่อนไขใหม่ก่อนทำงาน ตรวจข้อมูลที่จำเป็น สูตร Valid_If และ foreign key และบันทึกภายใน transaction การตรวจไม่ผ่านยกเลิกทั้งรายการ Key และช่องคำนวณแก้ด้วย Action ไม่ได้
- การเปลี่ยนชื่อคอลัมน์ปรับสูตร Slice/Action ตามไปด้วย ลบคอลัมน์ที่สูตรยังใช้อยู่ไม่ได้ ลบ Slice ที่ View ยังใช้ไม่ได้ การลบตารางลบการตั้งค่า Slice/Action ของตารางนั้นด้วย

หน้าบ้าน **/run** มีแถบชื่อและเมนูด้านบน แถบนำทางด้านล่าง ปุ่มเพิ่มข้อมูลลอย และรายการที่กดเปิดรายละเอียดได้ รองรับหน้าจอเล็กและธีมมืด View แบบตารางยังแสดงตารางบนจอใหญ่ และแสดงรายการเมื่อเปิดบนมือถือ

Preview ในหน้า View จองพื้นที่แถบเลื่อนให้คงที่ เพื่อให้ขนาดตัวอย่างไม่สั่นเมื่อความกว้างเว็บเกิน 1400 พิกเซล

ตรวจเพิ่มเติมด้วย npm run test:automation ซึ่งทดสอบหน้า Slice/Action, สูตรผิด, การใช้ Slice ใน View, Action ยืนยัน/ยกเลิก, เพิ่มข้อมูลบนมือถือ, dark mode และขนาด Preview ทั้ง 3 อุปกรณ์ที่ความกว้าง 1401–1910 พิกเซล


## Sidebar และหน้า Data แบบเดียวกันทั้งแอป

เมนูหลักใช้ชุดเดียวทุกหน้าตั้งค่า มี 4 รายการ:

- **การตั้งค่าแอพ**: ชื่อ ไอคอน สี และโหมดสว่าง/มืด/ตามอุปกรณ์ บันทึกแล้วใช้กับชื่อบนแถบหัวเรื่อง ไอคอน และสีของทั้งตัวสร้างและแอปหน้าบ้าน
- **Data**: ตารางฐานข้อมูลและ Slice กดชื่อตารางทางซ้ายเพื่อเปิดคอลัมน์ เมนูตารางจะขยายเป็น **คอลัมน์ / ข้อมูล** กดลูกศรเพื่อย่อหรือขยาย กด + เพื่อสร้างตารางใหม่
- **View**: หน้าจอของแอป พร้อม Preview ในหน้าตั้งค่าเดียวกัน
- **Action**: ปุ่มทำงานของแอป

หน้าคอลัมน์แสดงเป็นตารางแนวนอน เลือก Key/Label และช่องจำเป็นได้ในแถว แก้ชื่อที่แสดงหรือสูตรแล้วออกจากช่องหรือกด Enter เพื่อบันทึก กด Escape เพื่อยกเลิกค่าที่กำลังพิมพ์ กดดินสอเพื่อตั้งค่าตัวเลือก อ้างอิงตาราง เงื่อนไข และใช้ตัวช่วยสูตร ชนิดของคอลัมน์เดิมยังเปลี่ยนไม่ได้ตามกฎเดิม บนมือถือเลื่อนตารางคอลัมน์ไปทางขวาได้โดยไม่ทำให้ทั้งหน้าเกินขนาดจอ

หน้า Preview App As แยกถูกถอดออก ลิงก์ /preview เดิมพาไป /views และคง View ที่ระบุไว้ในลิงก์ เปลี่ยนขนาดอุปกรณ์ได้ใน Preview ของหน้า View และช่องจำลองผู้ใช้ถูกถอดออกแล้ว

การอัปเกรดเพิ่ม _app_settings โดยสำรองฐานข้อมูลเดิมที่รวม WAL ก่อนเป็น backups/data.before-app-settings-<เวลา>.db ไม่สร้างสำเนาซ้ำเมื่อเปิดครั้งต่อไป กรุณาปิดแอปและสำรอง data.db เองก่อนอัปเดตด้วย

ทดสอบ Sidebar เดียวกันทั้งหน้า การขยายตาราง แก้คอลัมน์ การบันทึกชื่อ/ไอคอน/สี/โหมด และมือถือด้วย npm run test:builder

Data รองรับ **รูปภาพ** (อัปโหลด JPG/PNG/WebP/GIF ไม่เกิน 5 MB ต่อรูป แสดงตัวอย่างในฟอร์ม/ข้อมูล/แอปมือถือ) และ **วัน–เวลา** (เวลาไทย รองรับ NOW() เป็นค่าเริ่มต้น) รูปภาพเก็บเป็น BLOB ใน _images ภายใน data.db ส่วนคอลัมน์เก็บรหัสรูป การนำรูปออกจากแถวไม่ได้ลบไฟล์รูปที่อาจใช้งานร่วมกับแถวอื่น การอัปเกรดจะสำรองฐานข้อมูลเดิมก่อนเพิ่มตารางเป็น backups/data.before-images-<เวลา>.db
หน้าต่างเพิ่ม/แก้ไขคอลัมน์กว้างสูงสุด 960px และย่อบนมือถือ วางชื่อในระบบก่อนชื่อที่แสดง ทดสอบรูป/วันเวลาและหน้าต่างด้วย node scripts/integration.cjs media


EnumList ใช้ Valid_If เป็นรายการได้ เช่น `permission[permission_key]` หรือ `SELECT(permission[permission_key], [active] = TRUE)` และกรองตามแถวในฟอร์มด้วย `SELECT(permission[permission_key], [role] = [_THISROW].[role])` ช่องตัวเลือกคั่นจุลภาคเว้นว่างได้เมื่อใช้สูตรรายการ ระบบเก็บคีย์และแสดง Label เมื่อคอลัมน์ที่ดึงเป็น Key ของตารางต้นทาง (เลือก Label ที่ต้องการในตาราง permission) หากไม่มี Label ใช้ข้อความคอลัมน์แรกหรือ id ตามกฎเดิม ถ้าคีย์เดิมไม่อยู่ในตัวเลือกปัจจุบัน ฟอร์มยังแสดงให้ยกเลิกการเลือก และ API ตรวจข้อมูลต้นทางใหม่ใน transaction ก่อนบันทึก ไม่ใช้รายการตัวเลือกจากเบราว์เซอร์เป็นหลักฐานอนุญาต

ตัวเลือกข้ามตารางอ่านได้สูงสุด 10,000 แถว ไม่ติดขีดจำกัด 500 แถวของหน้ารายการ ข้อมูลที่เลือกได้ยังมีขีดจำกัดเดิม 200 รายการต่อช่อง ตัวช่วยสูตรมีแท็บตารางเพื่อแทรกสูตรคีย์และ SELECT พร้อมทดสอบจากข้อมูลจริง สูตรยังผ่าน parser/evaluator ที่เขียนเอง ไม่ใช้ eval/new Function ใช้ metadata valid_if เดิม จึงไม่ต้องเปลี่ยนโครงสร้างฐานข้อมูลในการอัปเดตนี้ เมื่อเปลี่ยนชื่อคอลัมน์จะปรับสูตรข้ามตารางตาม และป้องกันลบตาราง/คอลัมน์ที่สูตรอื่นอ้างอยู่

ตรวจฟอร์ม EnumList ข้ามตารางด้วย `node scripts/integration.cjs select` และ API ด้วย `npm run test:api`


Data รองรับ **ทศนิยม (Decimal)** เก็บใน SQLite REAL เช่น 23.50, 7.25 และค่าติดลบ ใช้คำนวณ เรียง และตรวจเงื่อนไขได้เหมือนตัวเลข ยังไม่มีการกำหนดจำนวนหลักทศนิยมหรือระบบเลขฐานสิบความแม่นยำสูงสำหรับบัญชี ชนิดตัวเลขเดิมไม่ถูกเปลี่ยนและชนิดคอลัมน์เดิมยังเปลี่ยนไม่ได้

สูตรดึงค่าจาก Ref รองรับหนึ่งระดับ เช่น `[product].[product_price]` หรือ `[product].[product_price] * [qty]` โดย product ต้องเป็นคอลัมน์ Ref และ product_price เป็นชื่อในระบบของคอลัมน์ในตารางต้นทาง ใช้กับช่องคำนวณ ค่าเริ่มต้น เงื่อนไข และ Action ได้ ช่องคำนวณจะปรับตาม Ref ที่เลือก ค่าเริ่มต้นยังใช้ครั้งแรกตามกฎเดิม Ref ว่างให้ค่าว่าง หากไม่พบแถวต้นทางจะมี error ภาษาไทย การเปลี่ยนชื่อคอลัมน์ต้นทางปรับสูตรตามและป้องกันลบคอลัมน์ที่สูตร Ref ใช้อยู่

หน้าสร้างตารางใหม่มี Key และจำเป็นในแต่ละแถว เลือก Key ใหม่จะยกเลิก Key เก่า และบังคับกรอก Key เสมอ ชนิดที่เป็น Key ได้คือข้อความ ตัวเลข Decimal หรือเลือกหนึ่งรายการ ช่องคำนวณใช้ Key/จำเป็นไม่ได้ บนมือถือจัดช่องเลือกไว้บรรทัดถัดไปเพื่อให้กรอกได้สะดวก

ทดสอบ Decimal/Ref/หน้าสร้างตารางด้วย `node scripts/integration.cjs ref`

## ตั้งค่ารูปแบบหน้าจอราย View

เลือก View แล้วกดแท็บ **รูปแบบหน้าจอ** ข้างชื่อ View ด้านบน กด **บันทึก View** เพื่ออัปเดต Preview การตั้งค่าเก็บแยกในแต่ละ View

- **รายการ:** เลือกแบบเรียบ/การ์ด คอลัมน์รูปภาพ รูปทรงและขนาด หัวเรื่อง คอลัมน์ข้อความประกอบ ชื่อช่องหน้าข้อความ และปุ่มแก้ไข/Action หรือไม่แสดงปุ่ม ปุ่ม Action ใช้เงื่อนไขและการยืนยันที่ตั้งไว้ในเมนู Action
- **ตาราง:** แสดงเป็นตารางจริงทุกขนาดหน้าจอ เลื่อนซ้าย–ขวาได้ เลือกระยะห่างแถวและการตัดข้อความขึ้นบรรทัดใหม่
- **รายละเอียด:** วางชื่อและค่าแนวตั้งหรือแนวนอน แสดง 1 หรือ 2 ช่องต่อแถว และเลือกขนาดรูปภาพ
- **ฟอร์ม:** เลือก 1 หรือ 2 ช่องต่อแถว ตำแหน่งชื่อช่องด้านบน/ซ้าย ความกว้างครึ่งแถว/เต็มแถว หัวข้อแบ่งกลุ่ม คำแนะนำ ข้อความในช่องว่าง และข้อความหลายบรรทัดสำหรับช่องข้อความ จัดลำดับและเลือกช่องที่แสดงได้ กฎจำเป็น สูตร และการตรวจข้อมูลยังใช้ตามคอลัมน์เดิม

การอัปเกรดเพิ่ม `display_json` ใน `_views` สำรองฐานข้อมูลเดิมรวม WAL เป็น `backups/data.before-view-display-<เวลา>.db` ก่อนเปลี่ยน metadata เก็บข้อมูลและ View เดิมไว้ครบ โปรดปิดแอปแล้วสำรอง `data.db` ก่อนใช้เวอร์ชันใหม่

ตรวจการแสดงผลและการบันทึกด้วย `node scripts/integration.cjs layouts`

## ไอคอน เงื่อนไขแสดง View และการคลิกแถว

- **ไอคอน 141 แบบ:** เลือกได้ทั้งการตั้งค่าแอพและ View มีช่องค้นหาไทย/อังกฤษและหมวด เช่น ธุรกิจ การเดินทาง งาน และอุปกรณ์ ใช้ไอคอนในโปรเจกต์ ไม่ต้องเชื่อมอินเทอร์เน็ต
- **Show_If ของ View:** อยู่ในแท็บการตั้งค่า View ว่าง = แสดงเสมอ สูตร TRUE/FALSE กำหนดการแสดง Primary, Menu และ Reference View เมื่อเปิดลิงก์ตรงไปยัง View ที่ซ่อน ระบบจะแจ้งให้เลือกหน้าอื่น มีปุ่มตรวจผลกับข้อมูลปัจจุบัน เงื่อนไขนี้ควบคุมหน้าจอ ไม่ใช่สิทธิ์เข้าถึงข้อมูล
- View ไม่มีแถวปัจจุบัน จึงใช้ [คอลัมน์] เดี่ยวๆ ไม่ได้ ตัวอย่าง: `COUNT(SELECT(orders[id], [status] = "รอ")) > 0` หรือ `DAY(TODAY()) <= 15` ใช้ชื่อในระบบ เงื่อนไขใน SELECT อ้างคอลัมน์ของตารางนั้นได้
- ระบบตรวจ Show_If ใหม่หลังเพิ่ม แก้ไข ลบ หรือเรียก Action และเมื่อกดโหลดข้อมูลใหม่
- **เมื่อคลิกแถว:** เลือก View แบบตาราง > รูปแบบหน้าจอ > เมื่อคลิกแถว เลือกดูรายละเอียด (ตั้งต้น), แก้ไขข้อมูล, ลบข้อมูล, เรียก Action ของตารางเดียวกัน หรือไม่ทำอะไรได้ ใช้ Enter/Space ที่แถวได้ ปุ่มแก้ไข/ลบ/Action ในแถวยังคงเรียกการทำงานของปุ่มเอง
- การลบถามยืนยันเสมอ Action ใช้เงื่อนไขและข้อความยืนยันเดิม ตรวจซ้ำที่ API ก่อนเปลี่ยนข้อมูล และลบหรือย้ายตารางของ Action ที่ยังถูก View ใช้อยู่ไม่ได้

ก่อนใช้งานเวอร์ชันนี้ **ปิดแอปและสำรอง data.db** ระบบเพิ่ม `_views.show_if` อัตโนมัติ โดยสำรองข้อมูลรวม WAL ใน `backups/data.before-view-visibility-*.db` ก่อนปรับ metadata และเก็บการคลิกแถวใน `display_json` ของ View เดิม

## Related และชนิด List

- Related เกิดอัตโนมัติจากคอลัมน์ Ref ที่เก็บในตารางจริง เช่น รายการขายมี Ref ลูกค้า หน้ารายละเอียดลูกค้าจะแสดงรายการขายที่เกี่ยวข้อง แยกแต่ละ Ref ออกจากกัน
- ตั้งจำนวนเริ่มต้น 5 / 10 / 20 / ทั้งหมด ได้ในหน้าคอลัมน์ของตารางต้นทางที่ส่วน Related หรือในหน้าตั้งค่าคอลัมน์ Ref เปลี่ยนจำนวนชั่วคราวและกดก่อนหน้า/ถัดไปได้ในรายละเอียด
- Related ใช้ WHERE + COUNT + LIMIT/OFFSET ใน SQLite ก่อนส่งผลลัพธ์ แถวที่แสดงใช้ Label ของตารางนั้น และกดเปิดรายละเอียดได้ เพิ่มดัชนีให้ Ref เพื่อค้นหาความสัมพันธ์ได้เร็วขึ้น
- List เป็นชนิดใหม่ต่างจาก EnumList: เก็บรายการข้อความหรือตัวเลขเป็น JSON หรือเป็นช่องคำนวณ ไม่ต้องกำหนดตัวเลือกแบบคั่นจุลภาค หากเลือกตารางอ้างอิง ค่าใน List ใช้ Key ของตารางนั้น (หรือ id หากไม่มี Key) และแสดงเป็น Label
- ตัวอย่างช่องคำนวณ List อ้างถึงสินค้า: SELECT(product[product_key], [active] = TRUE) หรือ product[product_key] ตั้งค่าเริ่มต้นด้วย LIST("p1","p2") ได้ สูตร SELECT ยังใช้ขอบเขตความปลอดภัยเดิมสูงสุด 10,000 แถว การแบ่งหน้าช่วยลดข้อมูลรายการที่แสดง แต่ไม่เปลี่ยนผลของสูตร
- List ที่อ้างตารางเลือกข้อมูลด้วยช่องเลือกแบบแบ่งหน้า รักษารายการที่เลือกเมื่อข้ามหน้า รองรับ Required และ Valid_If แบบรายการ ผลจาก SELECT หรือเงื่อนไข TRUE/FALSE ตรวจซ้ำที่ API
- List ข้อความที่ไม่อ้างตารางกรอก JSON เช่น ["โทรนัดหมาย","ส่งเอกสาร"] รายละเอียดแบ่งหน้ารายการให้ด้วย
- ระบบตรวจคีย์ List ก่อนบันทึก และป้องกันลบข้อมูลที่ยังถูก List แบบเก็บค่าจริงใช้งานอยู่ รวมถึงเปลี่ยน Key ที่ List ใช้อยู่ การเปลี่ยนตารางอ้างอิงของ List เดิมจะตรวจข้อมูลทั้งหมดก่อนบันทึก หากไม่ผ่านจะไม่เปลี่ยน metadata
- ตารางหน้า Data มีความสูงขั้นต่ำใช้พื้นที่เกือบเต็มจอ ลดระยะห่างแถว และคงการเลื่อนซ้ายขวา ข้อความขนาดใหญ่และโหมดมืด
- ก่อนเปิดเวอร์ชันนี้ ปิดแอปและสำรอง data.db migration เพิ่ม _columns.list_limit (ค่าเริ่มต้น 5) และสร้างสำเนา SQLite รวมข้อมูลใน WAL ไว้ที่ backups/data.before-related-lists-*.db ก่อนปรับ metadata ไม่เขียนคอลัมน์ List ลงตารางข้อมูลเมื่อเป็นช่องคำนวณ
- ทดสอบ: npm test, npm run test:api และ node scripts/integration.cjs lists ใช้ฐานข้อมูลแยกเสมอ ภาพตัวอย่าง artifacts/lists-data-desktop.png และ artifacts/lists-related-mobile.png


## Inline Views และรูปแบบ Related

- หน้า View มีกลุ่ม Inline Views เพิ่มเติม สร้างหนึ่ง View ต่อหนึ่งคอลัมน์ Ref ที่เก็บในตารางจริงโดยอัตโนมัติ ทั้ง Ref เดิมหลัง migration, ตารางใหม่ และคอลัมน์ Ref ที่เพิ่มใหม่ Inline ไม่แสดงใน Primary/Menu Navigation
- Inline เลือกตารางและ Ref ที่เชื่อมกลับไปยังตารางต้นทาง ใช้ชนิดรายการหรือตาราง ตั้งรูปแบบในแท็บรูปแบบหน้าจอได้: รายการ/การ์ด, คอลัมน์รูปภาพ, รูปทรงและขนาด, หัวเรื่อง, ข้อความประกอบ, ปุ่มแก้ไข/Action; ตารางเลือกคอลัมน์ ลำดับ ความแน่น ตัดข้อความ และการคลิกแถว
- ใน View รายละเอียด → รูปแบบหน้าจอ → รายการที่เกี่ยวข้อง เลือก Inline ของ Related แต่ละส่วน ตั้งหัวข้อ เปิด/ปิด และกำหนดจำนวน 5/10/20/ทั้งหมด หรือใช้ค่าจาก Data ได้ การเลือกอัตโนมัติใช้ Inline ลำดับแรกของ Ref นั้น
- ทั้งแอปหน้าบ้าน Preview และรายละเอียดใน Data ใช้รูปแบบ Related ที่บันทึกไว้ Inline เคารพ Show_If และยังแบ่งหน้าใน SQLite โดย WHERE Ref = id ของแถวต้นทางก่อน LIMIT/OFFSET ไม่โหลดทุกแถวมาตัดในเบราว์เซอร์
- Inline ใช้ตารางโดยตรง ไม่มี Slice เพิ่มเติม และใช้คอลัมน์ที่เก็บจริงในการเรียง/จัดกลุ่มเพื่อให้แบ่งหน้าในฐานข้อมูลได้ ช่องคำนวณยังเลือกแสดงได้
- ปุ่มแก้ไขเปิดฟอร์มของแถวที่เกี่ยวข้อง ลบและ Action ที่ต้องยืนยันใช้กล่องยืนยัน ตรวจเงื่อนไข Action ฝั่ง API และรีโหลดเฉพาะรายการหลังทำงาน
- การเปลี่ยนชื่อ Ref ปรับ Inline และการผูก Related ตามไปด้วย การลบ Ref ลบ Inline ของ Ref นั้นและนำการตั้งค่าที่ไม่ใช้งานออก ป้องกันลบหรือย้าย Inline ที่ View รายละเอียดยังเลือกไว้ ให้เลือกอัตโนมัติหรือ Inline อื่นก่อน
- ก่อนเปิดเวอร์ชันนี้ ปิดแอปและสำรอง data.db migration เพิ่ม _views.inline_ref และสร้างสำเนารวม WAL ก่อนแก้ metadata ที่ backups/data.before-inline-views-*.db รูปแบบ Related อยู่ใน display_json เดิม
- ทดสอบ npm test, npm run test:api, node scripts/integration.cjs inline และตรวจรูปแบบเดิมด้วยชุดทดสอบ layouts/lists/builder ทุกชุดใช้ฐานข้อมูลแยกจาก data.db ภาพตัวอย่าง artifacts/inline-view-settings.png, artifacts/inline-related-table.png, artifacts/inline-related-mobile.png

## ป้องกันข้อมูลซ้ำ

- Data → คอลัมน์: ตั้งห้ามซ้ำ และตรวจข้อมูลซ้ำพร้อมลิงก์แก้ไขแต่ละแถว ต้องแก้ข้อมูลเดิมที่ซ้ำก่อนเปิดกฎ
- ตรวจขณะกรอกฟอร์ม ตอนบันทึกผ่าน API และ Action พร้อมกฎใน SQLite ช่องไม่จำเป็นเว้นว่างซ้ำได้ ตัวพิมพ์เล็ก–ใหญ่และช่องว่างรอบข้อความถือว่าต่างกัน
- รองรับคอลัมน์ปกติที่เก็บค่าเดียว ไม่รองรับช่องคำนวณ List และ EnumList ส่วน Key ห้ามซ้ำอยู่แล้ว การแปลงชนิดเดิมรักษากฎและตรวจค่าซ้ำหลังแปลง การคัดลอกเป็นคอลัมน์ใหม่ไม่คัดลอกกฎห้ามซ้ำ
- สำรอง data.db ก่อนเปิดเวอร์ชันนี้ เพิ่ม _columns.is_unique ตั้งต้นปิดสำหรับคอลัมน์เดิม และสำรองก่อนเปลี่ยน metadata
- npm run test:unique ทดสอบด้วยฐานข้อมูลแยก ครอบคลุมมือถือ โหมดมืด และ API


## ค้นหา กรอง และแบ่งหน้าข้อมูล

- หน้า Data และแอปหน้าบ้าน กรองหลายเงื่อนไขร่วมกันได้ (ตรงทุกเงื่อนไข) เช่น ราคา >= 100 และ <= 500 พร้อมสถานะและช่วงวันที่
- รองรับเท่ากับ ไม่เท่ากับ มีข้อความ ตั้งแต่ ถึง ว่าง และไม่ว่าง เลือกจำนวน 10/25/50/100 รายการต่อหน้า เปลี่ยนตัวกรองหรือการเรียงจะกลับหน้าแรก การจัดกลุ่มแสดงเฉพาะหน้าปัจจุบัน
- ตารางปกติกรอง นับ และแบ่งหน้าใน SQLite ก่อนคำนวณช่องเสมือน กรณี Slice/กรองหรือเรียงช่องคำนวณ/ค้นหาชื่อ Ref จะคำนวณข้อมูลก่อนแบ่งหน้า จึงอาจช้าหากข้อมูลมาก
- API GET แบบเดิมยังส่งอาร์เรย์ไม่เกิน 500 แถว ใส่ page และ page_size จะคืน {rows,total,page,page_size,pages} และ filters เป็น JSON ของ {column,op,value} ตรวจชื่อจาก metadata และใช้ prepared statements
- npm run test:filters ทดสอบด้วยข้อมูลแยก 1,200 แถว ไม่เปลี่ยนโครงสร้างฐานข้อมูลของคุณ

### รหัสภายในและ Key ที่ผู้ใช้กำหนด

- id คือรหัสภายในอัตโนมัติ แสดงในหน้า Data และแก้ไม่ได้ ส่วน Key ในแอปเป็นรหัสที่ผู้ใช้กำหนดและแก้ได้ โดยยังห้ามว่าง ห้ามซ้ำ และเคารพการตั้งค่าอ่านอย่างเดียว/Editable_If
- Ref เก็บ id เป็นตัวเลข และ List ที่อ้างตารางเก็บรายการ id เป็นข้อความใน JSON ทั้งสองเชื่อมแถวเดิมเมื่อแก้หรือเปลี่ยนคอลัมน์ Key ช่องเลือกแสดง Label และรหัส Key ประกอบ
- สูตร SELECT(table[key], condition) และ table[key] เมื่อใช้เป็นผลของ List ที่อ้างตารางจะเลือกแถวแล้วคืน id รวมถึงผลจาก IF/IFS ส่วน SELECT ทั่วไปและ EnumList ยังคืนค่าคอลัมน์ที่ระบุ EnumList แบบ SELECT/table[column] โดยตรงจะปรับค่าที่เลือกไว้เมื่อแก้รหัสต้นทางในธุรกรรมเดียวกัน
- ค่า API/PagedList ของ List ที่อ้างตารางใช้ id เช่น ["17","23"] สูตร LIST แบบระบุรหัสโดยตรงใน List ชนิดนี้ให้ใช้ id เช่น LIST("17") ส่วน List ข้อความที่ไม่อ้างตารางใช้ข้อความได้ตามเดิม
- ก่อนเริ่มเวอร์ชันนี้ ให้สำรอง data.db รุ่นเดิมไว้ การเปิดฐานข้อมูลจะสร้างไฟล์สำรองอัตโนมัติใน backups/ ก่อนเพิ่ม _app_settings.list_reference_version และแปลง List เก่าจาก Key เป็น id แบบธุรกรรมเดียว รหัสตัวเลขจับคู่ด้วย Key เดิมเสมอ หากรหัสหาย/ซ้ำจะยกเลิกทั้งหมดและเก็บไฟล์สำรองไว้ การเปิดซ้ำไม่แปลงซ้ำ
- สูตร List เดิมที่ระบุ LIST("รหัสเดิม") ในผลลัพธ์/แขนง IF/IFS จะแปลง literal เป็น id ให้ ข้อความในเงื่อนไขไม่ถูกแทนที่แบบค้นหาและแทนทั้งสูตร สูตรที่นำค่าของ List ไปเทียบกับข้อความรหัสธุรกิจโดยตรงในช่องอื่นต้องใช้ id ให้ตรงกับรูปแบบใหม่
- การกู้คืนไฟล์สำรองเดิมแปลงในไฟล์เตรียมก่อนกู้คืน ส่วนไฟล์ใหม่ไม่แปลง id ซ้ำ และปฏิเสธ List ที่อ้างรหัสภายในที่ไม่มีอยู่
- ทดสอบเพิ่ม: npm test และ node scripts/integration.cjs identity (ฐานข้อมูลแยก ครอบคลุม migration/rollback/restore, รหัสชนกัน, Key/Ref/List/EnumList, หน้าจอ Data, Actions และมือถือ/โหมดมืด)


### Login และ Session (เจ้าของแอป)

- ก่อนเปิดเวอร์ชันนี้ ให้ปิดแอปและสำรอง data.db ระบบเพิ่ม _users, _sessions และ _auth_attempts ใน transaction พร้อมไฟล์สำรองก่อน migration โดยรักษาตารางงานและข้อมูลเดิม
- เปิด localhost แล้วสร้างบัญชีเจ้าของแอปครั้งแรก (ชื่อ อีเมล รหัสผ่าน 10–128 ตัวอักษร) หลังจากนั้นใช้หน้า /login บัญชีแรกสร้างได้ครั้งเดียวและไม่มีการสมัครสมาชิกสาธารณะ
- รหัสผ่านใช้ scrypt พร้อม salt แบบสุ่ม ไม่เก็บรหัสผ่านจริง; Session เป็นรหัสสุ่มใน HttpOnly/SameSite Cookie และเก็บเฉพาะ hash ฝั่ง SQLite ใช้ Secure Cookie เมื่อ URL เป็น HTTPS
- Session มีอายุสูงสุด 12 ชั่วโมง และหมดอายุเมื่อไม่ใช้งาน 2 ชั่วโมง ออกจากระบบได้ที่หัวหน้า Builder หรือเมนูแอป; ในเมนูแอปมีออกจากระบบทุกอุปกรณ์
- หน้า Builder/runtime และ API ทั้งหมด (รวมรูปภาพและสำรองข้อมูล) ต้องเข้าสู่ระบบ การทำรายการตรวจ Origin และจำกัดการลองเข้าสู่ระบบผิด
- USEREMAIL() ใช้อีเมลจาก Session จริง ทั้งฟอร์ม สูตร และ API ไม่รับตัวตนจากพารามิเตอร์ as หรือ header ที่ผู้เรียกส่งมา ส่วนทดสอบสูตรใช้ผู้ใช้ปัจจุบัน
- เมื่อออกจากระบบ/เปลี่ยนบัญชีจะล้างแคชและโหลดหน้าต่างอื่นใหม่; Session หมดอายุระหว่างใช้งานจะกลับหน้า Login
- กู้คืนข้อมูลผ่านหน้า Backups จะรักษาบัญชีเจ้าของแอปปัจจุบันและยกเลิก Session ทั้งหมด ต้องเข้าสู่ระบบใหม่หลังการกู้คืน การใช้ data.db จากไฟล์โดยตรงยังคงมีบัญชีของไฟล์นั้น
- ขั้นนี้รองรับเจ้าของแอปเท่านั้น การเพิ่มผู้ใช้ บทบาท/สิทธิ์ และ User Settings เป็นขั้นถัดไป ตาราง role/permission เดิมยังไม่เชื่อมกับบัญชีระบบ
- เทสต์ใช้ฐานข้อมูลแยกเสมอ: npm test, node scripts/integration.cjs auth, npm run test:api. ชุดเดิมใช้ Session ทดสอบจริงผ่าน scripts/auth-test-preload.cjs โดยไม่ปิดการตรวจสิทธิ์ในโค้ดใช้งาน


## ผู้ใช้และสิทธิ์

สำรอง data.db ก่อนเปิดแอปหลังอัปเดตนี้ ระบบจะสำรองไฟล์ก่อน migration ไว้ใน backups/data.before-permissions-*.db อีกชั้นหนึ่ง บัญชี รหัสผ่าน ข้อมูลเดิม และ ID ยังคงอยู่

เจ้าของแอปเปิดเมนู **ผู้ใช้และสิทธิ์** (/users) แล้ว:
1. เปิดแท็บ **บทบาทและสิทธิ์** เพิ่มบทบาท เช่น พนักงาน หรือผู้ดูข้อมูล
2. เลือกสิทธิ์ดู เพิ่ม แก้ไข ลบแยกตามตาราง และเลือก Action ที่อนุญาต สิทธิ์เขียนต้องมีสิทธิ์ดูตารางด้วย
3. เปิดแท็บ **ผู้ใช้** เพิ่มชื่อ อีเมล รหัสผ่าน (10–128 ตัวอักษร) และเลือกบทบาท
4. ผู้ใช้เข้าสู่ระบบด้วยบัญชีของตน ผู้ใช้ทั่วไปจะเปิดหน้ารันแอปและเห็นเฉพาะข้อมูล/ปุ่มที่อนุญาต

บทบาทใหม่ไม่มีสิทธิ์โดยอัตโนมัติ สิทธิ์นี้เป็นระดับตาราง ยังไม่ได้จำกัดข้อมูลรายแถว สิทธิ์ **อนุญาตให้แก้ไขแอป** รวมการแก้โครงสร้าง สูตร View Action และข้อมูลทุกตาราง จึงควรให้เฉพาะผู้ดูแลที่ไว้ใจ ส่วนการจัดการบัญชีและไฟล์สำรองเป็นของเจ้าของแอปเท่านั้น ระบบต้องมีเจ้าของแอปที่เปิดใช้งานอย่างน้อยหนึ่งบัญชีเสมอ

แก้สิทธิ์บทบาท เปลี่ยนอีเมล/บทบาท ปิดบัญชี ตั้งรหัสผ่านใหม่ หรือสั่งออกจากระบบ จะยกเลิก Session ที่เกี่ยวข้องทันที การกู้คืนข้อมูลรักษาบัญชี/บทบาทปัจจุบัน ตัดสิทธิ์ของตารางและ Action ที่ไม่มีในข้อมูลที่กู้คืน และให้ทุกบัญชีเข้าสู่ระบบใหม่

บัญชีระบบแยกจากตาราง users/role/permission ที่ผู้ใช้สร้างเอง สูตร USEREMAIL() ใช้อีเมลจาก Session จริง การตรวจสิทธิ์ครอบคลุม API ข้อมูล Ref/Related สูตรข้ามตาราง รูปภาพ และ Action

ทดสอบ: npm test, npm run test:permissions, npm run test:api (ใช้ฐานข้อมูลแยกใน .test-data ไม่ใช้ data.db จริง)


## สูตรข้อมูลบัญชีและค่าตั้งค่าผู้ใช้

สำรอง data.db ก่อนเปิดแอปหลังอัปเดต ระบบสำรองก่อนเพิ่ม _user_setting_defs และ _user_setting_values เป็น data.before-user-settings-*.db ใน backups

- USEREMAIL(): อีเมลของบัญชีปัจจุบัน
- USERID(): รหัสบัญชีระบบ (_users.id) เป็นตัวเลข ไม่ใช่รหัสแถวของตารางข้อมูล
- USERNAME(): ชื่อบัญชีปัจจุบัน
- USERROLE(): ชื่อบทบาทที่แสดง เช่น เจ้าของแอป หรือ พนักงาน
- USERROLEKEY(): คีย์บทบาท เช่น owner หรือ role_... ซึ่งคงเดิมเมื่อเปลี่ยนชื่อบทบาท
- ISOWNER(): TRUE เฉพาะบทบาทเจ้าของแอป
- USERSETTINGS("branch"): ค่าตั้งค่าชื่อในระบบ branch ของบัญชีปัจจุบัน

เจ้าของแอปกำหนดช่องที่ ผู้ใช้และสิทธิ์ → ค่าตั้งค่าผู้ใช้ (ข้อความ ตัวเลข ใช่/ไม่ใช่ หรือเลือกหนึ่งรายการ) พร้อมค่าเริ่มต้น ผู้ใช้เลือกค่าของตนที่ เมนูแอป → ค่าตั้งค่าของฉัน บันทึกแล้วโหลดแอปใหม่ ค่าแยกตามบัญชีและเก็บใน data.db ค่าที่ผู้ใช้บันทึกเองจะทับค่าเริ่มต้น ถ้ายังไม่เคยบันทึกจะใช้ค่าเริ่มต้นล่าสุด ค่าค่าว่างคือ null และชื่อที่ไม่มีจริงจะแสดงข้อผิดพลาดภาษาไทย

สูตรใช้ได้ในค่าเริ่มต้น ช่องคำนวณ Show_If Editable_If Required_If Valid_If, Slice, View และ Action โดยใช้บัญชีจริงทั้งฝั่งฟอร์มและ API ตัวช่วยสูตรมีแท็บ บัญชีและค่าตั้งค่า เลือกชื่อบทบาทและค่าตั้งค่าเพื่อแทรกสูตรได้ ไม่ต้องจำคีย์บทบาท

ตัวอย่างเงื่อนไขแสดง View: AND(USERROLE() = "พนักงาน", USERSETTINGS("branch") = "กรุงเทพ")
ตัวอย่างค่าเริ่มต้นผู้สร้าง: USERNAME()
ตัวอย่างเงื่อนไขบทบาทที่ไม่ขึ้นกับชื่อที่แสดง: USERROLEKEY() = "owner"

ค่าตั้งค่าผู้ใช้เป็นความต้องการส่วนตัวที่ผู้ใช้แก้เองได้ สิทธิ์เข้าถึงตารางและ Action ยังคงตรวจด้วยบทบาทบนเซิร์ฟเวอร์ เปลี่ยนชนิดค่าตั้งค่าเดิมไม่ได้ ระบบป้องกันลบช่องที่สูตรในคอลัมน์ View Slice หรือ Action ยังใช้อยู่ และไม่อนุญาตตัดตัวเลือกที่ผู้ใช้บันทึกไว้ การกู้คืนข้อมูลรักษาบัญชี บทบาท นิยามและค่าตั้งค่าผู้ใช้ปัจจุบัน

ทดสอบเพิ่มเติม: npm run test:user-formulas (ฐานข้อมูลแยกใน .test-data)


## บัญชีผู้ใช้ สิทธิ์แถว และ Excel

- หน้าเข้าสู่ระบบใช้ชื่อ ไอคอน สี ฟอนต์ และโหมดของแอป การตั้งค่าที่เปิดให้อ่านก่อนเข้าสู่ระบบมีเฉพาะรูปลักษณ์
- ในผู้ใช้และสิทธิ์ > บทบาทและสิทธิ์ > แก้ไขสิทธิ์ > ขั้นสูง · สิทธิ์ระดับแถว ตั้งกฎดู เพิ่ม แก้ไข และลบของแต่ละตารางได้ เว้นว่างหมายถึงทุกแถวที่บทบาทมีสิทธิ์ในตาราง
- ตัวอย่างกฎดูงาน: `[assigned_email] = USEREMAIL()` หรือ `IN([branch], LIST("A", "B"))` ชื่อคอลัมน์ต้องตรงกับชื่อในระบบ กฎใช้คอลัมน์ปกติและข้อมูลบัญชี ไม่ใช้ช่องคำนวณ, SELECT, Ref ข้ามตาราง หรือ USERSETTINGS ที่ผู้ใช้เปลี่ยนเองได้
- กฎดูใช้กับ API, ค้นหา, จำนวนรายการ, Ref, Related, SELECT, รูปภาพ และ Excel ด้วย การเพิ่ม/แก้ไขต้องมีสิทธิ์ดูแถวหลังบันทึก เจ้าของและผู้แก้ไขแอปเข้าถึงทุกแถวได้ การเปลี่ยนสิทธิ์ให้ผู้ใช้เข้าสู่ระบบใหม่
- คอลัมน์ที่ใช้ในกฎเปลี่ยนชื่อได้ ระบบปรับสูตรให้ ลบหรือแปลงชนิดทับคอลัมน์นั้นต้องแก้กฎก่อน (ยังคัดลอกไปคอลัมน์ใหม่ได้)
- ปุ่ม Excel ในหน้าข้อมูลรองรับ .xlsx: ส่งออกไม่เกิน 10,000 แถวที่มองเห็น พร้อมชีตคู่มือ; นำเข้าไฟล์ไม่เกิน 10 MB/5,000 แถว โดยใช้หัวคอลัมน์แถวแรก เลือกชีต ตรวจตัวอย่าง แล้วจึงยืนยัน
- เพิ่มข้อมูลสร้าง id ใหม่ แก้ไขจับคู่ด้วย id เดิม Ref/List อ้างอิง id, EnumList/List ใช้ JSON, ช่องคำนวณไม่นำเข้า สูตรในเซลล์ Excel ต้องแปลงเป็นค่าก่อน
- นำเข้าตรวจสิทธิ์ เงื่อนไข ค่าห้ามซ้ำ และ Ref เหมือนฟอร์ม หากมีข้อผิดพลาดยกเลิกทั้งชุด การตรวจตัวอย่างไม่เก็บข้อมูล ระบบสำรองไฟล์ก่อนนำเข้าจริง
- Action รองรับเปลี่ยนค่า ลบ คัดลอก เพิ่มแถว เปิด View และเปิดลิงก์ ตั้งไอคอน สี #RRGGBB, พื้นสี/เส้นขอบ/ข้อความ, ขนาด และเฉพาะไอคอนได้ ลิงก์รองรับ http, https หรือเส้นทาง / ภายใน
- Action คัดลอกช่องที่แก้ไขได้ ยกเว้น Key และช่องห้ามซ้ำ ช่องอื่นใช้ค่าเริ่มต้น สูตรค่าที่กำหนดอ่านแถวต้นทาง การเพิ่มแถวทำในตารางที่เลือกของ Action
- หน้าตั้งค่ามีตัวอย่างรูปลักษณ์และแยกค่าตั้งต้นหน้าจอทั้งหมดไว้ในขั้นสูง

ก่อนเปิดเวอร์ชันนี้ กรุณาสำรอง data.db: migration เพิ่ม _role_row_rules และ config_json/appearance_json ใน _actions โดยสำรองไฟล์ให้อัตโนมัติก่อนเปลี่ยนโครงสร้าง

ทดสอบ: `npm test`, `npm run test:api`, `node scripts/integration.cjs upgrades` (ใช้ฐานข้อมูลแยก)

หมายเหตุแพ็กเกจ: ExcelJS ใช้ uuid 11.1.1 ผ่าน override เพื่อแก้รายการแจ้งเตือนของไลบรารีที่เพิ่มใหม่ รายการ npm audit ที่เหลือเป็น Next.js 14.2.15 และ postcss ของโปรเจกต์เดิม การอัปเดตส่วนนี้ต้องทดสอบการย้ายเวอร์ชัน Next.js แยกต่างหาก


Action เพิ่มเติม: เปิดฟอร์มแก้ไขแถวเดิม / เปิดฟอร์มเพิ่มข้อมูล (เลือก View แบบ form), โทรออก / SMS / อีเมล (สูตรส่งกลับเบอร์หรืออีเมล ไม่ส่งอัตโนมัติ ต้องมีแอปรองรับบนอุปกรณ์), ทำชุด Action 1–10 ขั้นตอนในตารางเดียวกัน (set/add/copy/delete; delete เฉพาะขั้นสุดท้าย). ชุดอ่านค่าล่าสุดทุกขั้น ตรวจสิทธิ์และเงื่อนไขของทุก Action ย่อย และ rollback ทั้งชุดเมื่อผิดพลาด ต้องยืนยันก่อนทำชุดเสมอ. ไม่ต้อง migration ใหม่ ใช้ config_json เดิม.

Action เปิดฟอร์มใหม่: config.initial_values จับคู่คอลัมน์ปลายทางกับสูตรจากแถวต้นทาง เช่น [_THISROW].[name]. คำนวณฝั่ง API แล้วส่งผ่าน history state (fallback ใช้ sessionStorage token ไม่ใส่ค่าฟอร์มใน URL). ไม่บันทึกจนกดบันทึก ตรวจสิทธิ์และข้อมูลตามปกติ. Action open_detail เลือก View detail และ config.row_expr ให้ค่า id ภายในของแถวปลายทาง เช่น [_THISROW].[user_id]; ตรวจสิทธิ์ระดับแถวและ Slice ก่อนเปิด. ตัวเลือก open_view ใหม่ใน UI เฉพาะ Primary/Menu ที่ไม่ใช่ form/detail; การตั้งค่าเก่ายังเปิดได้เพื่อความเข้ากันได้. กลุ่มตารางใน Action หุบไว้ก่อนเมื่อเปิดหน้า.


การตั้งค่าไอคอน/หน้าแรก/รูปภาพ: เลือกไอคอนเดิม, URL http(s) ของรูป, หรืออัปโหลดครอปตรงกลาง 512×512. เฉพาะรูปที่เลือกเป็นไอคอนปัจจุบันเปิดให้หน้า login อ่านผ่าน /api/app-icon ได้ รูปข้อมูลอื่นยังตรวจสิทธิ์เดิม. หน้าแรกเลือก Primary/Menu ที่ไม่ใช่ฟอร์ม/รายละเอียด ตรวจสิทธิ์และ Show_If หลัง login และคงลิงก์ปลายทางเฉพาะที่ผู้ใช้เปิดไว้.
รูปใหม่ย่อด้านยาว 640/1280/1920/2560 หรือขนาดต้นฉบับ, JPEG/WebP/ชนิดต้นฉบับ, คุณภาพ 40–100, ขนาดสูงสุด 0.5/1/2/5 MB. ย่อในเบราว์เซอร์ก่อนส่งและตรวจขนาด/ชนิดไฟล์ที่ API. GIF กลายเป็นภาพนิ่งเมื่อย่อ/แปลง. รูปยังอยู่ใน data.db เสมอ; เลือกสร้างไฟล์สำเนาภายใต้ uploads ข้าง data.db ได้ โดย Path ของคอลัมน์รูปภาพแทนโฟลเดอร์ตั้งต้นของแอพ. ใช้ relative path ภาษาอังกฤษ ตัวเลข _ - คั่นด้วย /; ห้าม .., ไดรฟ์, Windows device names และลิงก์โฟลเดอร์. ไม่ย้ายหรือเปลี่ยนรูปเก่า ไม่เปิด uploads เป็นเว็บสาธารณะ; สำรอง data.db ยังคงครอบคลุมรูปทั้งหมด และแอปยังอ่านรูปได้แม้สำเนาหาย. รูปที่ลิงก์จากเว็บไซต์ภายนอกไม่รวมใน data.db.
Migration เพิ่ม _columns.image_path, _images.storage_path และการตั้งค่าใหม่ใน _app_settings พร้อมสำรอง SQLite ก่อนอัปเดตโดยอัตโนมัติ; ควรสำรอง data.db เองก่อนใช้เวอร์ชันใหม่ด้วย.


## View: แผนที่ กราฟ ปฏิทิน และแดชบอร์ด

เลือกชนิดใน View > การตั้งค่า View แล้วกำหนดช่องข้อมูลในแท็บรูปแบบหน้าจอ ตัวอย่างปรับตามค่าก่อนบันทึก ใช้บันทึก View เมื่อพร้อม และยกเลิกเพื่อกลับค่าเดิมได้

- แผนที่: ใช้คอลัมน์ตัวเลขละติจูด/ลองจิจูดคนละคอลัมน์ ตั้งชื่อจุด ซูม ความสูง และปรับกรอบอัตโนมัติได้ ใช้ Leaflet 1.9.4 ที่ติดตั้งในโปรเจกต์ พื้นแผนที่ OpenStreetMap ต้องใช้อินเทอร์เน็ต ไม่มีการดาวน์โหลดแผนที่ล่วงหน้าหรือเก็บเพื่อใช้ออฟไลน์ และแสดงที่มาของแผนที่เสมอ เมื่อพื้นแผนที่โหลดไม่ได้ยังเปิดข้อมูลจากรายการจุดได้ นโยบาย: https://operations.osmfoundation.org/policies/tiles/
- กราฟ: แท่งตั้ง/นอน เส้น พื้นที่ วงกลม โดนัท เลือกคอลัมน์แบ่งกลุ่มและนับ/รวม/เฉลี่ย/ต่ำสุด/สูงสุด ตั้งลำดับ จำนวนกลุ่ม ขนาด และสีได้ กดกลุ่มเพื่อดูข้อมูลต้นทาง วงกลมต้องไม่มีค่าติดลบและผลรวมมากกว่า 0 การค้นหาจะกรองข้อมูลก่อนคำนวณ
- ปฏิทิน: ช่องวันที่หรือวัน–เวลาเริ่มและสิ้นสุด เลือกหัวเรื่อง สีตามกลุ่ม วันแรกของสัปดาห์ และมุมมองเดือน/สัปดาห์/วัน/รายการนัดหมาย แสดงเวลาไทย กดรายการเปิดรายละเอียด วันที่สิ้นสุดรวมวันนั้น ส่วนวัน–เวลาสิ้นสุดเวลาเที่ยงคืนไม่รวมวันถัดไป ไม่นำกิจกรรมที่วันที่ไม่ถูกต้องหรือจบก่อนเริ่มมาแสดง
- แดชบอร์ด: รวมได้ 8 View จากหลายตาราง เรียงต่อกัน ตาราง 1–3 ช่อง หรือแท็บ ปรับลำดับ ระยะห่าง ความสูง และหัวข้อได้ มือถือเป็น 1 ช่อง กดหัวข้อเปิดหน้าเต็ม ไม่ซ้อนแดชบอร์ด/ฟอร์ม/รายละเอียดที่ไม่มีแถวปัจจุบัน ใช้สิทธิ์ตารางหลักในการเข้าหน้า แล้วตรวจสิทธิ์และ Show_If ของทุก View ลูกอีกครั้ง

ค่าตั้งต้นสำหรับทั้งสี่ชนิดอยู่ในการตั้งค่าแอพ รูปแบบเฉพาะ View ใช้แทนค่าตั้งต้น การตั้งค่าเก็บใน display_json เดิม ไม่ต้องเพิ่มตารางข้อมูล

ข้อมูลแผนที่และกราฟรวมทุกแถวที่มีสิทธิ์อ่านในตารางหรือ Slice สูงสุด 10,000 แถว ถ้าเกินจะแจ้งให้ลดด้วย Slice ไม่ตัดข้อมูลเงียบ ๆ ปฏิทินดึงเฉพาะช่วงที่เปิด ถ้าใช้วันเริ่ม/สิ้นสุดที่เก็บจริงจะกรองช่วงด้วย SQL ก่อนคำนวณ และตรวจสิทธิ์ระดับแถวก่อนส่งออกทุกครั้ง


### พิกัด (Lat, Long) และตำแหน่งเครื่อง
- Data → คอลัมน์ → ชนิดข้อมูล **พิกัด (Lat, Long)** เก็บพิกัดสองค่าในช่องเดียว เช่น `13.7097601,100.8135513` เป็น TEXT ใน SQLite ตรวจช่วงพิกัดทั้งฟอร์มและ API
- เปิด **ใช้ตำแหน่งปัจจุบัน (GPS)** เพื่อเติมจากเครื่องอัตโนมัติเมื่อเพิ่มข้อมูล ฟอร์มจะไม่ให้พิมพ์หรือจิ้มแผนที่เพื่อเปลี่ยนพิกัดเอง ต้องอนุญาตตำแหน่งของเว็บไซต์และเปิดบริการตำแหน่งในเครื่อง
- เมื่อแก้แถวเดิมจะเก็บพิกัดเดิมไว้ กด **ดึงตำแหน่งปัจจุบันใหม่** หากต้องการเปลี่ยนตำแหน่ง ไม่เปลี่ยนตำแหน่งย้อนหลังเพียงเพราะแก้ข้อความหรือรูปภาพ
- หากไม่ได้เปิด GPS อัตโนมัติ สามารถพิมพ์พิกัด จิ้มแผนที่ หรือกดใช้ตำแหน่งปัจจุบันได้ พื้นแผนที่ OpenStreetMap ต้องใช้อินเทอร์เน็ต
- View แผนที่ → รูปแบบหน้าจอ → เลือกคอลัมน์พิกัดเพียงช่องเดียว และเลือกคอลัมน์รูปภาพของจุดได้ กดภาพในจุดเพื่อดูภาพขยาย รายละเอียดแสดงพิกัดพร้อมแผนที่ร่วมกับรูปภาพได้
- แผนที่เก่าที่ใช้ละติจูด/ลองจิจูดสองช่องยังเปิดได้ เปลี่ยนมาใช้ช่องเดียวเมื่อพร้อม ระบบไม่ลบหรือรวมคอลัมน์เดิมเอง
- เวอร์ชันนี้เพิ่ม metadata `_columns.gps_auto` โดยสำรองฐานข้อมูลก่อน migration และรักษาข้อมูล/รหัสแถวเดิม ควรสำรอง data.db ของคุณก่อนรันเวอร์ชันใหม่
- ทดสอบด้วย `npm test` และ `node scripts/integration.cjs location` ใช้ตำแหน่งและฐานข้อมูลจำลอง ไม่มีการร้องขอ GPS จริงจากเครื่องผู้ทดสอบ


### Label ข้อความและรูปภาพ
- Data → ตาราง → คอลัมน์และการตั้งค่า: เลือก Label ในคอลัมน์ข้อความ 1 ช่อง และในคอลัมน์รูปภาพ 1 ช่องได้พร้อมกัน
- รูป Label ขนาดเล็กแสดงหน้าข้อความในรายการ รายละเอียด ตัวเลือก Ref, List/Related และ EnumList ที่ดึงตัวเลือกจากตาราง แถวไม่มีรูปยังใช้ชื่อเดิมได้
- เปลี่ยน Label รูปภาพจะเปลี่ยนเฉพาะกลุ่มรูปภาพ เปลี่ยน Label ข้อความจะเปลี่ยนเฉพาะกลุ่มข้อความ ใช้ is_label เดิมโดยแยกชนิด ไม่เพิ่มโครงสร้างฐานข้อมูล
- ข้อมูลที่เก็บ, Key/Ref/List และสูตรยังใช้ค่าจริงหรือข้อความเดิม รูปเป็นข้อมูลแสดงผล __image และ <ref>__image ไม่รวมรูปลงในค่า Key
- สิทธิ์ระดับแถวยังใช้กับชื่อและรูป Label: แถวอ้างอิงที่ไม่มีสิทธิ์ดูจะไม่ส่งชื่อหรือ URL รูปมาให้
- ควรสำรอง data.db ก่อนเปลี่ยนการตั้งค่าคอลัมน์ ทดสอบแยกด้วย node scripts/integration.cjs imagelabels


### ปลายทางหลังบันทึกฟอร์ม
- View → เลือกฟอร์ม → รูปแบบหน้าจอ → **หลังบันทึกข้อมูล**
- **กลับหน้าก่อนหน้า (ค่าตั้งต้น)**: กลับหน้าที่เปิดฟอร์มมา เช่น รายการหรือรายละเอียดเดิม
- **หน้ารายละเอียดของข้อมูลที่บันทึก**: เปิดแถวที่เพิ่งเพิ่มหรือแก้ไขด้วย id จริง พร้อมแจ้งบันทึกสำเร็จ แทนหน้าฟอร์มในประวัติการย้อนกลับ เพื่อไม่ย้อนกลับไปฟอร์มที่เสร็จแล้ว
- ถ้าแก้ไขจากรายละเอียดของแถวเดียวกัน จะกลับรายละเอียดเดิม แทนการสร้างหน้าซ้ำในประวัติ
- ตั้งเป็นค่าตั้งต้นทั้งแอปได้ที่ การตั้งค่าแอพ → ค่าตั้งต้นรูปแบบหน้าจอ → ฟอร์ม ค่าที่กำหนดในแต่ละ View ใช้แทนค่าตั้งต้น
- ฟอร์มเพิ่ม/แก้ไขในหน้า Data ใช้การตั้งค่าของ Reference View ฟอร์มของตารางเดียวกัน การยกเลิกหรือบันทึกไม่ผ่านยังคงพฤติกรรมเดิม
- เก็บตัวเลือก form_after_save (back/detail) ใน display_json เดิม ไม่มี migration โครงสร้างฐานข้อมูล ก่อนบันทึกการตั้งค่าควรสำรอง data.db
- ทดสอบด้วย node scripts/integration.cjs formsave และ npm test โดยใช้ฐานข้อมูลทดสอบแยก

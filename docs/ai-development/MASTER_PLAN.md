# แผนแม่บท AI-Native App Builder

สถานะ **ข้อเสนอเพื่ออนุมัติ** · ตรวจหลักฐาน 26 พฤศจิกายน 2569

เลือก **Copilot ที่เสนอแผนและรอการอนุมัติ** ให้ทำงานผ่านกลไก Builder เดิม ระบบพร้อมต่อยอดสูตรและโครงสร้างในฉบับร่าง มีช่องว่างหลักเรื่อง Canonical Context, การตรวจผลก่อนเปลี่ยน, การบันทึกสิทธิ์อนุมัติ และหลักฐานผลของแต่ละแผน รักษาแอป Runtime ให้ทำงานได้เมื่อ Provider ขัดข้อง

| เอกสาร | ขอบเขต |
|---|---|
| [01 ระบบปัจจุบัน](01_CURRENT_SYSTEM.md) | โครงสร้าง ฟีเจอร์ คะแนนความพร้อม หนี้ทางเทคนิค ช่องว่าง |
| [02 สถาปัตยกรรมและ UX](02_ARCHITECTURE.md) | เปรียบเทียบ A/B/C, Context, Capability Registry, UX, ADR และ Mermaid |

| [05 Roadmap](05_ROADMAP.md) | MVP, Phase 0–6, Dependencies, Backlog และเกณฑ์รับมอบ |

**ขอบเขตหลักฐาน** รายงานใช้ Source Code ใน working tree รวมงานค้างจากก่อนหน้า สถานะ Production และการทำงานของ Provider ด้วยคีย์จริงยังไม่ได้ยืนยัน ตัวเลข SLO และ Effort เป็นสมมติฐานเพื่อวางแผน

**เริ่มหลังอนุมัติ** เก็บ baseline ด้วยข้อมูลสังเคราะห์ → แยก Context/Registry และทดสอบสิทธิ์ → ทำแผนที่ตรวจ diff และ revision ได้ → ย้ายเครื่องมือโครงสร้างเดิมเข้าสู่ทางเดินเดียว → เปิด pilot และวัดผล ปล่อย Blueprint, Agent และหลาย Provider ตามหลักฐานความต้องการ

**ทรัพยากร** MVP ประมาณ 41–63 คน-วัน ค่า Provider ตัวอย่าง $10–33 ต่อ 1,000 คำขอตามรุ่นและสมมติฐานในเอกสาร 04 ค่าแรงและสภาพแวดล้อมแยกจากตัวเลขนี้

**เรื่องขออนุมัติ** ข้อมูลที่ส่งออกไปยัง Provider, สิทธิ์ใช้ AI รายแอป, รุ่นและค่าใช้จ่าย pilot, อายุแผนและประวัติ, ขอบเขต rollback และเกณฑ์เปิดใช้งาน การเผยแพร่จริงผ่าน App Versions ตามขั้นตอนเดิม

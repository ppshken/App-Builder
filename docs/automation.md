# Automation, เชื่อม API และสร้าง PDF

ก่อนเริ่มใช้เวอร์ชันนี้ ให้ปิดแอปและสำรอง `data.db` ก่อน เมื่อเปิดใหม่ ระบบจะสำรองฐานข้อมูลเดิมในโฟลเดอร์ `backups` แล้วเพิ่มตารางเก็บ Automation แม่แบบ PDF และคิวงาน โดยไม่เปลี่ยนข้อมูลเดิม

## เริ่มจากรายงานตรวจสภาพ

1. เข้าสู่ระบบด้วยบัญชีเจ้าของแอป แล้วเลือกเมนู **Automation → แม่แบบ PDF → เพิ่มแม่แบบ PDF**
2. เลือกตาราง เช่น inspection ใส่ชื่อแม่แบบและสูตรหัวรายงาน เช่น `CONCATENATE("ใบตรวจสภาพ ",[inspection_no])`
3. เลือกคอลัมน์และเรียงลำดับ เพิ่มตารางลูกที่มี Ref อ้างอิงตารางนี้ได้ คอลัมน์รูปภาพและลายเซ็นจะใส่รูปลงในรายงาน
4. ระบุ id ข้อมูลจริงสำหรับตัวอย่าง แล้วกด **แสดงตัวอย่าง PDF** ดูผลก่อนกด **บันทึกแม่แบบ PDF**
5. ไปแท็บ **Automation → เพิ่ม Automation** เลือกตารางเดียวกัน เหตุการณ์ และสูตรเงื่อนไข
6. เพิ่มขั้นตอน **สร้างไฟล์ PDF** เลือกแม่แบบและสูตรชื่อไฟล์ เช่น `CONCATENATE("ใบตรวจ-",[inspection_no])` ระบบเติม .pdf ให้เอง
7. หากต้องการให้ผู้ใช้ดาวน์โหลดจากแถวข้อมูล ให้เพิ่มคอลัมน์ชนิด **File** แล้วเลือกคอลัมน์นั้นใน **เก็บไฟล์กลับลงคอลัมน์** หรือดาวน์โหลดจากประวัติการทำงานได้
8. เปิดใช้งานแล้วบันทึก ถ้าเลือกเหตุการณ์แบบกดปุ่ม ให้ไปหน้า Action สร้างปุ่มชนิด **เริ่ม Automation** และเลือกงานนี้ หรือสั่งทำงานกับ id จากหน้าตั้งค่า Automation ได้

แม่แบบเริ่มต้นเป็น A4 แนวตั้ง/แนวนอน ใช้ฟอนต์ Sarabun ในโปรเจกต์ รองรับภาษาไทย คอลัมน์ที่เลือก และรายการลูก สูงสุด 200 รายการต่อตารางลูก รูปทั้งหมดรวมไม่เกิน 12 MB และ PDF ไม่เกิน 20 MB รูปจาก /api/images จะแนบในไฟล์ ส่วนลิงก์รูปภายนอกจะแสดงข้อความแทน ไม่ดึงรูปจากอินเทอร์เน็ต

การสร้าง PDF ต้องมี Microsoft Edge ในเครื่อง หรือรัน `npx playwright install chromium` ใช้ Node.js 20 ขึ้นไป หากใช้ Chromium ที่ติดตั้งเอง กำหนด `NOCODE_PDF_BROWSER_PATH` เป็นเส้นทางไฟล์โปรแกรมได้

## เหตุการณ์และเงื่อนไข

- **กดปุ่มหรือสั่งทำงาน**: เริ่มเมื่อกด Action หรือเริ่มงานจากหน้าตั้งค่า
- **เมื่อเพิ่มข้อมูล**: เข้าคิวหลังแถวหลักและรายการลูกบันทึกผ่านทั้งหมด
- **เมื่อแก้ไขข้อมูล**: ทำเฉพาะเมื่อค่าข้อมูลจริงเปลี่ยน เลือกคอลัมน์เฝ้าดูได้ ไม่เลือกหมายถึงดูทุกคอลัมน์ข้อมูลจริง
- **เมื่อลบข้อมูล**: ใช้ค่าของแถวก่อนลบสำหรับส่ง Webhook หรือ PDF เฉพาะข้อมูลหลัก รับค่ากลับมาอัปเดตแถวที่ลบแล้วไม่ได้ หากรายงานมีรายการลูก ให้สร้าง PDF ก่อนลบด้วยเหตุการณ์กดปุ่ม แล้ววาง Action ลบเป็นขั้นตอนสุดท้าย
- **ตามเวลา**: ทำทุกจำนวนเวลาที่กำหนด เช่น 60 นาที หรือ 1440 นาที เริ่มนับจากตอนบันทึก ต้องเปิดเซิร์ฟเวอร์ไว้ เลือกแถวที่ตรงเงื่อนไขได้ไม่เกิน 500 แถวและตรวจไม่เกิน 10,000 แถวต่อรอบ ถ้าเกินจะไม่เข้าคิวบางส่วน และแสดงข้อผิดพลาดในประวัติ กรุณาแบ่งตาราง/เงื่อนไข

สูตรเงื่อนไขใช้รูปแบบเดียวกับคอลัมน์ เช่น `[status] = "ตรวจเสร็จ"` หรือ `AND([status] = "ตรวจเสร็จ", ISNOTBLANK([driver_signature]))` และ `TRUE` หมายถึงผ่านทุกแถวที่เกิดเหตุการณ์

เงื่อนไขตรวจใน transaction ของการบันทึก งานเข้าคิวพร้อมข้อมูล ไม่ส่ง API หรือเปิดเบราว์เซอร์ PDF ระหว่าง transaction งานที่เริ่มแล้วใช้ข้อมูลล่าสุดของแถวในขณะทำแต่ละขั้นตอน

## ขั้นตอนที่ทำได้

- **เรียก Action**: เลือก Action เปลี่ยนค่า เพิ่มแถว คัดลอก ลบ หรือชุด Action ของตารางเดียวกัน Action ลบต้องเป็นขั้นตอนสุดท้าย
- **ส่ง Webhook / API**: ส่ง JSON ด้วย POST, PUT หรือ PATCH แต่ละช่องมีสูตรของตัวเอง เลือกรับค่าจาก JSON กลับมาลงคอลัมน์ได้ เช่น `result.reference`
- **สร้างไฟล์ PDF**: ใช้แม่แบบ เก็บไฟล์ใน data.db และเก็บลิงก์กลับลงคอลัมน์ File ได้

เรียงได้สูงสุด 10 ขั้นตอน การแก้ข้อมูลจาก Automation จะไม่เรียก Automation ต่อซ้ำ เพื่อป้องกันงานวน หากต้องการหลายงาน ให้เรียงขั้นตอนใน Automation เดียว

## อนุญาตปลายทาง API และเก็บรหัสลับ

การส่ง Webhook **ปิดเป็นค่าเริ่มต้น** เจ้าของต้องระบุปลายทางในไฟล์ `.env.local` ก่อน เช่น:

```dotenv
NOCODE_WEBHOOK_ORIGINS=https://api.example.com,https://hooks.example.com
SERVICE_API_TOKEN=ใส่รหัสลับของบริการที่คุณใช้
```

แทนที่ด้วยปลายทางของคุณจริง แล้วเริ่มเซิร์ฟเวอร์ใหม่ ในหน้าขั้นตอนใส่ URL เต็ม เช่น `https://api.example.com/inspection` ช่องชื่อค่าลับใส่แค่ `SERVICE_API_TOKEN` ระบบอ่านค่าลับจากเซิร์ฟเวอร์และส่งเป็น Bearer Token ไม่เก็บตัวรหัสลับลง metadata หรือประวัติการแก้ไข และไม่ใส่ไฟล์ .env.local ขึ้น Git

ชื่อเว็บต้องตรงทั้ง http/https และพอร์ต ไม่มีการตามลิงก์เปลี่ยนปลายทาง (redirect) ส่งได้ไม่เกิน 1 MB รับกลับไม่เกิน 1 MB และหมดเวลาหลัง 15 วินาที การส่งแต่ละขั้นตอนมี Idempotency-Key คงเดิมเมื่อทำใหม่ แต่ปลายทางต้องรองรับคีย์นี้จึงจะป้องกันรายการซ้ำได้

ตัวอย่าง JSON ที่ตั้งค่าในหน้า:

| ชื่อช่อง JSON | สูตร |
| --- | --- |
| inspection_id | [id] |
| inspection_no | [inspection_no] |
| status | [status] |

หาก API ตอบ `{"result":{"reference":"EXT-001"}}` เลือกคอลัมน์ข้อความที่ต้องการ แล้วใส่เส้นทาง JSON `result.reference` เพื่อเก็บค่า EXT-001 ข้อมูลที่รับกลับยังต้องผ่านชนิดข้อมูล สูตร Valid_If และสิทธิ์เหมือนการบันทึกปกติ

## สิทธิ์และประวัติ

เจ้าของแอปเท่านั้นที่ตั้งค่า Automation แม่แบบ และดูประวัติได้ ผู้ใช้ทั่วไปกด Action เริ่มงานได้เมื่อได้รับสิทธิ์ปุ่มและตาราง งานตรวจสิทธิ์ปัจจุบันของผู้สั่งก่อนแต่ละขั้นตอน ต้องอนุญาต Action ย่อยและตารางที่งานใช้ด้วย งานตามเวลาทำในนามเจ้าของที่บันทึก Automation

ประวัติแสดงสถานะ ขั้นตอนที่สำเร็จ HTTP ของ API ข้อผิดพลาด และลิงก์ PDF เปลี่ยนการตั้งค่าจะมี Audit log ด้วย ถ้าล้มเหลว งานจะหยุด ไม่ส่ง API ซ้ำอัตโนมัติ กด **ทำขั้นตอนที่ล้มเหลวใหม่** จะเริ่มจากขั้นตอนที่ยังไม่สำเร็จ โดยขอยืนยันก่อน เพราะปลายทางอาจรับข้อมูลไปแล้วแม้คำขอตอบกลับไม่สำเร็จ

ถ้าเซิร์ฟเวอร์หยุด คิวที่ยังไม่เริ่มจะทำต่อเมื่อเปิดเซิร์ฟเวอร์ งานที่หยุดกลางขั้นตอนจะเป็นไม่สำเร็จหลัง 5 นาทีเพื่อรอให้เจ้าของตรวจผลก่อนสั่งใหม่ การกู้คืนฐานข้อมูลจะปิด Automation และยกเลิกงานที่รอ/กำลังทำ เพื่อไม่เล่นงานเก่าซ้ำ ให้ตรวจและเปิดใช้งานใหม่เอง

ยังไม่รวมการรับ Webhook จากภายนอก ตัวเชื่อมต่อเฉพาะบริการ อีเมล/LINE โดยตรง หรือแก้แม่แบบ PDF แบบลากวาง สามารถใช้ Webhook ต่อบริการที่มี API ได้ก่อน

## ออกแบบแม่แบบ PDF แบบลากวาง
เลือกแม่แบบ PDF > วิธีจัดรูปแบบแม่แบบ > ออกแบบเอง · ลากวาง จากนั้นเพิ่มข้อความ ช่องข้อมูล รูปภาพ/ลายเซ็น เส้น หรือกรอบ ลากย้ายและจับมุมขวาล่างเพื่อปรับขนาด ปรับตำแหน่งเป็นมิลลิเมตรได้ กดแสดงตัวอย่าง PDF ด้วย id แถวจริง และบันทึกแม่แบบเมื่อพอใจ

พื้นที่ออกแบบคือกระดาษ A4 ด้านในเว้นขอบ 16 mm รายการลูกต่อท้ายหน้าใหม่และขยายหลายหน้าอัตโนมัติ รูปภาพใช้คอลัมน์ที่เก็บรูปในระบบ เลขหน้าบนพื้นที่ออกแบบแสดง 1 สำหรับหน้าแรก ข้อความที่เกินกรอบจะถูกตัด ให้ขยายกรอบก่อนบันทึก เปลี่ยนกลับเป็นรายงานมาตรฐานจะล้างการจัดวางเมื่อบันทึก รองรับสูงสุด 100 องค์ประกอบ ไม่รองรับ HTML หรือสคริปต์ที่ผู้ใช้กรอก

## โฟลเดอร์ไฟล์และเปิด PDF
Data > คอลัมน์ชนิด File > Path โฟลเดอร์ไฟล์ เช่น reports/inspection จะเก็บไฟล์ใหม่ใน uploads/reports/inspection ข้าง data.db ทั้งไฟล์ที่อัปโหลดและ PDF ที่ Automation เก็บกลับคอลัมน์นั้น โดยใช้รหัสไฟล์นำหน้าชื่อเพื่อไม่ให้ชนกัน ฐานข้อมูลยังเก็บเนื้อไฟล์ครบเพื่อสำรองและกู้คืนได้ ไฟล์เดิมไม่ย้ายอัตโนมัติ เว้น Path ว่างเพื่อเก็บเฉพาะฐานข้อมูล โฟลเดอร์ใช้ Path สัมพัทธ์ ไม่รับไดรฟ์หรือ ..

กด “เปิดไฟล์” ในแอปเพื่อเปิดแท็บใหม่ PDF รูปภาพ และข้อความจะเปิดในเบราว์เซอร์ที่รองรับ ส่วนชนิดอื่นดาวน์โหลดตามการรองรับของเบราว์เซอร์ การกู้คืน data.db กู้ไฟล์ให้เปิดจากระบบได้ แต่ไม่สร้างสำเนาโฟลเดอร์เก่าขึ้นใหม่ ไฟล์ใน uploads ไม่เป็นลิงก์สาธารณะ การเปิดจากแอปยังตรวจสิทธิ์ตารางและระดับแถว

# ความพร้อมก่อนใช้งานจริง

ปรับปรุง 20 ตุลาคม 2569

## 1. ตรวจสุขภาพแอพ

เปิดเมนู **ตรวจสุขภาพแอพ** แล้วกด **ตรวจสุขภาพแอพ** ระบบอ่านการตั้งค่าตาราง สูตร View Slice Action Automation และแม่แบบ PDF พร้อมลิงก์ไปแก้รายการที่พบปัญหา เลือกตรวจข้อมูลตัวอย่างเพื่อคำนวณสูตรกับ 10 แถวแรกของแต่ละตาราง การตรวจนี้ไม่แก้ข้อมูล และไม่ได้รับรองว่าข้อมูลทุกแถวผ่านเงื่อนไข

## 2. จำลองการทำงาน

ในหน้า Action หรือ Automation เปิด **ทดสอบการทำงาน · ไม่บันทึกข้อมูล** ระบุ id ที่มีอยู่ แล้วกด **จำลองการทำงาน** หรือเลือกรายการจากหน้าตรวจสุขภาพ ระบบใช้เครื่องคำนวณ Action ตัวเดียวกับการทำงานจริง แสดงเงื่อนไข สูตร ค่าที่อ่าน ค่าก่อน–หลัง และผลเพิ่ม/อัปเดต/ลบแถว แล้ว rollback ธุรกรรมทั้งหมด รวม ID ที่จอง คิวงาน และ audit ที่เกิดในธุรกรรมนั้น

Action แบบอ่านค่าเดิมพร้อมกันและแบบตามลำดับแสดงผลต่างกันตามค่าที่ตั้งจริง Automation รองรับ Action ของแถวแม่ผ่าน Ref การส่ง API แสดงเฉพาะแผน payload ไม่อ่านค่าลับ bearer จาก environment และไม่ส่งเครือข่าย การสร้าง PDF แสดงชื่อไฟล์และคอลัมน์ปลายทาง แต่ไม่สร้างไฟล์ หากขั้นถัดไปต้องใช้ค่าตอบกลับจากภายนอก ระบบแสดงว่าผลยังไม่ทราบ ไม่เดาผลสำเร็จแทนบริการภายนอก

ทดสอบการตั้งค่าที่บันทึกแล้ว ถ้าต้องการทดลองก่อนเผยแพร่ ให้บันทึกในฉบับร่าง

## 3. ฉบับร่างและเวอร์ชัน

สำหรับเจ้าของแอพ เปิด **เวอร์ชันแอพ** → ตั้งชื่อ → **สร้างฉบับร่างจากเวอร์ชันจริง** → **เปิดฉบับร่าง** ตัวสร้างและ Preview ในเบราว์เซอร์นี้ใช้ฐานข้อมูลแยก ผู้ใช้ในเบราว์เซอร์อื่นยังใช้เวอร์ชันจริง การเปลี่ยนพื้นที่ทำงานแจ้งแท็บอื่นให้โหลดใหม่ และคำขอจากแท็บที่ยังใช้พื้นที่เดิมถูกปฏิเสธก่อนเขียนข้อมูล

รองรับสูตรและการตั้งค่าของคอลัมน์เดิม View Slice Action Automation แม่แบบ PDF และการตั้งค่าแอพ การทดลองกรอก แก้ หรือลบข้อมูลในฉบับร่างไม่ถูกเผยแพร่กลับลงข้อมูลจริง งานเบื้องหลังในฉบับร่างไม่ถูกส่งให้ worker ให้ใช้การจำลองแทน

การเพิ่ม/ลบ/เปลี่ยนชนิดโครงสร้างตาราง Key Unique และ Ref ต้นทาง ต้องทำในเวอร์ชันจริงผ่านกระบวนการแปลงเดิมก่อนสร้างฉบับร่าง บัญชี สิทธิ์ ค่าตั้งค่าผู้ใช้ และไฟล์อัปโหลดให้จัดการในเวอร์ชันจริง ทั้งนี้เพื่อไม่ให้ข้อมูลทดลองหรือบัญชีจากสำเนาทับข้อมูลที่ใช้งานอยู่

**ตรวจและเผยแพร่** แสดงหมวด รายการ และค่าก่อน–หลังทั้งหมด ตรวจสุขภาพก่อนอนุญาตเผยแพร่ ต้องพิมพ์คำว่า **เผยแพร่** รุ่นจริงที่เปลี่ยนหลังสร้างฉบับร่าง และฉบับร่างที่เปลี่ยนหลังตรวจ จะทำให้เผยแพร่ไม่ผ่าน ไม่รวมความเปลี่ยนแปลงทับกันอัตโนมัติ

การเผยแพร่เป็นธุรกรรมเดียว เปลี่ยนเฉพาะ configuration และบันทึกเวอร์ชันใน SQLite ข้อมูลตารางผู้ใช้ยังเป็นข้อมูลปัจจุบัน งานตามเวลาที่ไม่ได้แก้ยังคงเวลานัดเดิม **สร้างฉบับร่างย้อนกลับ** นำค่าก่อนเวอร์ชันนั้นมาให้ตรวจและเผยแพร่อีกครั้ง ไม่ย้อนข้อมูลธุรกรรมหรือบัญชีผู้ใช้ หากโครงสร้างเปลี่ยนไปแล้ว ระบบปฏิเสธการย้อน configuration ที่ไม่เข้ากัน

ประวัติเวอร์ชันรวมอยู่ในไฟล์สำรอง SQLite ฉบับร่างที่ยังไม่เผยแพร่เก็บในโฟลเดอร์ .app-releases ข้างฐานข้อมูล ต้องสำรองโฟลเดอร์นี้เพิ่มเติมหากต้องการย้ายงานร่างไปเครื่องอื่น เก็บฉบับร่างที่ไม่ใช้ได้โดยไม่ลบข้อมูลสำเนาออกจากดิสก์ มีฉบับร่างที่เปิดใช้ได้ไม่เกิน 10 ฉบับต่อเจ้าของ

ใช้ไฟล์ SQLite บนเซิร์ฟเวอร์เดียว การจัดคิวคำขอฉบับร่างอยู่ใน process เดียว ไม่ใช่ระบบร่วมแก้หลายโหนด

## 4. การบันทึกและการเชื่อมต่อ

แสดงกำลังบันทึก สำเร็จ ขัดแย้ง หรือไม่ทราบผลเมื่อเครือข่ายขาด ข้อมูลในฟอร์มยังอยู่ ไม่มีการส่งคำขอเขียนซ้ำอัตโนมัติ หากผลไม่แน่นอน ควรตรวจข้อมูลล่าสุดก่อนลองอีกครั้ง ป้องกันปิดหน้าระหว่างยังมีคำขอเขียนค้าง ส่วนการแก้ไขหลายคนใช้ row version เดิมในการกันบันทึกทับ

งานเบื้องหลังแสดงจำนวนเฉพาะงานที่ผู้ใช้เป็นผู้สั่งและมีสิทธิ์เห็น เมื่อสถานะเปลี่ยนจะโหลดข้อมูลใหม่โดยไม่เริ่มฟอร์มที่กำลังกรอกใหม่ ไม่ถือว่าการเข้าคิวเท่ากับทำงานสำเร็จ ระบบนี้ยังไม่ใช่โหมดออฟไลน์หรือคิวส่งข้อมูลอัตโนมัติหลังเชื่อมต่อ

## 5. ผลตรวจประสิทธิภาพและอุปกรณ์

ทดสอบด้วยฐานข้อมูลแยก 10,000 แถว บน Chromium จำลองมือถือแบบสัมผัส ผลรอบอ้างอิงใน artifacts/readiness-performance.json: API 25 แถว 545 ms, ค้นหารายการท้ายตาราง 339 ms, Dashboard เริ่มแสดง 844 ms ตัวเลขเป็นผลบนเครื่องพัฒนา ไม่ใช่ SLA

Dashboard ที่มีมากกว่า 1,000 แถวเริ่ม render 200 แถว และทยอยเพิ่มเมื่อเลื่อน โดยยังค้นหาจากข้อมูลทั้งหมดและคงผลสรุปกลุ่มจากข้อมูลทั้งหมด ไม่เพิ่ม pagination กลับมา

คำสั่งตรวจ: node scripts/integration.cjs readiness, node scripts/integration.cjs readinessperf, node scripts/integration.cjs concurrentedit, node scripts/integration.cjs smooth และ node scripts/test.cjs ใช้ฐานทดสอบแยกทั้งหมด

### รายการตรวจ iPhone เครื่องจริง — รอดำเนินการ

- Chrome และ Safari แนวตั้ง/แนวนอน: เปิดรายการ รายละเอียด ฟอร์ม กดย้อนกลับและปิด ตรวจ header และ pagination ไม่กระพริบ
- กรอกข้อความ ตัวเลข วันที่ และค้นหา dropdown ตรวจไม่ซูมอัตโนมัติ และแป้นพิมพ์ไม่บังปุ่มบันทึก
- ตั้งปิด Gallery แล้วถ่ายจากกล้อง บันทึกรูปจากเครือข่าย LAN และตรวจรูปหลังกลับหน้ารายละเอียด
- ระหว่างกรอกให้ปิด Wi-Fi/ข้อมูลมือถือ ตรวจค่าฟอร์มยังอยู่ และไม่มีการสร้างรายการซ้ำเองเมื่อเปิดเครือข่าย
- สั่ง Automation แล้วตรวจสถานะเบื้องหลังและค่ารายละเอียดหลังเสร็จ
- สลับแอพ/ล็อกหน้าจอแล้วกลับมา ตรวจข้อมูลล่าสุดก่อนบันทึก โดยเฉพาะกรณีมีอีกคนแก้แถวเดียวกัน

การจำลอง Chromium ไม่ยืนยันพฤติกรรม WebKit กล้อง แป้นพิมพ์ และ browser chrome บน iOS จริง

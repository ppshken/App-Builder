# สเปกระบบ App Builder

ฉบับสถานะปัจจุบัน · ตรวจจากโค้ดวันที่ 14 ตุลาคม 2569 (2026-10-14)

เอกสารนี้ระบุความสามารถที่พัฒนาแล้ว กฎที่ต้องรักษา ข้อจำกัด และแผนต่อยอด ไม่ใช่รายการรับรองว่าทุกกรณีใช้งานได้รับการทดสอบแล้ว เมื่อพัฒนาต่อให้ปรับสเปกและเกณฑ์ทดสอบที่เกี่ยวข้องด้วย

## 1. เป้าหมายและขอบเขต

เครื่องมือ No-code ภาษาไทยสำหรับสร้างเว็บแอปโดยเริ่มจากตารางข้อมูล ผู้สร้างกำหนดคอลัมน์ ความสัมพันธ์ สูตร และสิทธิ์ แล้วระบบสร้างหน้ารายการ ฟอร์ม และรายละเอียดให้อัตโนมัติ ปรับเพิ่มหน้าจอ ปุ่ม และงานอัตโนมัติได้

เป้าหมายหลักคือใช้งานบนคอมพิวเตอร์ของเจ้าของผ่าน localhost ใช้ SQLite ที่มี foreign key และ transaction สำรองง่าย และปรับโครงสร้างโดยตรวจผลกระทบก่อนเปลี่ยนจริง ปัจจุบันหนึ่งการติดตั้งใช้งานฐานข้อมูลหลักหนึ่งชุด ยังไม่มีตัวจัดการหลายแอปหรือชุดส่งออกเฉพาะแอป

ระบบมีสองส่วนในโค้ดเดียวกัน:

| ส่วน | หน้าที่ |
| --- | --- |
| ส่วนสร้างแอป | จัดการ Data, View, การตกแต่ง, Action, Automation, ผู้ใช้ และการตั้งค่า |
| ส่วนใช้งานแอป | Login, แสดงข้อมูลตามสิทธิ์, กรอกฟอร์ม, เปิดรายละเอียด และกด Action ผ่าน /run |

การแยกส่วนข้างต้นเป็นการแบ่งหน้าที่และสิทธิ์ ยังไม่ใช่การแยกเป็นโปรแกรมติดตั้งสองชุด

## 3. โมเดลข้อมูลและกฎพื้นฐาน

### 3.1 ตารางและรหัสแถว

- ตาราง metadata หลักคือ _tables และ _columns ส่วนข้อมูลจริงเก็บในตาราง t_<name>
- ทุกตารางข้อมูลมี id INTEGER PRIMARY KEY AUTOINCREMENT ระบบสร้างให้อัตโนมัติ แก้ไขค่าเองไม่ได้
- Key ที่ผู้สร้างเลือกเป็นรหัสทางธุรกิจ ใช้บังคับไม่ว่างและไม่ซ้ำ แต่ไม่แทน id ภายในระบบ
- Ref ใช้ id ของแถวปลายทางเป็นค่าที่เก็บจริง
- ชื่อในระบบของตารางและคอลัมน์ต้องผ่าน ^[a-z][a-z0-9_]{0,40}$ และห้ามใช้ id เป็นชื่อที่ผู้สร้างเพิ่มเอง
- ชื่อที่ใช้ประกอบ SQL ต้องผ่าน metadata/การตรวจชื่อ ส่วนค่าข้อมูลต้องใช้ prepared statements
- Label เลือกข้อความได้หนึ่งช่องและรูปภาพได้หนึ่งช่อง เพื่อแสดงชื่อพร้อมรูปเล็กในตำแหน่งที่รองรับ
- หากไม่เลือก Label ข้อความ ใช้ช่องข้อความที่เหมาะสมตาม helper ของระบบ และใช้ id เมื่อไม่มีช่องชื่อ

### 3.2 ชนิดข้อมูล

| ชนิด | การใช้งาน |
| --- | --- |
| Text / Longtext | ข้อความสั้น/หลายบรรทัด ตั้งจำนวนตัวอักษรสูงสุดได้ |
| Number / Decimal | ค่าตัวเลข/ทศนิยม เก็บเป็นชนิดตัวเลขของ SQLite |
| Date / DateTime | วันที่ / วันและเวลา |
| YesNo | ใช่–ไม่ใช่ |
| Enum | เลือกหนึ่งค่า จากตัวเลือก ตารางอ้างอิง หรือสูตรรายการ; ไม่กำหนดแหล่งรายการเลยสามารถพิมพ์ค่าเองได้ |
| EnumList | เลือกหลายค่า มีปุ่มเลือกทั้งหมดในฟอร์ม ใช้ตัวเลือก ตารางอ้างอิง หรือสูตรรายการ |
| Ref | อ้างแถวจากอีกตารางผ่าน foreign key |
| List | รายการค่า ตั้งตารางอ้างอิงและใช้ร่วมกับ SELECT ได้ |
| Image | รูปภาพ พร้อมการอัปโหลด ปรับขนาด และเปิดดูรูป |
| LatLong | พิกัดช่องเดียว เช่น 13.7097601,100.8135513 พร้อมแผนที่และตัวเลือก GPS |
| Color | สี |
| Signature | ลายเซ็น |
| File | ไฟล์แนบ เช่น PDF |

Enum/EnumList และ Ref แสดงตัวเลือกแบบค้นหาและเลื่อนเลือกได้ มีตัวเลือก Input mode แบบปุ่มสำหรับชนิดที่รองรับ การเลือกตารางอ้างอิงไม่ทำให้ Enum กลายเป็น foreign key แบบ Ref

### 3.3 คอลัมน์และการตรวจข้อมูล

- แยกชื่อในระบบกับชื่อที่แสดง
- ตั้ง Required, แก้ไขได้, ห้ามซ้ำ, Label และ Key ตามข้อจำกัดของชนิดข้อมูล
- Required ตรวจที่ฟอร์มและ API ไม่ใช้ NOT NULL เป็นกฎหลัก
- virtual column เก็บสูตรใน metadata และคำนวณตอนอ่าน ไม่สร้างช่องเก็บผลในตารางข้อมูล
- ค่าเริ่มต้นใช้เมื่อเพิ่มข้อมูล; Reset On Edit ใช้สูตรค่าเริ่มต้นใหม่เมื่อคอลัมน์ที่เลือกเฝ้าดูเปลี่ยน
- การตรวจ API ครอบคลุมชนิดข้อมูล Required, Valid_If, เงื่อนไขแก้ไข, ค่าไม่ซ้ำ, Ref และไฟล์ที่มีสิทธิ์ใช้
- ไม่เปิดให้เปลี่ยนชนิดช่องจริงโดยตรงใน dropdown แต่มีขั้นตอนแปลง/คัดลอกข้อมูลอย่างปลอดภัย

### 3.4 ปรับโครงสร้างอย่างปลอดภัย

รองรับเพิ่ม/แก้การตั้งค่า/เปลี่ยนชื่อ/ลบคอลัมน์และลบตาราง ตรวจสูตร View และการอ้างอิงที่ได้รับผลกระทบ ตารางที่ถูกอ้างด้วย Ref ลบไม่ได้โดยตรง

การแปลงชนิดต้องตรวจตัวอย่างและข้อมูลจริงก่อนยืนยัน ตรวจอีกครั้งว่าข้อมูล/การตั้งค่าไม่เปลี่ยนหลังการตรวจ และสำรองก่อนเปลี่ยน ลบคอลัมน์ใช้การสร้างตารางใหม่โดยรักษา id และลำดับ AUTOINCREMENT พร้อมควบคุม foreign_keys ตามขั้นตอนใน schema helper

ผู้ดูแลต้องสำรอง data.db ก่อนปรับโครงสร้างหรือ metadata ที่สำคัญ การทดสอบ migration/restore ต้องใช้ฐานข้อมูลแยก

## 4. Data และความสัมพันธ์

หน้า Data มีรายการตารางด้านซ้ายและแท็บคอลัมน์/การตั้งค่า ข้อมูล และข้อมูลจริงในฐานข้อมูล แท็บข้อมูลจริงแสดงค่าที่เก็บแทน Label หรือผลคำนวณที่เติมเพื่อแสดงหน้าจอ

ความสามารถหลัก:

- ค้นหา เรียงลำดับ กรองหลายเงื่อนไข และแบ่งหน้าข้อมูล 10/25/50/100 รายการ
- เพิ่ม แก้ไข ลบข้อมูล และตรวจค่าซ้ำ
- เคลียร์ทั้งตารางพร้อมรีเซ็ต id มีข้อความพิมพ์ยืนยันและปุ่มอันตรายชัดเจน เคารพ Ref ที่เปิดลบลูกตามแม่หรือ Is a part of ลบลูก/หลานใน transaction เดียว หากมี Ref/List ที่ยังป้องกันการลบให้ย้อนกลับทั้งหมด รีเซ็ต ID เฉพาะตารางแม่ ไม่รีเซ็ต ID ตารางลูกและไม่ส่ง Automation จากการเคลียร์
- นำเข้า/ส่งออก Excel ผ่านสิทธิ์ของตาราง
- Ref แสดงชื่อและรูปของปลายทาง ส่วนค่าจริงยังเป็น id
- Related/Inline ตั้งจำนวนต่อหน้า 5/10/20 หรือทั้งหมด
- Related แสดงจำนวนทั้งหมดและสรุปกลุ่มแบบนับจำนวนหรือผลรวมจากช่องตัวเลขจริง คำนวณตามสิทธิ์และครบทุกหน้า

### 4.1 Is a part of

Ref ของลูกกำหนด Is a part of เพื่อจัดการหลายรายการในฟอร์มแม่ได้ รายการลูกที่เพิ่มหรือแก้ยังเป็นร่างจนแม่บันทึกสำเร็จ ยกเลิกฟอร์มแล้วไม่บันทึกร่างใหม่

- เลือก Inline View เพื่อกำหนดรูปแบบและคอลัมน์ของรายการลูก
- ใช้ฟอร์มของตารางลูกเป็นหน้ากรอกและเรียงช่อง
- part_show_if กำหนดการแสดงส่วนลูก, part_add_if กำหนดสิทธิ์เพิ่มตามเงื่อนไข
- part_valid_if ตรวจรายการลูก เช่น COUNT([_THIS]) <= 5
- ปุ่มเพิ่มในรายละเอียดตรวจว่าจะเพิ่มอีกหนึ่งรายการแล้วผ่าน Valid_If หรือไม่ ครบจำนวนแล้วซ่อนปุ่ม
- ตรวจเงื่อนไขอีกครั้งฝั่งเซิร์ฟเวอร์ บันทึกแม่–ลูกใน transaction เดียว
- ลบแม่ที่มีความสัมพันธ์ Is a part of จะจัดการลบลูกตามสิทธิ์และกฎที่เกี่ยวข้อง; Ref ปกติยังถูกคุ้มครองด้วย foreign key

### 4.2 ป้องกันการแก้ไขทับกัน

API ส่ง __version จากข้อมูลจริงของแถวให้ฟอร์มส่งกลับเมื่อแก้ไข ถ้ารายการเปลี่ยนหรือถูกลบระหว่างเปิดฟอร์ม ตอบ 409 และไม่บันทึกทับ ค่าที่กรอกยังอยู่ มีปุ่มโหลดล่าสุดที่ถามยืนยันก่อนแทนค่า

ตรวจลูกที่ถูกแก้/นำออกด้วย เมื่อชนกันต้องยกเลิกชุดแม่–ลูก ไม่รวมค่า virtual หรือ Label ของ Ref ในรหัสตรวจสอบ

API เก่าที่ยังไม่ส่ง __version ยังรองรับอยู่ บริการภายนอกต้องส่งค่านี้เองหากต้องการป้องกันทับกัน การตรวจเป็นการเทียบสภาพข้อมูล ไม่ใช่ตัวนับ revision ถาวรทุกครั้งที่มีการเปลี่ยนแปลง

## 5. Expression Engine

ใช้ parser/evaluator ของระบบ ไม่ใช้ eval หรือ new Function กับข้อความสูตร

| รูปแบบ | ตัวอย่าง |
| --- | --- |
| อ้างช่องปัจจุบัน | [amount] |
| อ้างแถวต้นทางใน SELECT | [_THISROW].[inspection_id] |
| ดึงช่องจาก Ref | [product].[product_price] |
| รายการจากตาราง | permission[id] |
| กรองข้ามตาราง | SELECT(permission[id], [active] = TRUE) |
| ค่าที่ตรวจใน Valid_If | [_THIS] |

ฟังก์ชันที่มีใน evaluator ได้แก่ IF, IFS, AND, OR, NOT, LIST, COUNT, IN, ISBLANK, ISNOTBLANK, CONCATENATE, SUM, RIGHT, TEXT, INDEX, LEN, TRIM, UPPER, LOWER, TODAY, NOW, DAY, MONTH, YEAR, ROUND, ABS, MIN, MAX, SELECT และ UNIQUEID

ฟังก์ชันบัญชี/ค่าตั้งค่า ได้แก่ USEREMAIL, USERID, USERNAME, USERROLE, USERROLEKEY, ISOWNER และ USERSETTINGS

ใช้สูตรกับ virtual column, default_expr, show_if, valid_if, required_if, editable_if, View Show_If, Slice, Action และ Automation ตามบริบทของแต่ละส่วน

ช่องสูตรมีสีไวยากรณ์ เลขบรรทัด ตัวช่วยแทรกช่อง/ตาราง ตรวจ syntax และปุ่มจัดรูปแบบ มีเมนูคู่มือสูตร การรองรับไวยากรณ์คล้าย AppSheet ไม่หมายถึงรองรับทุกฟังก์ชันหรือทุกรูปแบบของ AppSheet

## 6. View และแอปใช้งาน

ชนิด View: ตาราง รายการ ฟอร์ม รายละเอียด แผนที่ กราฟ ปฏิทิน และแดชบอร์ดที่รวมหลาย View

| ตำแหน่ง | ความหมาย |
| --- | --- |
| Primary Navigation | หน้าหลักในการนำทาง |
| Menu Navigation | หน้าในเมนู |
| Reference View | ฟอร์ม/รายละเอียดที่เปิดต่อจากข้อมูล |
| Inline Views | Related ภายในหน้าข้อมูลที่อ้างอิง |

ตั้งชื่อ View แยก Display Name ตรวจชื่อซ้ำ ตั้งไอคอน Show_If การเรียงและ Group By ได้ เมนูผู้สร้างจัดกลุ่มตามตารางเฉพาะ Reference และ Inline พร้อมพับ/ขยายและค้นหา

- รายการ: compact/card/outlined/striped/grid ปรับรูป ข้อความ ปุ่ม padding ความสูงขั้นต่ำ gap และมุมได้
- ตาราง: ใช้ตารางบนมือถือ เลื่อนแนวนอนได้ ปรับความแน่น ระยะขอบแถว ระยะบรรทัด ตัดข้อความ ปุ่ม และเหตุการณ์คลิกแถว
- รายละเอียด: แนวตั้ง/แนวนอน จำนวนคอลัมน์ รูป cover/inline ขนาดรูป ระยะขอบ ระยะบรรทัด เส้นคั่น ป้ายชื่อ และซ่อนช่องว่าง
- ฟอร์ม: จำนวนคอลัมน์ ตำแหน่ง Label ลำดับ/แสดงช่อง ความกว้าง ส่วนย่อย ข้อความช่วยและ multiline ตามชนิด
- หลังบันทึก: กลับหน้าก่อนหน้า หรือรายละเอียด; เลือก Action หลังบันทึก และ Re Open ฟอร์มใหม่ได้
- Re Open คงฟอร์มและตัวโหลดจนฟอร์มใหม่พร้อม หากเปิดใหม่ผิดพลาดไม่ควรสร้างข้อมูลเดิมซ้ำ
- แผนที่ใช้ช่อง LatLong; GPS ต้องได้รับอนุญาตจากเบราว์เซอร์
- หน้าซ้อนรักษาทางย้อนกลับ เดสก์ท็อปมีรายละเอียด/ฟอร์มด้านขวาตามรูปแบบระบบ มือถือใช้พื้นที่หน้าจอ
- แจ้งบันทึกสำเร็จเป็นสีเขียวและเปิดรูปเพื่อดูขยายได้

### 6.1 Preview

สลับมือถือ/แท็บเล็ต/เดสก์ท็อปและเปิดแอปอีกแท็บได้ View แสดงการแก้รูปแบบก่อนบันทึก Action ส่งร่างไปยัง Preview เพื่อเปลี่ยนชื่อ สี ไอคอน และ Position ทันที

ปุ่ม Action ที่เป็นร่างใน Preview ไม่สั่งเปลี่ยนข้อมูลจริง ส่วนการเพิ่ม/แก้/ลบผ่านฟอร์ม Preview ใช้ข้อมูลจริง ต้องไม่เข้าใจว่าเป็นฐานข้อมูลจำลอง

## 7. การตกแต่งข้อมูล

เมนูตกแต่งข้อมูลเลือกตาราง คอลัมน์ และ View กำหนดข้อความ Badge ไอคอน สีข้อความ/ไอคอน/พื้นหลัง/เส้นขอบ ขนาด มุม และตัวหนาได้ ใช้ค่าคงที่หรือกฎตามค่า/สูตร เช่น สถานะสำเร็จเป็นสีเขียว มีตัวอย่างและ Preview ก่อนบันทึก

เมื่อคอลัมน์ Label ข้อความมีการตกแต่ง ระบบส่งรูปแบบที่ประเมินแล้วไปพร้อมชื่อของ Ref และแสดงในรายละเอียด/รายการที่รองรับ กฎใช้ค่าของแถวต้นทาง เลือกการตกแต่งจาก View รายละเอียดแบบ Reference ก่อน ตามด้วยรายละเอียดอื่นและ View หลัก หาก Ref ใน View ปลายทางมีการตกแต่งของตัวเองให้ใช้ค่าปลายทางก่อน ไม่ส่งข้อมูลแถวต้นทางทั้งหมดให้หน้าอ้างอิง

การตกแต่งเป็นการแสดงผล ไม่เปลี่ยนค่าที่เก็บจริงหรือสิทธิ์ข้อมูล

## 8. Action

ชนิดที่รองรับ: เปลี่ยนค่าคอลัมน์ ลบ คัดลอก เพิ่มแถว เปิด View เปิดฟอร์มเพิ่ม/แก้ไข เปิดรายละเอียด เปิด URL โทรศัพท์ SMS อีเมล เรียก Automation และชุด Action ตามลำดับ

- สูตรค่าใหม่อ่านจากแถวตามบริบทของ Action
- Action เปลี่ยนค่าคอลัมน์มีรายการเรียงลำดับ ลากหรือเลื่อนขึ้น–ลง เพิ่ม/นำคอลัมน์ออกได้ ลำดับบันทึกตามรายการค่าใน JSON
- `config.value_mode=sequential` คำนวณบนลงล่าง สูตรขั้นหลังอ่านค่าขั้นก่อนรวมคอลัมน์คำนวณที่อ้างค่าใหม่ได้ ตรวจสิทธิ์และบันทึกทั้งชุดครั้งเดียว หากสูตร/การตรวจข้อมูลผิดให้ย้อนกลับทั้งหมด Action ใหม่จากหน้า editor ใช้โหมดนี้
- `snapshot` หรือไม่ได้ตั้งโหมด ยังคำนวณทุกสูตรจากค่าเดิมก่อนเริ่ม Action เพื่อรักษาพฤติกรรม Action เดิม ผู้ใช้เปลี่ยนโหมดเองในหน้าตั้งค่าได้
- ฟอร์มเพิ่มปลายทางกำหนดค่าตั้งต้นจากแถวต้นทางได้
- เปิดรายละเอียดปลายทางใช้สูตร id ภายในระบบ
- มีเงื่อนไขแสดง/ทำงาน ข้อความยืนยัน และตรวจซ้ำฝั่งเซิร์ฟเวอร์
- ชุด Action มีข้อจำกัดชนิดและลำดับ โดยการลบต้องอยู่ท้ายชุด
- สี ไอคอน สไตล์ ขนาด และ icon-only ตั้งแยกได้

| Position | การแสดงผล |
| --- | --- |
| Primary | ไอคอนอัตโนมัติในแถวเดียวกับแก้ไข/ลบของรายละเอียด |
| Prominent | ปุ่มใต้หัวรายละเอียด |
| Inline | ปุ่มข้างรายการ และพื้นที่ปุ่มในรายละเอียดที่รองรับ |
| Hide | ไม่แสดงปุ่ม แต่ยังเรียกผ่านกลไกอื่นได้ตามสิทธิ์ |

Hide และ Show_If ไม่ใช่การเพิกถอนสิทธิ์ ต้องใช้สิทธิ์ตาราง/Action ควบคุมการทำงาน

## 9. Automation

เหตุการณ์: manual, create, update, delete และ schedule; การแก้ไขเลือกคอลัมน์เฝ้าดูได้ ขั้นตอนรองรับ Action, Webhook/API และ PDF

| โหมด | พฤติกรรม |
| --- | --- |
| เบื้องหลัง | บันทึกข้อมูลก่อน แล้วเข้าคิวทำงาน มีประวัติ/ผลแต่ละขั้นตอน ต้องเปิดเซิร์ฟเวอร์ไว้ |
| ทำงานพร้อมบันทึก | เฉพาะ create/update/delete และ Action เปลี่ยนค่าคอลัมน์ ทำภายใน transaction ของการบันทึก หากขั้นตอนผิดยกเลิกทั้งชุด |

ในโหมดพร้อมบันทึก Action ที่ condition เป็น false จะถูกข้าม ไม่ทำให้ทั้งงานล้มเหลว งาน PDF/API และตามเวลาไม่ใช้โหมดนี้ Automation เดิมยังเป็นเบื้องหลังจนเปลี่ยนการตั้งค่า

### 9.1 อัปเดตตารางแม่

ขั้นตอนเรียก Action เลือกแถวแม่จาก Ref ของลูกได้ เป็นแม่หนึ่งแถวและ Action ชนิดเปลี่ยนค่าคอลัมน์ สูตร Action อ่านบริบทของแม่ ใช้ได้กับการเพิ่ม/แก้ไข/ลบลูก

ตัวอย่างเวลาเริ่ม: Action แม่มีเงื่อนไข ISBLANK([started_at]) และกำหนด started_at = NOW() เวลาเสร็จใช้เงื่อนไขว่าตรวจครบและเวลาสิ้นสุดยังว่าง พร้อมบันทึกช่วยให้ค่าอัปเดตก่อน API ตอบกลับและรายละเอียดโหลดแม่ใหม่

ถ้าย้าย Ref ไปแม่อื่น ขั้นตอนอัปเดตแม่ปลายทางของเหตุการณ์ ยังไม่อัปเดตแม่เดิมอัตโนมัติ

### 9.2 Webhook และคิวงาน

ส่ง JSON ด้วย POST/PUT/PATCH กำหนดสูตรข้อมูลส่ง ใช้ชื่อ environment variable สำหรับ token และอ่านช่อง JSON กลับลงคอลัมน์ได้ ต้องอนุญาต origin ปลายทางด้วย NOCODE_WEBHOOK_ORIGINS ก่อน

งานเบื้องหลังหยุดเมื่อขั้นตอนผิด ดูประวัติและสั่งทำต่อจากขั้นตอนที่ล้มเหลวได้ ไม่รับประกันว่า API ภายนอกยังไม่ได้รับข้อมูลเมื่อ timeout จึงไม่ควรสั่งซ้ำโดยไม่ตรวจผล งานที่ Automation แก้ข้อมูลไม่เรียก Automation ซ้ำเพื่อป้องกันวงวน

หลัง restore จะปิด Automation และยกเลิกงานค้าง ต้องตรวจการตั้งค่าและเปิดใหม่

## 10. PDF

รองรับรายงานมาตรฐานหรือออกแบบเองแบบลากวางบน A4 แนวตั้ง/แนวนอน ฟอนต์ Sarabun รองรับภาษาไทย

- ข้อความ ช่องข้อมูล รูปภาพ/ลายเซ็น เส้น กรอบ และเลขหน้า
- เครื่องมือด้านขวา โหมดเต็มจอ ซูม เส้นช่วยจัดแนว ล็อกตำแหน่ง ย้อนกลับ/ทำซ้ำ และเพิ่มหลายหน้า
- ตารางกำหนดแถว/คอลัมน์ รวม/แยกช่อง สัดส่วนขนาด สี เส้นขอบ ระยะด้านใน ข้อความ [col] และสูตรที่เริ่มด้วย =
- ตารางลูกเลือก Ref คอลัมน์ หัวคอลัมน์ กรอง เรียง จำนวนต่อหน้า และรูปแบบตาราง/การ์ด
- หัว/ท้ายทุกหน้าและเลขหน้าจริงด้วย {page}/{pages}
- Preview ข้อมูลจริงก่อนบันทึก และเก็บ PDF กลับคอลัมน์ File ได้
- รูปที่เก็บในระบบแนบลง PDF; ลิงก์รูปภายนอกไม่ได้ดาวน์โหลดเข้าไฟล์โดยอัตโนมัติ

ขีดจำกัดสำคัญ: 20 หน้าที่ออกแบบเอง, 100 หน้าหลังขยายรายการลูก, ตารางคงที่สูงสุด 30×12 ช่อง, ตารางลูกในองค์ประกอบออกแบบสูงสุด 1,000 รายการ รูปรวมสูงสุด 12 MB และ PDF ไม่เกิน 20 MB ข้อความในช่องตารางล้นต้องปรับก่อนสร้างไฟล์

## 11. บัญชี สิทธิ์ และค่าตั้งค่าผู้ใช้

- ตั้งบัญชีเจ้าของครั้งแรกผ่าน localhost, Login/Logout, เปิด/ปิดบัญชี และกำหนดบทบาท
- รหัสผ่าน 10–128 ตัวอักษร เก็บ hash แบบ scrypt พร้อม salt ไม่เก็บรหัสผ่านตรง ๆ
- Session อายุสูงสุด 12 ชั่วโมง และหมดอายุเมื่อไม่ใช้งาน 2 ชั่วโมง มีการจำกัดการลอง Login
- สิทธิ์ระดับตาราง: read/create/update/delete; สิทธิ์ Action กำหนดแยก
- กฎแถวใช้คอลัมน์จริงของแถวและข้อมูลบัญชี ไม่ใช้ช่อง virtual, SELECT/dereference ข้ามตาราง หรือ USERSETTINGS
- Show_If ของ View/Slice เป็นเงื่อนไขหน้าจอ/กรองข้อมูล ไม่แทนกฎสิทธิ์
- เจ้าของดูแลผู้ใช้ สำรอง/กู้คืน Audit และ Automation/PDF ตามการตรวจ API
- USERSETTINGS มีนิยาม text/number/yesno/enum และค่าของแต่ละบัญชี ผู้ใช้แก้ค่าเองได้ จึงไม่ใช้เป็นฐานตัดสินสิทธิ์
- API ที่เขียนข้อมูลตรวจ session, origin และสิทธิ์; ไฟล์/รูปต้องผ่านสิทธิ์ ไม่เปิดโฟลเดอร์ uploads เป็นพื้นที่สาธารณะโดยตรง

## 12. การตั้งค่าแอปและไฟล์

ตั้งชื่อ ไอคอนแบบสำเร็จรูป/รูปจากลิงก์หรืออัปโหลด สีธีมด้วยรหัสสี โหมด ฟอนต์ Google Fonts ที่มีให้เลือก ขนาด/น้ำหนักตัวอักษร หน้าแรกหลัง Login และตัวโหลดแบบ spinner/ข้อความ

กำหนดรูปแบบหน้าจอตั้งต้นแยกตามชนิด View มี Preview ตัวอย่าง และให้ View รายหน้า override ได้

รูปภาพตั้งขนาดการบีบ/ย่อ วิธีจัดเก็บ และ Path ได้ File ตั้งโฟลเดอร์ได้ เปิดผ่าน API ในเบราว์เซอร์เมื่อชนิดไฟล์รองรับ การเปิดแทนดาวน์โหลดขึ้นกับชนิดไฟล์และเบราว์เซอร์ ไม่ได้ทำได้กับทุกนามสกุล

ไฟล์สำเนาอยู่ใน uploads ข้างฐานข้อมูล เนื้อไฟล์ที่ระบบเก็บในฐานข้อมูลช่วยรองรับ backup/restore ต้องตรวจโหมดจัดเก็บและไฟล์ที่จำเป็นก่อนย้ายเครื่อง ห้ามถือว่าการคัดลอกโฟลเดอร์โค้ดอย่างเดียวเป็นการสำรองข้อมูล

## 13. สำรอง ประวัติ และการปฏิบัติการ

- หน้า backup รองรับสำรอง/ดาวน์โหลด/กู้คืน พร้อมตรวจโครงสร้างและข้อจำกัดของไฟล์
- หากคัดลอก data.db เองให้หยุดแอปก่อน เพราะ SQLite ใช้ WAL; การสำรองผ่านระบบเป็นทางเลือกที่เหมาะระหว่างใช้งาน
- Audit log บันทึกการเปลี่ยน metadata และการตั้งค่า เช่น Data schema, View, Action, Slice, ผู้ใช้, Automation และ PDF พร้อมผู้กระทำ เวลา และค่าที่เปลี่ยน
- Audit ปัจจุบันไม่ใช่ประวัติครบทุกแถวข้อมูลจริง และไม่มีระบบย้อนค่าข้อมูลรายแถวอัตโนมัติ
- ประวัติ Automation แยกจาก Audit และแสดงผลแต่ละขั้นตอน
- Git เก็บโค้ด เอกสาร และ dependency lock ไม่เก็บ data.db, uploads, backup, ไฟล์ลับ หรือ build output

## 14. API หลัก

API อยู่ใต้ /api และตรวจสิทธิ์ฝั่งเซิร์ฟเวอร์ ตารางนี้สรุปกลุ่ม ไม่ใช่สัญญา OpenAPI แบบละเอียด

| กลุ่ม | หน้าที่ |
| --- | --- |
| /tables, /tables/[name] | metadata และปรับโครงสร้าง |
| /tables/[name]/convert, /duplicates, /raw | แปลง ตรวจซ้ำ และค่าจริง |
| /data/[table], /validate, /clear | ข้อมูล ฟอร์ม ตรวจค่า และเคลียร์ตาราง |
| /lists/[table], /view-data/[table] | รายการแบ่งหน้า Related และ View พิเศษ |
| /expression-data | ข้อมูลบริบทสำหรับสูตร |
| /views, /views/preview | การตั้งค่า View และร่าง Preview |
| /actions, /slices | ปุ่มและชุดข้อมูลกรอง |
| /workflows, /pdf-templates | Automation ประวัติ งาน และ PDF |
| /images, /files, /workflows/files/[id] | อัปโหลด/อ่านไฟล์ตามสิทธิ์ |
| /auth/*, /users, /user-settings | บัญชี session สิทธิ์และค่าตั้งค่า |
| /settings, /branding, /app-icon | ธีมและข้อมูลแอป |
| /excel/[table], /backups, /audit-log | แลกเปลี่ยนข้อมูล สำรองและประวัติ |

- ตารางมีได้สูงสุด 200 คอลัมน์ตามการตรวจ metadata
- Excel นำเข้าสูงสุด 5,000 แถว และไฟล์สูงสุด 10 MB ตามโค้ดปัจจุบัน
- File สูงสุด 20 MB; API รูปภาพมีเพดาน 5 MB และยังมีค่าขนาดรูปที่ตั้งในแอป
- ชุดรายการลูกบันทึกไม่เกิน 200 รายการ มีขีดจำกัดชั้นซ้อน; ไม่เหมาะกับส่งรายการจำนวนมากครั้งเดียว
- Automation 1–10 ขั้นตอน; งานตามเวลาต้องมีเซิร์ฟเวอร์ทำงานต่อเนื่อง
- View พิเศษมีข้อจำกัดจำนวนแถว ต้องใช้ Slice/ช่วงวันที่ลดข้อมูลเมื่อเกินขีดจำกัด
- มี pagination, debounce ค้นหา, cache ฝั่ง runtime และรวมอ่าน Ref เป็นชุด
- สูตรข้ามตาราง/ช่อง virtual และกฎสิทธิ์แถวอาจต้องอ่านมากกว่าเส้นทาง SQL แบบแบ่งหน้าปกติ
- ผลทดสอบข้อมูล 100,000 แถวใน docs/performance.md เป็นผลบนข้อมูลจำลอง ไม่ใช่การรับประกันเวลาตอบสนองกับทุกสูตรหรือทุกเครื่อง

## 16. ติดตั้งและอัปเดต

Windows PowerShell ในโฟลเดอร์โปรเจกต์:

~~~powershell
npm.cmd ci
npm.cmd run build
npm.cmd start
~~~

เปิด http://localhost:3000 และสร้างบัญชีเจ้าของครั้งแรก ใช้ npm.cmd run dev ระหว่างพัฒนา PDF ต้องมี Edge หรือ Chromium ที่ Playwright ใช้ได้

ค่าตั้งค่าเซิร์ฟเวอร์ที่สำคัญใน .env.local: NOCODE_DB_PATH, NOCODE_WEBHOOK_ORIGINS และ NOCODE_PDF_BROWSER_PATH ชื่อ token ของ API ใช้ environment variable ที่ผู้ดูแลกำหนดเอง ห้าม commit ไฟล์ลับ

ก่อนอัปเดตให้สำรองข้อมูลและหยุดแอป แล้วอัปเดตโค้ด ติดตั้ง dependency/build ใหม่ โดยไม่เอา data.db จากเครื่องพัฒนาไปทับข้อมูลจริง รายละเอียดเพิ่มเติมดู README

### เพิ่มข้อมูลใหม่จากคอลัมน์ Ref

- ตั้งค่าใน Data > คอลัมน์ Ref > อนุญาตให้เพิ่มข้อมูลใหม่จากช่อง Ref (ค่าเริ่มต้นปิด)
- ผู้ใช้ต้องมีสิทธิ์อ่านและเพิ่มข้อมูลของตารางอ้างอิง และมี Reference View แบบฟอร์มที่ไม่ถูกซ่อน
- Dropdown มีปุ่มเพิ่มใหม่ เปิดฟอร์มอ้างอิงซ้อนโดยเก็บค่าของฟอร์มเดิมไว้ บันทึกแล้วโหลดตัวเลือกและเลือก ID ใหม่อัตโนมัติ
- ใช้การตั้งค่าคอลัมน์/ลำดับของฟอร์มอ้างอิง รวมถึงการตรวจข้อมูลและ Action หลังบันทึกของฟอร์มนั้น
- ข้อมูลอ้างอิงบันทึกทันที แม้ภายหลังจะยกเลิกฟอร์มเดิม การยกเลิกฟอร์มอ้างอิงก่อนบันทึกไม่สร้างรายการ
- Valid_If ของ Ref ยังตรวจตามเดิม หากรายการใหม่ไม่ตรงเงื่อนไขจะไม่สามารถบันทึกฟอร์มเดิมด้วยค่านั้นได้


### Duration และผลต่างวันเวลา

- ชนิด Duration เก็บค่าเป็นข้อความ HH:MM:SS รองรับชั่วโมงเกิน 24 ชั่วโมง ค่าติดลบ และเศษวินาทีถึงมิลลิวินาที
- DateTime ลบ DateTime ได้ Duration โดยตีวันเวลาที่ไม่มี timezone เป็นเวลาไทย ส่วน Date ลบ Date ได้จำนวนวัน
- หากค่า DateTime ข้างใดว่าง ผลต่างเป็นค่าว่าง รวมถึงตอนเปิดฟอร์มใหม่ที่ทั้งสองช่องยังว่าง
- DURATION("01:30:00") ตรวจรูปแบบระยะเวลา และ TOTALHOURS/TOTALMINUTES/TOTALSECONDS แปลงเป็นตัวเลขทศนิยม
- SUM รายการ Duration คืน Duration; เครื่องหมายบวก/ลบระหว่าง Duration และการเปรียบเทียบใช้เวลาจริง
- ใช้ชนิด Duration สำหรับคอลัมน์ผลต่างเวลา และ Decimal สำหรับผลจาก TOTALHOURS/TOTALMINUTES/TOTALSECONDS


### DISTANCE ระหว่างพิกัด

- DISTANCE([origin], [destination]) รับ LatLong หรือข้อความละติจูด,ลองจิจูด และคืนค่าชนิดตัวเลขหน่วยกิโลเมตร
- ใช้ Haversine บนโลกทรงกลมรัศมีเฉลี่ย 6,371 กิโลเมตร เป็นระยะทางบนผิวโลกโดยประมาณ ไม่ใช่ระยะทางตามถนน และไม่เรียกบริการภายนอก
- หากพิกัดใดว่างคืนค่าว่าง พิกัดผิดรูปแบบหรือเกินช่วงจะแจ้งข้อผิดพลาด
- คูณผลลัพธ์ด้วย 1000 เพื่อแปลงเป็นเมตร ใช้คอลัมน์ Decimal เมื่อต้องการเก็บผลคำนวณ


### ORDERBY เรียงรายการแถว

- ORDERBY(ตาราง[id], [ลำดับ], FALSE) คืนรายการรหัสแถวที่เรียงจากน้อยไปมาก; TRUE เรียงจากมากไปน้อย หากไม่ใส่ค่าใช้ FALSE
- รองรับ SELECT(ตาราง[id], เงื่อนไข) เป็นช่องแรก และเรียงหลายคอลัมน์ เช่น ORDERBY(ตาราง[id], [priority], TRUE, [name], FALSE)
- ช่องแรกต้องระบุตารางผ่านรายการ id/Key หรือ SELECT/ORDERBY ที่อ้างถึงตารางเดียวกัน ไม่เดาตารางจากรายการข้อความทั่วไป
- เงื่อนไข SELECT และคอลัมน์สำหรับเรียงอ้างอิงแถวของตารางต้นทาง ส่วน [_THISROW] อ้างอิงแถวผู้เรียก
- ใช้ INDEX(ORDERBY(...), 1) เป็นค่าเริ่มต้น หรือใช้ ORDERBY ใน Valid_If ของ Ref เพื่อกำหนดลำดับตัวเลือกได้
- ค่าที่เท่ากันคงลำดับเดิม ตรวจข้อมูลตามสิทธิ์และจำกัดชุดสูตรไม่เกิน 10,000 แถว

### DATE()
- `DATE(value)` รับ Date, DateTime หรือข้อความ ISO คืนวันที่ `YYYY-MM-DD`
- วันเวลาที่มีเขตเวลาจะปรับเป็นเวลาไทยก่อนดึงวันที่ ส่วนวันเวลาที่ไม่ระบุเขตเวลาใช้เวลาไทย
- ค่าว่างคืน `null` วันที่ไม่ถูกต้องและชนิดอื่นแจ้งข้อผิดพลาด ไม่เดารูปแบบวัน/เดือน/ปี
- ตัวอย่าง `DATE([created_at])`, `DATE(NOW())`, `DATE([finished_at]) - DATE([started_at])` คืนจำนวนวัน

### Related ในฟอร์ม
- View ฟอร์มกำหนดแสดง/ซ่อน ชื่อ Inline View จำนวนต่อหน้า และลำดับ `form_order` ของ Related แทรกระหว่างช่องจริงได้ แยกจาก `detail_order` โดย Related ใช้ความกว้างเต็มแถว
- รายการลูก Is a part of ยังเพิ่ม/แก้ไขเป็นร่างและบันทึกพร้อมแม่ ส่วน Ref ทั่วไปแสดงรายการที่เชื่อมกับแม่ที่บันทึกแล้ว
- การลบลูกผ่าน Ref ใช้ค่าตั้ง `ref_delete_cascade` รายคอลัมน์ตามหัวข้อด้านล่าง โดยไม่จำกัดชื่อตาราง

### การลบลูกผ่าน Ref แบบกลาง
- คอลัมน์ Ref จริงมีตัวเลือก `ref_delete_cascade` (ลบลูกตามแม่) ค่าเริ่มต้นปิด แยกจาก Is a part of ใช้ได้กับทุกตารางโดยไม่ผูกชื่อในโค้ดลบ
- เปิดตัวเลือกใน Data → ตารางลูก → แก้ไขคอลัมน์ Ref → ลบลูกตามแม่ ตรวจสิทธิ์ทุกแถวและ transaction เดิม หากลูกใดลบไม่ได้จะย้อนกลับทั้งหมด
- การอัปเกรดสำรองฐานข้อมูลก่อนเพิ่มฟิลด์ และย้ายสิทธิ์ลบเดิมของ inspection → inspection_image,list_inspection เป็นค่าตั้งครั้งเดียว ตารางอื่นไม่ถูกเปิดอัตโนมัติ

### บังคับ Related ในฟอร์ม
- Data → ตารางแม่ → คอลัมน์ → รายการที่เกี่ยวข้อง มีตัวเลือก ไม่บังคับ/บังคับอย่างน้อย 1 รายการ เก็บเป็น `related_required` ของคอลัมน์ Ref ลูก ค่าเริ่มต้นปิด
- ฟอร์มแม่ที่บังคับ Related จะแสดงส่วนลูกพร้อมเครื่องหมาย * เพิ่มรายการลูกเป็นร่างและบันทึกพร้อมแม่ได้แม้ไม่เปิด Is a part of ไม่มีผลเปิดลบลูกตามแม่
- เซิร์ฟเวอร์ตรวจจำนวนหลังประมวลผลรายการลูกทั้งหมดใน transaction นับเฉพาะลูกที่อ้างถึงแม่แถวนี้ หากเหลือ 0 ให้ยกเลิกการบันทึกทั้งแม่และลูก รวมถึงการแก้ไขแม่ที่มีลูกเดิมและการนำลูกออกจากฟอร์ม
- Related ที่บังคับไม่สามารถซ่อนจากรูปแบบฟอร์มได้ การย้ายโครงสร้างสำรองฐานข้อมูลก่อนเพิ่มค่าตั้ง โดยไม่เปิดบังคับให้ตารางเดิมอัตโนมัติ

### Navigation Bar
การตั้งค่าแอพมี Navigation Bar 9 แบบ: มาตรฐาน เส้นใต้ เส้นบน วงกลมไอคอน แคปซูล ไอคอนสีทึบ ปุ่มเด่นยกสูง ปุ่มเด่นและเส้นใต้ ปุ่มเด่นและแคปซูล เลือกชื่อเมนูทุกตัว/เฉพาะเมนูที่เลือก/ไอคอนล้วน รูปทรงเต็มขอบหรือแบบลอย ความกระชับ และเมนู Primary ที่ใช้เป็นปุ่มเด่นได้ เดสก์ท็อปเลือกแถบล่างหรือเมนูด้านข้างได้ ค่าเริ่มต้นคงเมนูด้านข้าง
ตัวอย่างในหน้าตั้งค่าใช้ renderer เดียวกับแอพ แก้ร่างไม่กระทบหน้าระบบจนบันทึก การเปลี่ยนเมนูรักษา navigation guard เดิม ไม่มีการทำงาน Action เมื่อเลือกปุ่มเด่น ใช้สีธีมและชื่อ/ไอคอนจาก View Primary ที่มองเห็นได้ เมนูที่ซ่อนด้วยสิทธิ์/Show_If ไม่แสดง หากเมนูเด่นถูกซ่อนใช้เมนูกลางที่มองเห็นได้ ความสูงแถบวัดจริงเพื่อเว้นที่ให้ pagination และฟอร์มไม่ทับกัน

โหมดมืดใช้พื้นหลังหลัก พาเนล เมนูด้านข้าง ช่องกรอก และ Navigation Bar เป็น `#000000` รวมตัวอย่างในหน้าตั้งค่า ใช้เส้นแบ่งเทากลางเพื่อแยกขอบ และคงสีธีม/สถานะไว้ การปรับสีข้อความธีมอัตโนมัติคำนวณความต่างสีกับพื้นดำจริง โหมดตามอุปกรณ์ใช้สีเดียวกันเมื่ออุปกรณ์เป็นโหมดมืด

### Header แถบด้านบน
ตั้งค่าแอพ → Header เลือกตำแหน่งชื่อ ซ้าย/กลาง/ขวา ข้อความชื่อแอพ/ชื่อหน้า/ทั้งสอง/ซ่อน รูปแอพจากค่าตั้งแอพหรือรูปเฉพาะ Header (อัปโหลด/ลิงก์) รูปทรงมุมโค้ง/วงกลม เปิดปิดรูปโปรไฟล์ แจ้งเตือน และรีโหลดได้ ตัวอย่างใช้ component เดียวกับ runtime และสีธีมของร่าง
รูปโปรไฟล์อ้างค่าตั้งค่าผู้ใช้ชนิดข้อความที่เก็บ URL รูป แสดงรูปของผู้ใช้ปัจจุบันโดยไม่ส่งค่ารูปของผู้อื่น หากว่าง ลิงก์ไม่ปลอดภัย หรือโหลดไม่สำเร็จ แสดงอักษรย่อ กดเปิดค่าตั้งค่าของฉัน
ไอคอนแจ้งเตือนเปิด View หลักหรือเมนูที่เลือกตามสิทธิ์/Show_If ไม่มีการสร้างการแจ้งเตือนหรือจำนวนปลอม หากไม่เลือกปลายทางจะแจ้งว่ายังไม่กำหนด หากผู้ใช้ไม่มีสิทธิ์เห็นปลายทางจะซ่อนปุ่ม รีโหลดยังคงโหลดข้อมูลล่าสุดตามกลไกเดิม บันทึก Header เป็น metadata และสำรองอัตโนมัติก่อนเพิ่มโครงสร้าง ค่าเริ่มต้นคงรูปแบบก่อนอัปเกรด

### แหล่งรูปภาพในฟอร์ม

ตั้งค่าแอพ → การบันทึกรูปภาพ มี `image_allow_gallery` ค่าเริ่มต้น true เพื่อรักษาการเลือกภาพเดิม เมื่อปิด ช่อง Image ในฟอร์มและรายการลูกใช้ `accept="image/*" capture="environment"` เพื่อเรียกกล้องหลังบนมือถือที่รองรับ ปุ่มช่องว่างแสดงเป็นกรอบไอคอนกล้องเต็มความกว้าง การเปิดกล้องจริงขึ้นกับเบราว์เซอร์/อุปกรณ์ บน Desktop อาจยังเปิดหน้าต่างเลือกไฟล์ ไม่ใช่ข้อจำกัดแหล่งไฟล์ที่บังคับตรวจบนเซิร์ฟเวอร์ ไอคอนแอพและลายเซ็นไม่ใช้การตั้งค่านี้


### Dashboard search and data source
Dashboard does not require a primary table. Each selected child View retains its own table permissions, row rules, Slice, and Show_If. One dashboard search filters every child View (including tabs); embedded Views hide individual search and pagination and show all matching rows. Standalone Views retain search and pagination. Existing dashboard table links migrate to NULL; backup validation and Action navigation support tableless dashboards.

# ตรวจและแก้บัค 21 ตุลาคม 2569

ตรวจด้วยฐานข้อมูลทดสอบแยก ไม่เปิดหรือแก้ data.db ของผู้ใช้

## แก้ไข

1. ฟอร์มลูก Inline/Ref ไม่ได้ส่ง guard ไปยัง browser Back และการเปลี่ยนเมนู ทำให้เสี่ยงเสียข้อมูลที่กรอก เพิ่มทะเบียน guard ของหน้าลูก เรียกตามลำดับหน้าซ้อนก่อน guard ของหน้าแม่ รองรับยกเลิกการออกและยืนยันออก
2. หน้าแม่หลังฟอร์มลูกยังรับ focus และ keyboard ได้ กำหนด inert และ aria-hidden ให้หน้าข้อมูลที่ถูกบัง และคืนเมื่อกลับมา
3. บันทึกโปรไฟล์ส่งสัญญาณ nocode:auth ทำให้แท็บอื่น reload แม้กำลังกรอกข้อมูล เปลี่ยนเป็น nocode:profile แล้วโหลดข้อมูลบัญชีล่าสุดมาปรับ context โดยไม่เปลี่ยนหน้า

4. เมื่อยืนยันออกไปหน้าอื่น ฟอร์มลูกยังอยู่ในหน้าแม่ที่ retained ทำให้กลับมาแล้วเจอ draft เดิม เพิ่มการปิดหน้าลูกเมื่อ route แม่ถูกซ่อนจริง โดยไม่รบกวน motion ของการปิดปกติ

## กรณีทดสอบเพิ่ม

- Inline ลูก: browser Back และเปลี่ยนเมนูขณะมีข้อมูลค้าง ต้องเตือนและรักษาข้อมูลเมื่อเลือกกรอกต่อ ยืนยัน browser Back กลับรายการได้โดยไม่เพิ่มข้อมูลลูก
- ตรวจหน้าแม่เป็น inert ขณะฟอร์มลูกเปิด
- เปิดฟอร์มอีกแท็บ กรอกข้อมูลค้าง แล้วบันทึกโปรไฟล์จากแท็บแรก อีกแท็บอัปเดตบัญชีโดยไม่ reload และเก็บค่าฟอร์มเดิม
- ปรับ test Ref ให้ตรวจ floating alert ตามตำแหน่งจริงของ UI ปัจจุบัน

ไม่ได้ทดสอบบน iPhone จริง รายงานผลการตรวจชุด regression ในคำตอบส่งมอบ

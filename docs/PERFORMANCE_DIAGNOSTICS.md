# วิเคราะห์ความช้า

เปิดเมนู วิเคราะห์ความช้า (/performance) ผู้สร้างแอพและเจ้าของแอพใช้งานได้

## วัดการใช้งาน

1. ตั้งชื่อรอบแล้วกดเริ่มบันทึก
2. เปิดแอพและใช้งานส่วนที่ต้องการวัด
3. กดหยุดวัด กลับหน้าวิเคราะห์แล้วเลือกรอบที่ต้องการ

เปิดการวัดด้วยตนเองเท่านั้น เก็บสูงสุด 60 วินาทีและ 500 รายการต่อรอบ แสดง API รูปภาพ และ long task ที่ browser รองรับ เก็บประวัติล่าสุด 10 รอบใน localStorage แยกผู้ใช้ บทบาท สิทธิ์เจ้าของ และ workspace ไม่ส่งผลวัดออกไปยังบริการภายนอก ไม่เก็บ request/response body หรือ query string

API และรูปภาพวัดจาก PerformanceResourceTiming: เป็นเวลา resource ที่ browser รายงาน ไม่ใช่ CPU ล้วน ขนาดหรือ HTTP status อาจไม่ปรากฏจากแคชหรือข้อจำกัดข้าม origin เวลาโหลดรูปไม่รวม decode/render ภาพ Long task และช่วงเฟรมเป็นการวัดบนเครื่องที่ใช้งาน ไม่ใช่ผลจาก iPhone จริงโดยอัตโนมัติ

## ตรวจตาราง

API GET /api/performance?table=... อ่านสูงสุด 10 แถว ทดสอบแยกสูงสุด 50 สูตร/200 ครั้ง และตรวจงบเวลา 2 วินาทีระหว่างรอบ ไม่ขัดจังหวะสูตรเดี่ยวที่กำลังคำนวณ คำนวณแถวพร้อม dependencies ก่อน แล้ววัดสูตรแต่ละรายการแยกโดยอาจใช้แคช ไม่เรียก Action, Automation, webhook หรือสร้าง PDF และไม่แก้ข้อมูล

แสดงเวลาฐานข้อมูลตัวอย่าง เวลาคำนวณแถว และเวลารวม/เฉลี่ย/สูงสุดต่อสูตร ไม่ส่งค่าจากแถวหรือ source สูตรกลับในรายงาน ประวัติ Automation แสดงเฉพาะเจ้าของ สูงสุด 50 งานของตาราง เวลา Automation คือ updated_at-created_at ของงานจบแล้ว หรือเวลารอตั้งแต่ created_at สำหรับงานค้าง จึงรวมคิว/การลองใหม่และไม่ใช่เวลา execution ล้วน

## เปรียบเทียบ

เลือกก่อน–หลังเป็นคนละรอบของประเภทเดียวกัน ผลตรวจสูตรต้องตารางเดียวกัน แสดงผลต่าง ms และ % ลดลงเป็นเขียว เพิ่มขึ้นเป็นแดง ควรใช้ข้อมูล อุปกรณ์ เครือข่าย และสถานะแคชใกล้เคียงกัน ไม่มีข้อมูลแสดง — แทนการตีความว่าใช้เวลา 0

## การทดสอบ

scripts/integration.cjs perfdiagnostics ตรวจข้อมูลไม่ถูกเขียน สิทธิ์ผู้ใช้/เจ้าของ การบันทึก API/รูปภาพ การตัด query string ประวัติและ comparison UI รวมถึงมือถือจำลอง tests/performance-metrics.test.cjs ตรวจ P95 ขอบเขตประวัติ/รายการ และการแยก scope


## ปรับปรุงรอบ 27 ต.ค. 2569

- เพิ่มเวลาเปิดหน้า (Route เริ่มเปลี่ยนจนหน้าพร้อมใช้งาน ไม่รวมเวลาจบ animation) พร้อม P95
- ไม่นับการรอ Realtime และการตรวจ Automation เบื้องหลังเป็น API ช้า
- เก็บรายการ Resource ที่ค้างใน PerformanceObserver ก่อนหยุดวัด และตัดเวลารอบที่ 60 วินาทีแม้พักแท็บ
- แสดงเบราว์เซอร์ ขนาดจอ และ DPR ของรอบวัด ใช้เทียบรอบอุปกรณ์เดียวกัน
- ปุ่ม “ส่งออกผลการวัด” ส่งออก JSON เฉพาะรอบที่เลือก ไม่มี cookie/query string/เนื้อหาแถว/สูตรหรือชื่อ Automation
- ประวัติและการบันทึกอ้างบทบาทผู้พัฒนาแอปที่มีผลอยู่ปัจจุบัน

### วัดบน iPhone จริง
1. เข้าแอปด้วยบัญชีผู้พัฒนาแอป แล้วเปิดเมนูวิเคราะห์ความช้าบน iPhone เครื่องที่จะทดสอบ
2. ตั้งชื่อรอบ เช่น “iPhone ก่อน · เปิดรายละเอียด” และกดเริ่มบันทึก
3. กด “ไปใช้งานแอพ” ในหน้าเดียวกัน ทดสอบค้นหา เปิดรายละเอียด กดกลับ และเปิดฟอร์ม
4. หยุดวัด กลับมาวิเคราะห์ความช้า แล้วกดส่งออกผลการวัด
5. ทำขั้นตอนเดิมหลังปรับ โดยใช้อุปกรณ์ ขนาดจอ เครือข่าย บทบาท และข้อมูลเดียวกัน

การทดสอบด้วย Chromium mobile emulation ไม่ถือว่าเป็นผลวัดจาก iPhone จริง ผล SQL แบบอ่านอย่างเดียวไม่ใช่เวลารวม API หรือหน้าจอ

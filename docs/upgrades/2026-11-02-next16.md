# Next 16 upgrade — 2026-11-02

## Scope and installed versions

The repository already pinned Next 16.4.3 and React/react-dom 19.3.1, but installed node_modules still used Next 14 / React 18. Installed the lockfile with npm ci; verified actual exit code 0 and exact runtime/type pins. @types/react and @types/react-dom are 19.3.0. No version range or lockfile update was necessary.

Environment: Windows, Node 22.12.0. SQLite native module successfully loads in memory. Approved only the pinned better-sqlite3 11.10.0 install script in package.json.

## Changes

- Development uses Turbopack; production retains the existing webpack build. Test server selects the matching bundler.
- Disabled persistent Turbopack development filesystem caching after repeated HMR reloads on Windows. Cache-enabled barcode dev testing repeatedly reloaded /run and timed out; cache-disabled tests passed twice. This is a tested mitigation, not proof of the underlying framework/cache root cause.
- Webpack development also reproduced a Builder reload when a preview iframe connected after compilation. A beforeunload stack led to the Next HMR client; installed server broadcasts SYNC hashes to connected clients. Production was unaffected. Turbopack passed the unsaved-preview regression.
- Added a framework installation regression test so an old node_modules cannot silently pass against new manifest pins.
- Preview test now opens the record through its actual UI instead of forcing iframe navigation; all original assertions are retained.
- Named-app conversion HTTP test uses the real app cookie instead of an internal route header stripped by the proxy.
- Added generated development type directories to tsconfig for separate test/build output locations.

## Remaining risks / limits

- Seven POSIX deployment helper tests are skipped on Windows; Linux/Docker deployment was not tested in this task.
- Transitive @zxing/library 0.23.0 declares Node >=24, while this machine runs Node 22.12.0. npm emits an engine warning. Barcode browser tests pass, but that does not certify the dependency's full Node support. No global Node upgrade or scanner downgrade was performed.
- Physical iPhone camera, real SMTP/external providers and all feature permutations were not tested; camera tests use a simulated stream and actual image decoding.
- Disabling persistent dev caching can increase cold compilation time. Reassess the workaround on future Next patch versions; production cache settings are unchanged.
- HMR diagnostics are retained locally as logs, not as production or test instrumentation.
- Existing conversion bug fixes were preserved. AUD-002 authentication policy changes remain paused and untouched.

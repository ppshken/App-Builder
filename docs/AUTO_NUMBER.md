# เลขรันอัตโนมัติสำหรับ Text

เปิดที่ **Data → ตาราง → คอลัมน์ชนิด Text → เลขรันอัตโนมัติ** แล้วกำหนดข้อความนำหน้า ข้อความต่อท้าย จำนวนหลักขั้นต่ำ และเลขเริ่มต้น เช่น `DOC-` + 5 หลัก + เริ่ม 1 ได้ `DOC-00001`

## พฤติกรรม

- สร้างเลขจริงที่เซิร์ฟเวอร์ตอนบันทึกเท่านั้น การเปิดฟอร์มและโหลดค่าเริ่มต้นไม่จองเลข
- นับแยกตามตารางและคอลัมน์ แอปที่เชื่อมใช้ตารางเดียวกันใช้ลำดับร่วมกัน
- ใช้ SQLite IMMEDIATE transaction เดียวกับการบันทึกแถวและรายการลูก หากบันทึกไม่สำเร็จ การเพิ่มลำดับจะถูกย้อนกลับด้วย
- การแก้ไขคงเลขเดิม การเพิ่มหรือคัดลอกผ่าน Action สร้างเลขใหม่ ห้ามระบุเลขเองผ่าน API ตอนเพิ่ม และห้ามแก้เลขเดิม
- อ่านอย่างเดียวและห้ามซ้ำอัตโนมัติ ใช้เป็น Key/Label ได้ แต่ Ref ภายในยังเชื่อมด้วย `id` เดิม
- ไม่เติมเลขย้อนหลังให้ข้อมูลเก่า เมื่อเริ่มใช้จะตรวจเลขที่ตรงข้อความนำหน้า/ต่อท้ายเดิมและนับต่อจากค่าสูงสุด
- ลบข้อมูลแล้วไม่ลดตัวนับ รวมถึงหลังสำรอง/กู้คืน หรือโคลนพร้อมข้อมูล โคลนฐานข้อมูลใหม่แบบไม่เอาข้อมูลเริ่มนับใหม่
- เปลี่ยนชื่อคอลัมน์ยังคงลำดับ เปลี่ยนข้อความนำหน้าหรือต่อท้ายไม่รีเซ็ตตัวนับ กำหนดเลขเริ่มต้นที่สูงขึ้นได้แต่ลดเลขเพื่อใช้ซ้ำไม่ได้
- จำนวนหลักเป็นขั้นต่ำ เช่น 3 หลัก เมื่อเกิน 999 จะได้ 1000 โดยไม่ตัดเลข หากเกินจำนวนตัวอักษรสูงสุดของคอลัมน์จะบันทึกไม่ผ่านและไม่ใช้เลขนั้น
- ข้อความนำหน้าและต่อท้ายเป็นข้อความคงที่ รุ่นนี้ยังไม่รีเซ็ตรายเดือน/ปี และไม่ใช้สูตรประกอบข้อความนำหน้า
- ใช้ร่วมกับช่องคำนวณ ค่าเริ่มต้น Reset On Edit สแกน หรือ Editable_If ไม่ได้ ต้องปิดเลขรันก่อนแปลงชนิดหรือคัดลอกคอลัมน์
- นำเข้า Excel แถวใหม่: เว้นคอลัมน์เลขรันว่างเพื่อให้สร้างใหม่ แก้ไขแถวเดิมต้องคงเลขเดิม

ตัวอย่างที่แสดงในหน้าตั้งค่าเป็นเพียงรูปแบบจากเลขเริ่มต้น ไม่ใช่เลขที่จองไว้หรือลำดับถัดไปที่รับประกัน

## โครงสร้าง

- `_columns.auto_number_json`: การตั้งค่ารูปแบบ ไม่เก็บเลขถัดไปจาก client
- `_auto_numbers`: เก็บ high-water mark ตามตารางและคอลัมน์ มี foreign key แบบ cascade เพื่อรองรับการเปลี่ยนชื่อ/ลบคอลัมน์
- `lib/auto-number.ts`: ตรวจ config จัดรูปแบบ และจัดสรรเลขภายใน transaction
- `lib/data-write.ts`: เส้นทางบันทึกกลาง รวมฟอร์ม Action และรายการลูก
- `lib/columns.ts`: ข้ามการบังคับกรอกเลขที่ยังไม่ถูกสร้างในฉบับร่าง แต่ตรวจ Required/Valid_If ด้วยเลขจริงที่เซิร์ฟเวอร์
- `app/components/AutoNumberSettings.tsx`: ตัวเลือกของคอลัมน์ Text
- ชุด migration มี snapshot ก่อนเปลี่ยน schema ตามกลไกเดิม ไม่แก้ค่าข้อมูลเก่า

การอ่านหาค่าสูงสุดจะเกิดครั้งแรก หลังเปลี่ยนรูปแบบ หรือหลังบันทึกการตั้งค่าคอลัมน์ ส่วนการเพิ่มรายการปกติอ่านตัวนับและตรวจค่าซ้ำผ่าน index ไม่สแกนตารางทุกครั้ง

## การตรวจสอบ

ใช้ฐานข้อมูลจำลองเท่านั้น ไม่แก้ฐานข้อมูลจริง ไม่ deploy

- `node scripts/test.cjs`: รวม regression ของระบบ และ `tests/auto-number.test.cjs` สำหรับ config, transaction rollback, ลบแล้วไม่ใช้เลขซ้ำ, Unicode, เปลี่ยนชื่อ, migration, clone และ backup/restore
- `node scripts/integration.cjs autonumber`: ทดสอบ UI ตั้งค่า Text, โหลด defaults, API, บันทึกพร้อมกัน 20 คำขอ, Action copy, ตารางลูก, ฟอร์มมือถือที่ใช้เลขรันเป็น Key และการเปลี่ยนชื่อคอลัมน์
- ภาพตัวอย่าง: `artifacts/auto-number-settings.png` และ `artifacts/auto-number-mobile.png`
- หลักฐานการรัน: `.test-data/auto-number/`

ยังไม่ได้ทดสอบบน iPhone เครื่องจริงหรือโหลดระดับ production หลาย process การตรวจมือถือใช้ Chromium ที่ความกว้าง 390px

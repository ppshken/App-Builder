# สำรองรายแอป ไฟล์ และประวัติการใช้งาน

เข้าที่ **แอปของฉัน → การจัดการข้อมูลส่วนกลาง** สำหรับเจ้าของ Builder / Admin สูงสุด

## สำรองแยกแอป

- เลือกแอปเพื่อดูตาราง จำนวนแถว และสถานะตารางที่เชื่อม/ใช้ร่วม
- ดาวน์โหลด `.app.db` รวมตารางที่แอปอ่านได้ โครงสร้าง ข้อมูล Ref, View, Slice, Action, Settings, PDF, Automation และบทบาท/สมาชิกแบบรายแอป
- ต้องมีสิทธิ์ export ครบทุกตาราง ตรวจไฟล์ที่สร้างด้วยตัวตรวจสอบโครงสร้างก่อนส่งให้ผู้ใช้
- สร้างฐานข้อมูลใหม่จริง ไม่ใช่ลบข้อมูลอื่นออกจากสำเนาเดิม จึงไม่มีข้อมูลที่ลบแล้วตกค้างในหน้าว่างของ SQLite
- ไม่บรรจุรหัสผ่านเดิม Session ผู้ใช้ที่ไม่เกี่ยวข้อง ประวัติเวอร์ชัน และคิว Automation รูป/ไฟล์รวมเฉพาะที่ตรวจพบการอ้างอิงจากแอป รวมการอ้างอิงในค่าตั้งต้น สูตร และการตั้งค่า
- ไฟล์อาจมีข้อมูลธุรกิจและค่าตั้งค่า webhook ที่ผู้พัฒนาระบุไว้ จัดเก็บไฟล์สำรองตามสิทธิ์ของข้อมูลนั้น
- รูป/ไฟล์เก็บเป็น BLOB ในแพ็กเกจ ไม่ต้องพึ่งสำเนาใน uploads และไม่ย้ายไฟล์ปลายทางตาม path จากเครื่องต้นทาง
- หากตาราง Ref/สูตร/การตั้งค่าอ้างถึงตารางที่ไม่ได้เชื่อมให้แอป การตรวจจะปฏิเสธ ต้องเชื่อมตารางที่เกี่ยวข้องให้ครบก่อน

### กู้คืน

อัปโหลดไฟล์ → ตรวจสรุป → ตั้งชื่อแอปใหม่ → พิมพ์ `กู้คืน` → ยืนยัน

- รุ่นนี้กู้คืนเป็นแอปและตารางชุดใหม่เท่านั้น ไม่ทับแอปเดิมหรือตารางร่วม สร้างสำรองทั้งระบบก่อนดำเนินการ
- ตรวจ integrity, ชนิดคอลัมน์, Ref, สูตร, View, Action, Workflow และสิทธิ์ด้วยตัวตรวจสอบเดิม โดยสร้าง ready.db จาก schema ที่เชื่อถือได้ ไม่เรียก SQL จากไฟล์อัปโหลด
- จำกัดอัปโหลด 512 MB และรายการตรวจไฟล์ 4 รายการต่อ process เก็บ token 15 นาที ผูกกับผู้ใช้ รุ่นฐานข้อมูล และ revision ของบัญชี
- ใช้ transaction: หากผิดพลาด ยกเลิกการสร้างแอป ตาราง ไฟล์ และสิทธิ์ทั้งหมด
- จับคู่สมาชิกกับบัญชีปัจจุบันด้วยอีเมลแบบไม่สนตัวพิมพ์ บัญชีที่ไม่มีอีเมลใช้ username ตามแนวทาง accountMapping ของระบบ ไม่สร้างบัญชีหรือเปลี่ยนรหัสผ่าน
- User column ใช้ ID บัญชีปลายทางที่จับคู่ได้ หากหาไม่ได้จะว่าง แสดงจำนวนบัญชีที่หาไม่พบก่อนยืนยัน
- บทบาท/สิทธิ์รายแอปกลับมา แต่ไม่ให้สิทธิ์เจ้าของ Builder เพิ่มจากไฟล์สำรอง
- Ref และสูตรตารางเปลี่ยนชื่อให้ตรงตารางใหม่ รูป/ไฟล์ได้รับ UUID ใหม่ และแก้ URL ในแถว คอลัมน์ และ config ให้สอดคล้อง
- Automation ทุกตัวปิดไว้ พร้อมกำหนดผู้รับผิดชอบเป็นผู้กู้คืน ไม่มีการนำคิวงานเดิมกลับมารัน
- แยกชนิดไฟล์ด้วย SQLite application_id เพื่อป้องกันนำไฟล์รายแอปไปกู้คืนทับทั้งระบบโดยผิดหน้า

## ไฟล์และรูปภาพ

- กรองแอป ประเภท ชื่อ/ID และสถานะการอ้างอิง แสดงขนาด วันอัปโหลด (สำหรับไฟล์ใหม่) และจุดอ้างอิง
- ตรวจตารางกายภาพ ค่าคอลัมน์ config ทุกแอป ประวัติเวอร์ชัน งาน Automation และรูปโปรไฟล์
- ตารางร่วมจะแสดงจุดอ้างอิงตามแอปที่อ่านตารางได้
- ลบจากฐานข้อมูลได้เฉพาะไฟล์ที่ไม่พบการอ้างอิง ตรวจซ้ำทุกแอปภายใน immediate transaction ก่อนลบ
- การตรวจอ้างอิงเป็นการตรวจ URL สื่อภายในระบบ ไม่สามารถรับรู้การเก็บ URL ไว้ภายนอกระบบหรือ URL ที่ประกอบแบบ dynamic ได้ จึงไม่มีการลบอัตโนมัติ
- สำเนาใน uploads และสำรองเก่าไม่ถูกลบตามไปด้วย รุ่นนี้ยังไม่มีการเคลียร์สำเนาไฟล์บนดิสก์หรือที่เก็บภายนอก
- ไฟล์เดิมไม่มีวันที่/แอปผู้อัปโหลด แสดงไม่ทราบวันที่ และจัดแอปตามจุดอ้างอิง ไม่สร้างประวัติย้อนหลังขึ้นเอง
- หน้านี้เป็นงานจัดการของผู้ดูแล การค้นหาจุดอ้างอิงต้องอ่านคอลัมน์ที่เกี่ยวข้องจากฐานข้อมูล ไม่ทำทุกครั้งที่ผู้ใช้ทั่วไปเปิด View

## ประวัติใช้งานแอป

- แยกจาก Audit Log ของการเปลี่ยนแปลง Builder
- เก็บ login, login_failed สำหรับบัญชีที่รู้จัก, logout, เข้าแอป, คำขอเพิ่ม/แก้ไข/ลบข้อมูล อัปโหลด นำเข้า/ส่งออก Excel, Action และการสำรอง/กู้คืน
- แสดง actor, app, event, เป้าหมายระดับ API, เวลา และ HTTP status กรองแอป ผู้ใช้ เหตุการณ์ และช่วงวันที่ได้
- การเปิด /run หรือ PWA ส่งเหตุการณ์แบบ background โดยไม่ล้างแคช ไม่แสดง toast และไม่นับซ้ำผู้ใช้/แอปเดียวกันภายใน 60 วินาที
- นี่เป็นประวัติเหตุการณ์ ไม่ใช่จำนวนคนออนไลน์ ไม่ใช่สถิติเวลาที่อยู่ในหน้า และไม่ใช่ row-level audit ของค่าก่อน–หลังทุกแถว งาน Automation ที่ทำต่อภายหลังดูจากประวัติ Automation
- ไม่เก็บ request body, password, token หรือ query string ของผู้ใช้ในตารางนี้
- ค่าเริ่มต้นเก็บ 180 วัน ตั้ง `NOCODE_USAGE_RETENTION_DAYS` ได้ 1–3650 วัน เคลียร์เป็นชุดสูงสุด 5,000 รายการต่อชั่วโมงเมื่อมีเหตุการณ์ใหม่ ข้อมูลเก่าจำนวนมากอาจต้องทยอยล้างหลายรอบ
- การกู้คืนทั้งระบบยังคงประวัติการใช้งานปัจจุบันไว้ และไม่นำประวัติจากไฟล์อัปโหลดมาติดตั้งแทน

## งานเซิร์ฟเวอร์

การสำรองทั้งระบบเดิมและ `deploy/backup.sh` ยังคงใช้ได้ งานสำรองรายแอปรุ่นนี้เป็นการดาวน์โหลดด้วยตนเอง ยังไม่ได้เพิ่มตารางเวลารายแอป การส่ง S3/ไดรฟ์ภายนอก หรืออีเมลแจ้งเตือน ต้องกำหนดที่เก็บ ระยะเก็บ และช่องทางแจ้งเตือนก่อนเชื่อมบริการจริง

# กู้คืนข้อมูลหลายแอป

พัฒนาตามคำอนุมัติให้รองรับหลายแอป และตัวเลือกของผู้ใช้: คงบัญชี/รหัสผ่านปัจจุบัน จับคู่สิทธิ์จากไฟล์สำรองด้วยอีเมล

## การใช้งาน

แอปของฉัน → การจัดการข้อมูลส่วนกลาง → สำรองและกู้คืน → ตรวจไฟล์และกู้คืน หรืออัปโหลดไฟล์ .db ไม่เกิน 512 MB

หน้าตรวจไฟล์แสดงจำนวนแอป บทบาท ตาราง รายการ View รูปภาพ/ลายเซ็น ไฟล์ และจำนวนบัญชีที่จับคู่อีเมลได้/ไม่ได้ การตรวจยังไม่เปลี่ยนฐานข้อมูลปัจจุบัน ต้องพิมพ์ กู้คืน และกดยืนยันก่อนทำงานจริง ใช้ได้เฉพาะเจ้าของ Builder ผู้พัฒนาแอปไม่มีสิทธิ์กู้คืนแพลตฟอร์ม

กู้คืนทั้งแพลตฟอร์ม ไม่ใช่รวมแอปเข้ากับข้อมูลปัจจุบัน แอป/ตารางที่ไม่มีในไฟล์สำรองจะถูกนำออก ทุกแอปในไฟล์ได้ทะเบียนแอป เจ้าของตาราง การเชื่อมตาราง/เพดานสิทธิ์ View/Slice/Action การตกแต่ง Settings PDF Automation และประวัติเวอร์ชันที่เผยแพร่กลับมา ข้อมูลและ Ref คงรหัสเดิม

## บัญชีและสิทธิ์

- คงบัญชีปัจจุบัน รหัสผ่าน ชื่อ อีเมล ประเภทบัญชี สถานะ และสิทธิ์เจ้าของ Builder ไม่ติดตั้งบัญชี/รหัสผ่าน/ประเภทบัญชีจากไฟล์
- คืนบทบาทรายแอป สิทธิ์ตาราง/แถว/Action/Excel และการมอบหมายผู้พัฒนา โดยจับคู่ user ID ต้นทางกับบัญชีปัจจุบันด้วยอีเมลที่ trim และเทียบตัวพิมพ์เล็ก ไม่ใช้เลข ID ตรงกันเป็นหลักฐาน
- บัญชีที่จับคู่ไม่ได้ไม่ถูกสร้างใหม่ และไม่นำสิทธิ์ไปให้บัญชีที่เลข ID ตรงกันแต่คนละอีเมล บัญชีปัจจุบันที่ไม่มีสิทธิ์ใน snapshot ยังอยู่ แต่ต้องได้รับสิทธิ์ใช้งานใหม่ เจ้าของปัจจุบันยังจัดการได้ทุกแอป
- อีเมลซ้ำแบบไม่แยกตัวพิมพ์เล็ก/ใหญ่ทำให้การตรวจปฏิเสธ เพื่อไม่จับคู่ผิด
- นิยามค่าตั้งค่าผู้ใช้กลับมาตามแอปใน snapshot ค่าส่วนตัวปัจจุบันที่ยังเข้ากันได้ถูกคงไว้ หากไม่มีค่าปัจจุบันจึงใช้ค่าต้นทางที่จับคู่ด้วยอีเมล
- ไม่ลดระบบที่แยกสิทธิ์แล้วกลับไปใช้ global fallback ไฟล์รุ่นเก่าจะถูกแปลงสิทธิ์เป็นบทบาทรายแอปใน staging ก่อนจับคู่ เมื่อปลายทางมีบัญชีจะไม่เปิด global fallback แม้ไฟล์เก่าไม่มีบัญชีให้จับคู่ โดยไม่เปลี่ยนไฟล์ต้นทาง หากเกิดชื่อบทบาทชนกันจะปฏิเสธแทนการเปลี่ยนค่า USERROLE โดยเงียบ
- หากบัญชี อีเมล ประเภทบัญชี หรือสถานะเปลี่ยนหลังตรวจไฟล์ จะต้องตรวจไฟล์ใหม่ก่อนกู้คืน

## ความถูกต้องและการทำงานเบื้องหลัง

สร้างโครงสร้าง staging และโครงสร้างปลายทางจาก schema ของระบบที่ติดตั้งและนิยามคอลัมน์ที่ผ่านการตรวจ ไม่รัน CREATE TABLE/INDEX/TRIGGER จาก SQL ของไฟล์อัปโหลด รองรับเฉพาะ namespace ของแอปที่ลงทะเบียนและรหัสแอปที่ถูกต้อง ปฏิเสธ SQL View/Trigger ที่ไม่ใช่ของระบบ ตารางแปลกปลอม คอลัมน์เวอร์ชันใหม่ที่ระบบยังไม่รู้จัก และคอลัมน์ SQL นอกโครงสร้างที่อนุญาตในประวัติเวอร์ชัน

ตรวจ schema/Ref สูตร Key/Unique View/Slice/Inline/Dashboard Action PDF Automation สิทธิ์ ค่าตั้งค่าผู้ใช้ และ Foreign Keys ก่อนให้ยืนยัน คืนเนื้อหาใน SQLite transaction เดียว ใช้ไฟล์/connection ปัจจุบัน โดยสร้างสำรองก่อนเริ่ม หากผิดพลาดระหว่างทาง rollback ทั้งข้อมูล โครงสร้าง สิทธิ์ และ sessions

Automation ของทุกแอปถูกปิด งาน queued/running ถูกยกเลิก บัญชีผู้สั่งงาน/เจ้าของ Automation และประวัติเวอร์ชันถูกจับคู่ด้วยอีเมลด้วย ไม่ทำงานภายนอกซ้ำอัตโนมัติ ให้ผู้ดูแลตรวจและเปิด Automation อีกครั้ง งานภายนอกที่ส่งออกไปแล้วก่อนกู้คืนไม่สามารถย้อนผลภายนอกได้

รวมประวัติ audit จากไฟล์กับปัจจุบันตาม event ID และบันทึกเหตุการณ์กู้คืนด้วยบัญชีผู้ดำเนินการ เก็บรหัสลำดับ AUTOINCREMENT ติดตั้ง index และ audit/realtime triggers จากโค้ดระบบใหม่ หลังสำเร็จเพิกถอนทุก session ล้างบริบทแอป/ฉบับร่างและแคชของผู้กู้คืน แล้วกลับ login ด้วยบัญชีปัจจุบัน

## ขอบเขต

ไฟล์ .db รวมข้อมูลสื่อใน SQLite และเวอร์ชันที่เผยแพร่แล้ว งานร่างที่ยังไม่เผยแพร่ในโฟลเดอร์ .app-releases ไม่รวมอยู่ในไฟล์นี้ ต้องสำรองโฟลเดอร์แยกหากต้องการย้ายงานร่าง ไม่มีการกู้คืนฐานข้อมูลจริงของผู้ใช้ระหว่างพัฒนาและทดสอบ

- Regression ส่วนกลาง สิทธิ์ผู้พัฒนา API และ production build ใช้ฐานข้อมูลแยกใน .test-data ทั้งหมด

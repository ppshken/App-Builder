# Table realtime synchronization

Enable Realtime in Data > table > Columns > Data synchronization. Off by default. The switch saves immediately and rolls back visually on failure. Owner/builder permission is required. Settings are part of _tables and follow draft/publish metadata; draft previews do not maintain live SSE connections.

The live database has a revision counter per table in _realtime_versions. Trusted INSERT/UPDATE/DELETE triggers increment it within the same transaction only while realtime_enabled is set. Rollbacks produce no committed change. Toggling the setting also advances its revision. Triggers cover normal saves, child rows, cascade deletes, Excel import, Actions, and Automation without individual endpoint notifications. Startup, table creation, and table rebuild install the triggers. Table deletion removes the config trigger and revision record. Backup inspection accepts only exact generated trigger SQL and restores trusted triggers.

GET /api/realtime uses an authenticated SSE stream, one per visible application document, multiplexing all enabled readable tables. It checks small revision records once per second; no row payload is broadcast. API reads still apply table/Slice/row permissions. Each tick rechecks the session and current table permissions. Streams close after 60 seconds; native EventSource reconnects and receives a fresh snapshot. Closing/offline/background pauses the connection; returning compares snapshots to recover missed changes. Reverse proxies must allow streaming and avoid response buffering. Responses retain no-transform and X-Accel-Buffering:no. This requires a persistent Node runtime and shared SQLite database, not a static export. Multiple tabs each use a connection; HTTP/2 is preferable for many tabs.

The client coalesces notifications, invalidates data caches, and refreshes affected table dependencies (Refs, Related children, and explicit cross-table formulas). Lists, details, Inline counts, and Dashboard panels update without remounting the app shell or resetting scroll. Active form values are never replaced by realtime reads; existing row-version conflict checks reject stale saves. Form choices refresh on normal reopening; realtime does not recalculate and replace a dirty form. Formula references computed dynamically without a literal table name may require a manual refresh.

Typical update delay is around 1–2 seconds plus API/network time. This is live read synchronization; it does not implement offline writes, simultaneous collaborative text editing, or changes to external data files that do not pass through this database. Disabled tables do not generate row notifications; changes to an enabled related table can still refresh a dependent View. No tables are enabled automatically.

Validation: node scripts/integration.cjs realtime; node scripts/integration.cjs backstate; node scripts/integration.cjs concurrentedit; node scripts/integration.cjs savingworkflow; node scripts/test.cjs. All tests use isolated databases.

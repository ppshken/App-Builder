# ตรวจช่องตารางล้นให้พรีวิวและ PDF ตรงกัน

วันที่: 16 พฤศจิกายน 2026

## ปัญหาที่ตรวจพบ

พรีวิวเดิมแสดง HTML ที่ซ่อนส่วนล้นในช่อง แต่ไม่ตรวจความสูง ส่วนการสร้าง PDF ตรวจว่าความสูงเนื้อหาเกินช่องหรือไม่และหยุดด้วยข้อความรวม จึงไม่รู้ว่าต้องแก้หน้า ตาราง หรือช่องใด

## การเปลี่ยนแปลง

- พรีวิวข้อมูลจริงและการสร้าง PDF เรียกฟังก์ชันตรวจขนาดช่องเดียวกันบน Chromium โดยใช้สื่อสำหรับพิมพ์ รอฟอนต์และรูปภาพถอดรหัสเสร็จก่อนวัด
- ตรวจทั้งแนวตั้งและแนวนอน โดยเผื่อความคลาดเคลื่อนการปัดเศษ 2 พิกเซลตามกติกาความสูงเดิม
- ใส่ข้อมูลตำแหน่งในช่อง ได้แก่ หน้ารายงาน ตาราง แถว และคอลัมน์ ตารางลูกใช้ลำดับแถวต่อเนื่องข้ามหน้า ส่วนหัวตารางระบุแยก
- พรีวิวยังเปิดได้เมื่อพบปัญหา แต่แสดงกรอบสีแดงและรายการตำแหน่งพร้อมระยะที่เกินเป็นมิลลิเมตร แสดงรายละเอียดสูงสุด 20 ช่องพร้อมยอดรวม
- ตอนสร้าง PDF ยังหยุดหากเนื้อหาล้น เพื่อไม่ให้ตัดข้อมูลโดยไม่แจ้ง และให้รายละเอียด 5 ตำแหน่งแรก
- ไม่ส่งค่าข้อมูลในช่องหรือรหัสแถวจริงในข้อความแจ้งเตือน ไม่เปิด JavaScript หรือปลด sandbox ของกรอบพรีวิว
- การไฮไลต์เป็นรูปแบบหน้าจอเท่านั้น ไม่บันทึกลงแม่แบบหรือแก้พิกัดวัตถุ
- จำกัดงานตรวจหรือสร้าง PDF พร้อมกันไม่เกิน 2 งานต่อกระบวนการ หากเต็มให้ลองอีกครั้ง พรีวิวที่ไม่มีช่องตารางไม่เปิด Chromium เพิ่ม

## ไฟล์ที่เกี่ยวข้อง

- lib/pdf-overflow.ts: การตรวจขนาด ข้อความตำแหน่ง และการทำเครื่องหมายช่อง
- lib/pdf-design-html.ts: ข้อมูลกำกับตำแหน่งแต่ละช่อง
- lib/pdf-report.ts: ใช้เบราว์เซอร์และเงื่อนไขตรวจร่วมกัน
- app/api/pdf-templates/route.ts: ตรวจพรีวิวก่อนส่งกลับ
- app/components/PdfPreviewFrame.tsx และ pdf-preview-frame.css: สรุปปัญหาและแสดงช่องสีแดง

## หลักฐานการทดสอบ

- ก่อนแก้: .test-data/pdf-overflow-red.log พรีวิวไม่ทำเครื่องหมายช่องที่ล้น
- ทดสอบหน่วย: .test-data/pdf-overflow-unit.log จำนวน 638 ข้อ ผ่าน 631 ข้อ ข้าม 7 ข้อ ไม่มีข้อที่ล้มเหลว
- สร้างชุดเผยแพร่ด้วยฐานข้อมูลทดสอบแยก: .test-data/pdf-overflow-build.log
- ทดสอบใหม่: .test-data/pdf-overflow-pdfoverflow.log ตรวจข้อความยาว ช่องสีแดง ตำแหน่ง ข้อผิดพลาดตอนสร้างจริง ตารางลูกหน้าต่อ และรูปแนวตั้งที่พอดีช่อง
- ทดสอบเดิม: .test-data/pdf-overflow-pdfupgrade.log และ .test-data/pdf-overflow-pdftables.log รวมการตั้งค่ารูป แบ่งหน้า และการสร้างไฟล์ PDF จริง
- พรีวิวเดิม: .test-data/pdf-overflow-pdfpreview-recheck.log ทดสอบแยกผ่าน หลังรอบที่รันพร้อมกันหลายชุดเกินเวลารอ 5 วินาที จากนั้นปรับพรีวิวที่ไม่มีตารางให้ข้ามการเปิดเบราว์เซอร์ที่ไม่จำเป็น
- ภาพหน้าจอ: artifacts/pdf-overflow-preview.png

## ขอบเขตและข้อจำกัด

ตรวจช่องของตารางที่สร้างด้วยตัวออกแบบ ไม่เพิ่มกติกาตัดคำหรือขยายแถวอัตโนมัติ แม่แบบจริงของผู้ใช้ยังต้องกดพรีวิวใหม่เพื่อระบุตำแหน่งปัญหา ยังไม่ยืนยันสาเหตุเฉพาะของแม่แบบนั้นจากข้อมูลจำลอง การตรวจผ่านเบราว์เซอร์ทำให้พรีวิวที่มีตารางใช้เวลาเพิ่ม โดยแสดงสถานะกำลังสร้างตัวอย่างระหว่างรอ

ไม่ติดตั้งส่วนเสริมใหม่ ไม่แก้ฐานข้อมูลจริง และไม่เผยแพร่ขึ้นเซิร์ฟเวอร์

ผลรอบสุดท้าย: Build ผ่าน และเบราว์เซอร์ทั้ง 4 ชุดผ่านหลังปรับการตรวจกรณีไม่มีตาราง หลักฐานอยู่ใน .test-data/pdf-overflow-final-pdfoverflow.log, .test-data/pdf-overflow-final-pdfpreview.log, .test-data/pdf-overflow-final-pdfupgrade.log และ .test-data/pdf-overflow-final-pdftables.log

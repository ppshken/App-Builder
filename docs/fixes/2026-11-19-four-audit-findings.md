# แก้บัคที่ได้รับอนุมัติทั้งสี่เรื่องจากการทดลองใช้งาน

วันที่: 19 พฤศจิกายน 2569

อ้างอิงรายงาน `docs/reviews/2026-11-19-exploratory-testing.md` ผู้ใช้อนุมัติให้แก้ทั้งสี่เรื่อง ใช้ฐานข้อมูลทดสอบแยก ไม่ Deploy และไม่แก้ข้อมูลจริง งานก่อนหน้าที่ค้างใน Git ถูกเก็บไว้ตามเดิม

## EXP-20261119-001 — Draft หายเมื่อเพิ่มตารางอื่น

ระดับ P1

สาเหตุ: Runtime ใช้สิทธิ์รวมทั้งแอปสร้าง Permission Epoch เมื่อ Owner ได้ Dataset ของตารางใหม่ Epoch เปลี่ยนและทำให้หน้าฟอร์มถูกสร้างใหม่ แม้สิทธิ์ตารางที่กำลังกรอกไม่เปลี่ยน

แก้ไข:

- เพิ่มตัวเปรียบเทียบ `runtimeAccessInvalidates` ใน `lib/access.ts`
- รักษาหน้าฟอร์มได้เมื่อเป็นการเพิ่มทรัพยากรใหม่เท่านั้น โดยสิทธิ์เดิมทุกตัว บทบาท กฎแถว และขอบเขตความปลอดภัยต้องเหมือนเดิม
- การเปลี่ยนสิทธิ์เดิม การถอน Action การเปลี่ยน Role/กฎแถว และการเปลี่ยนขอบเขต Dataset ยังเพิ่ม Epoch และล้าง Cache ตามเดิม
- `app/run/page.tsx` แยกการโหลดรายการ View ใหม่ออกจากการล้างหน้าที่เปิดอยู่ จึงเพิ่มเมนูใหม่ได้โดยไม่ล้าง Draft
- ไม่ปิดตัวตรวจสิทธิ์ Backend และไม่เก็บ Draft ข้ามบัญชีหรือแอป

ก่อนแก้ Regression Test การรักษา Draft ไม่ผ่าน ตาม `.test-data/four-fixes-draft-red.log` หลังแก้ทดสอบบนหน้าเว็บมือถือและ Desktop ว่าค่าเดิมและ DOM ช่องกรอกยังอยู่ ไม่มี POST บันทึกอัตโนมัติ และยังบันทึกได้ตามปกติ

ไฟล์: `lib/access.ts`, `app/run/page.tsx`, `tests/runtime-access-change.test.cjs`, `tests/audit-four-fixes-browser.cjs`

## CONV-001 — กฎสิทธิ์ระดับแถวรายแอปไม่ถูกตรวจระหว่างแปลง

ระดับ P1

สาเหตุ: ตัวแปลงตรวจ Dependency เฉพาะ `_role_row_rules` แต่ไม่ตรวจ `_application_role_rows` และ Fingerprint ไม่มีรายการกฎของบทบาทรายแอป

แก้ไข:

- ตรวจ Dependency ทั้งกฎเดิมและกฎรายแอปก่อนแปลงทับคอลัมน์
- ตรวจทุกกฎที่ใช้ตารางนั้น แม้เป็นบทบาทของแอปอื่นที่เชื่อมตาราง โดยไม่เปิดเผยชื่อบัญชีหรือรายละเอียดสมาชิกในข้อความผิดพลาด
- รวมกฎรายแอปใน Fingerprint เพื่อปฏิเสธ Preview เก่าหลังแก้กฎ
- ยังคัดลอกไปคอลัมน์ใหม่ได้ เพราะไม่เปลี่ยนค่าหรือชนิดของคอลัมน์ที่กฎเดิมใช้อยู่

ก่อนแก้ Test พบว่า Fingerprint ไม่เปลี่ยน ตาม `.test-data/four-fixes-conversion-red.log` หลังแก้ทดสอบสิทธิ์ด้วยบัญชีจริงในฐานข้อมูลจำลอง: แปลงทับไม่ได้ คัดลอกได้ และจำนวนแถวที่บัญชีอ่านได้ยังเท่าเดิม การเพิ่มกฎหลัง Preview ทำให้ Apply ได้ 409

ไฟล์: `lib/column-conversion.ts`, `tests/conversion.test.cjs`, `tests/audit-four-fixes-browser.cjs`

## CONV-002 — แปลงเป็น User ที่ไม่มีจริงหรือไม่มีสิทธิ์เข้าแอป

ระดับ P2

สาเหตุ: เส้นทางแปลงตรวจเพียงรูปแบบเลข ไม่ใช้ตัวตรวจสมาชิกเดียวกับการบันทึกฟอร์ม

แก้ไข:

- แยกตัวตรวจเดิมเป็น `createUserFieldValidator` โดย `assertUserFields` เดิมยังใช้ข้อกำหนดและพฤติกรรมเดิม
- ส่งฐานข้อมูลที่กำลังตรวจอย่างชัดเจน เพื่อให้ Preview ใช้สำเนาทดสอบ ไม่ไปอ่านบัญชีจากฐานข้อมูลอื่น
- ใช้รายชื่อผู้ใช้ชุดเดียวต่อการตรวจหนึ่งงาน ไม่โหลดสมาชิกใหม่ทุกแถว และไม่ Cache ข้ามคำขอ
- ตรวจทั้ง Preview และภายในธุรกรรม Apply
- รวมสถานะผู้ใช้ บทบาท และข้อมูลการเป็นสมาชิก/สิทธิ์ Builder ที่มีผลต่อการเข้าแอปใน Fingerprint สำหรับการแปลงเป็น User โดยไม่อ่านรหัสผ่านมาสร้าง Fingerprint
- รองรับค่าว่างตามเงื่อนไขคอลัมน์ ผู้ใช้ที่เปิดใช้งานและเข้าแอปได้ยังแปลงได้
- ไม่บังคับตรวจสมาชิกซ้ำของช่อง User เก่าที่ไม่ได้เปลี่ยน เมื่อแปลงคอลัมน์อื่น เพื่อรักษาพฤติกรรมการบันทึกเดิม มี Regression Test แยกสำหรับกรณีนี้

ก่อนแก้ Test ยืนยันว่า Preview อนุญาต User ID ที่ไม่มีจริง หลังแก้ทดสอบ ID ไม่มีจริง ผู้ใช้ปิดใช้งาน สมาชิกที่ถูกปฏิเสธ ค่าว่าง ผู้ใช้ปกติ และการถอนสมาชิกหลัง Preview พร้อมตรวจว่าฟอร์มปกติใช้ข้อกำหนดตรงกัน

ไฟล์: `lib/user-fields.ts`, `lib/column-conversion.ts`, `tests/conversion.test.cjs`, `tests/audit-four-fixes-browser.cjs`

## CONV-003 — เปลี่ยน Ref แล้วจำนวนลูกของแม่ใหม่ไม่ผ่านเงื่อนไข

ระดับ P2

สาเหตุ: ตัวแปลงตรวจโครงสร้างสูตรรายการลูก แต่ไม่ได้ประเมินรายการลูกในบริบทของแม่ที่ได้รับผลกระทบหลังเปลี่ยน Ref

แก้ไข:

- รวบรวมรหัสแม่ที่ได้รับผลกระทบจาก Ref ก่อนและหลังแปลง
- ตรวจแม่ในตารางที่กำลังแปลงด้วย หากการเปลี่ยนค่าของแม่อาจกระทบเงื่อนไขลูก
- ใช้ `assertPartValues` ตัวเดียวกับฟอร์มแม่และการเผยแพร่ เพื่อตรวจ Related Required และ Valid_If
- ประเมินด้วยข้อมูลแม่และบริบทตารางที่ถูกต้อง ไม่ใช้ข้อมูลของแถวลูกแทนแม่
- ไม่อ่านแถวของตารางนอกขอบเขตแอป หากตรวจไม่ได้จะปฏิเสธด้วยข้อความทั่วไป
- ตรวจซ้ำภายในธุรกรรม Apply ถ้าไม่ผ่านจะย้อนข้อมูล คอลัมน์ และ Inline View ที่เปลี่ยนไปทั้งหมด

ก่อนแก้ Test ยืนยันว่าแม่ใหม่ที่ต้องการลูกสองรายการแต่มีหนึ่งรายการผ่าน Preview หลังแก้ Preview ระบุปัญหาที่แม่ใหม่ Apply โดยตรงก็ย้อนกลับ และกรณีแม่ใหม่ต้องการหนึ่งรายการสามารถแปลงและบันทึกแม่ตามปกติได้ รหัสลูกและข้อมูลเดิมยังอยู่

ไฟล์: `lib/column-conversion.ts`, `tests/conversion.test.cjs`, `tests/audit-four-fixes-browser.cjs`

## ความเสี่ยงและข้อจำกัดที่เหลือ

- ยังไม่รองรับการแปลงทับคอลัมน์ที่กฎสิทธิ์ใช้อยู่โดยรักษากฎเดิมอัตโนมัติ ต้องแก้กฎอย่างตั้งใจหรือคัดลอกไปคอลัมน์ใหม่
- การเปลี่ยนสิทธิ์เดิมหรือเพิกถอนสิทธิ์ยังล้างหน้าที่ Cache ไว้ตามกลไกความปลอดภัย ไม่ได้รับรองว่าจะรักษา Draft ในเหตุการณ์เหล่านั้น
- มีการตรวจสูตรและรายการลูกเพิ่มในงานแปลงข้อมูล จึงยังขึ้นกับขนาดข้อมูลและความซับซ้อนของสูตร ไม่ได้ทำ Load Test ระดับหลายล้านแถวในรอบนี้
- ทดสอบมือถือด้วยเบราว์เซอร์จำลอง ยังไม่ใช่ iPhone/Safari จริง
- ไม่มีการ Deploy หรือแก้ฐานข้อมูลผู้ใช้จริง

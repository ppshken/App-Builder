# เผยแพร่เงื่อนไขรายการลูกและข้อมูลจากตารางใหม่

## ขอบเขตที่อนุมัติ

รองรับการเผยแพร่เงื่อนไขรายการลูกจากพื้นที่พัฒนา และนำข้อมูลจากตารางที่สร้างใหม่ไปยังเวอร์ชันจริง โดยผู้ใช้ยืนยันให้ตรวจความเกี่ยวข้อง **รายแถว** ไม่ตัดสินทั้งตาราง

ไม่แก้ฐานข้อมูลจริง ไม่เผยแพร่ขึ้นเซิร์ฟเวอร์ และไม่เปลี่ยนเงื่อนไขการบันทึกปกติของระบบ

## เงื่อนไขรายการลูก

- รองรับการเพิ่มหรือปรับ Is a part of การบังคับรายการลูก สูตรตรวจค่า เงื่อนไขแสดง/เพิ่ม และข้อความแจ้งเมื่อไม่ผ่าน
- ตรวจจำนวนลูกและสูตรในบริบทแถวแม่ ด้วยตัวตรวจเดียวกับการบันทึกฟอร์มแม่
- การซ้อมและการตรวจก่อนเผยแพร่ต้องผ่านทั้งข้อมูลเดิมและข้อมูลใหม่ที่จะนำเข้า
- ข้อผิดพลาดระบุชื่อตารางแม่และรายการลูกที่เกี่ยวข้อง โดยไม่บันทึกค่าข้อมูลหรือข้อความส่วนตัวลงผลตรวจ
- ยังรักษาขอบเขตเจ้าของแอปและตารางร่วม หากเงื่อนไขกระทบตารางแม่ของแอปอื่นหรือตารางแม่ที่ใช้ร่วมกันจะไม่เปิดให้เผยแพร่

## การนำข้อมูลใหม่ไปด้วย

1. อ่านเฉพาะคอลัมน์จริงของตารางภายในที่สร้างใหม่ในแอปนี้ ไม่อ่านข้อมูลตารางเดิมมารวมเป็นข้อมูลนำเข้า
2. แถวที่ไม่มีข้อมูลอ้างอิง หรืออ้างอิงกันภายในกลุ่มตารางใหม่ นำไปด้วยได้
3. แถวที่มี Ref ไปยังตารางเดิม หรือข้อมูลผู้ใช้เดิม จะถูกข้าม แม้ชื่อแอปเจ้าของจะตรงกัน
4. แถวใหม่ที่อ้างอิงแถวที่ถูกข้ามจะถูกข้ามต่อเนื่อง รวมถึงความสัมพันธ์หลายชั้นและวงอ้างอิง
5. หาก Ref ไปยังแถวใหม่ที่ไม่พบจริง จะข้ามแถวนั้นและแถวที่พึ่งพา
6. แสดงจำนวนทั้งหมด จำนวนที่จะนำเข้า จำนวนที่ข้าม และเหตุผลแยกตามตารางในหน้าตรวจเผยแพร่
7. รักษา ID และค่าคอลัมน์จริงของแถวที่นำเข้า จึงรักษาความสัมพันธ์ระหว่างตารางใหม่ได้ และลำดับ ID ถัดไปยังทำงานตาม SQLite
8. ใช้ธุรกรรมเดียวกับโครงสร้างและการตั้งค่า หากนำเข้าหรือตรวจอ้างอิงไม่ผ่าน จะย้อนกลับธุรกรรมทั้งหมด
9. ไม่เรียก Action หรือ Automation เพื่อสร้างข้อมูลนำเข้าซ้ำ แต่คงกลไกบันทึกประวัติและติดตามการเปลี่ยนแปลงระดับฐานข้อมูลเดิม

### ตัวอย่าง

ตารางใหม่ `หมวดงาน` มีสองแถว: แถว ก ไม่อ้างอิงตารางเดิม ส่วนแถว ข อ้างอิงรถในเวอร์ชันจริง

- นำแถว ก ไปด้วย
- ข้ามแถว ข
- ตารางใหม่ `หัวข้องาน` ที่อ้างอิงแถว ก นำไปได้ ส่วนที่อ้างอิงแถว ข จะถูกข้ามด้วย
- ไม่เปลี่ยนแถวรถหรือข้อมูลเดิมในเวอร์ชันจริง

## การป้องกันข้อมูลเปลี่ยนหลังตรวจ

- ผูกลายนิ้วมือข้อมูลของตารางใหม่กับแผนซ้อมและรหัสยืนยันเผยแพร่
- การเพิ่ม แก้ หรือลบข้อมูลในตารางใหม่หลังซ้อมทำให้ต้องซ้อมใหม่
- อ่านข้อมูลใหม่อีกครั้งในธุรกรรมก่อนเผยแพร่จริง ไม่รับค่าข้อมูลนำเข้าจากเบราว์เซอร์
- ตรวจข้อมูลจริงล่าสุดในงานแยกก่อนเผยแพร่ และยังตรวจการเปลี่ยนแปลงข้อมูลเดิมก่อนยืนยันธุรกรรม
- เพิ่มรุ่นตัวเผยแพร่เพื่อให้ผลซ้อมจากกลไกเดิมไม่ถูกใช้ยืนยันกลไกใหม่
- คงการสำรองก่อนเผยแพร่และใบรับผลเผยแพร่เดิม การส่งคำขอเดิมซ้ำไม่เพิ่มข้อมูลซ้ำ

## ข้อจำกัด

- ข้อมูลนำเข้าจากตารางใหม่รวมไม่เกิน 100,000 แถว หรือ 32 MB และมีเวลาจำกัดในการตรวจแผน ส่วนข้อมูลจริงยังใช้ขีดจำกัดการตรวจเผยแพร่เดิม
- ยังไม่นำไฟล์ที่อัปโหลดในพื้นที่พัฒนาไปด้วย เพราะต้องมีแผนย้ายไฟล์แยก แถวที่มีไฟล์ลักษณะนี้จะแสดงเหตุผลที่ข้าม รูปภาพจากลิงก์ HTTP/HTTPS ไม่อยู่ในข้อจำกัดนี้
- ถ้าตั้งบังคับรายการลูกให้ตารางแม่เดิม แต่ข้อมูลใหม่ที่เป็นลูกอ้างอิงแม่เดิมถูกข้าม การซ้อมอาจไม่ผ่านตามเงื่อนไขนั้น ต้องจัดข้อมูลหรือเงื่อนไขให้สอดคล้องกัน ไม่ข้ามการตรวจให้เผยแพร่ผ่าน
- ยังไม่รองรับการเผยแพร่การลบ เปลี่ยนชื่อ หรือแปลงชนิดคอลัมน์ตามขอบเขตเดิม

## ไฟล์หลัก

- `lib/release-seed-data.ts`: คัดแถว ตรวจความสัมพันธ์ ลายนิ้วมือข้อมูล และนำเข้าในธุรกรรม
- `lib/part-validation.ts`: ตัวตรวจรายการลูกร่วมระหว่างฟอร์มและการเผยแพร่
- `lib/release-publication-policy.ts`: ขอบเขตเงื่อนไขรายการลูกที่เผยแพร่ได้
- `lib/release-rehearsal.ts`, `lib/releases.ts`, `lib/release-publication.ts`: ซ้อม ตรวจข้อมูลล่าสุด และเผยแพร่
- `app/components/DevelopmentPublicationPanel.tsx`: สรุปข้อมูลใหม่และเหตุผลการข้าม
- `app/components/ReleaseRehearsalPanel.tsx`: ผลซ้อมและข้อผิดพลาดรายการลูก

## หลักฐานการทดสอบ

- ก่อนแก้ ส่วนเงื่อนไขรายการลูกมีการทดสอบล้มเหลว 2 ข้อ: `.test-data/publication-child-red.log`
- การทดสอบครอบคลุมความสัมพันธ์หลายชั้น วงอ้างอิง การข้ามแถวที่เกี่ยวข้องกับข้อมูลเดิม การคง ID การย้อนธุรกรรม ขีดจำกัดข้อมูล และข้อมูลเปลี่ยนหลังตรวจ
- การทดสอบคอลัมน์ทั่วไปที่มีค่าเริ่มต้นปิดรายการลูกเคยล้มเหลว 1 ข้อ และเพิ่มการป้องกันแล้ว: `.test-data/publication-default-flags-red.log`
- การทดสอบอัตโนมัติทั้งหมด 671 ข้อ: ผ่าน 664 ข้อ ข้าม 7 ข้อที่ต้องใช้สภาพแวดล้อม Linux ไม่มีข้อที่ล้มเหลว: `.test-data/publication-childseed-tests-final.log`
- Build สำหรับใช้งานจริงผ่าน รวมตรวจ TypeScript: `.test-data/publication-childseed-build-verified-final.log`
- ทดสอบครบเส้นทางบน Build สำหรับใช้งานจริงโดยใช้ฐานข้อมูลแยก ผ่านทั้งหมด:
  - เงื่อนไขรายการลูก ข้อมูลใหม่ ความสัมพันธ์ ID เดิม ข้อมูลเปลี่ยนหลังซ้อม คำขอซ้ำ และตารางสรุปในหน้าเว็บ: `.test-data/publication-childseed-childseed-final.log`
  - การเผยแพร่โครงสร้างเดิม สำรองข้อมูล ข้อมูลล่าสุด การย้อนธุรกรรม การเรียกพร้อมกัน ประวัติ และขอบเขตแอป: `.test-data/publication-childseed-publication-final.log`
  - การเพิ่มและแก้สูตร ข้อมูลล่าสุดไม่ผ่าน การย้อนธุรกรรม และข้อมูลมากกว่า 2,000 แถว: `.test-data/publication-childseed-publicationformula-final.log`
  - ซ้อมแบบเดิม ตรวจข้อมูลเดิม ค่าข้อมูลไม่รั่วในรายงาน แผนหมดอายุ สิทธิ์ และล้างสำเนาทดลอง: `.test-data/publication-childseed-rehearsal-verified.log`
- การบันทึกฟอร์มแม่–ลูกเดิมผ่านบนเซิร์ฟเวอร์ทดสอบ รวมการย้อนธุรกรรม บังคับจำนวนลูก และฟอร์มมือถือ: `.test-data/publication-childseed-partof-final.log`
- ปรับ Test เก่าของการซ้อมให้ตรงกับขอบเขตแยกแอปที่ระบบใช้อยู่ก่อนงานนี้: การเปลี่ยนแอปอื่นที่ไม่เกี่ยวข้องไม่ต้องบล็อกฉบับร่าง และปรับจำนวนข้อมูลตารางใหม่ตามข้อกำหนดที่อนุมัติให้คัดแถวอิสระไปด้วย ไม่ได้เปลี่ยนนโยบายการแยกแอปเพื่อให้ Test ผ่าน

ยังไม่ได้ทดสอบบน VPS หรือเครื่อง iPhone จริง และไม่ได้ Deploy หรือเปลี่ยนฐานข้อมูลจริง

# Conversion blocked on an empty table — 2026-11-02

Status: Passed in isolated regression and HTTP/browser tests.

## Confirmed cause

lib/column-conversion.ts prepare() queried sqlite_master with tbl_name = target OR type = view. It rejected every SQL view in the database during replace conversion. Builder itself creates cached/live external API datasets as SQL views in lib/external-storage.ts. Consequently, an unrelated system-owned API view blocked conversion of a newly created empty internal table. Row count is not relevant to this structural check.

Reproduction: initialize an in-memory Builder database, create an empty internal table and a canonical cached API view generated by createExternalReadView, then preview Text -> EnumList. Before the fix this throws the reported SQL View/Trigger/index error. Evidence: .test-data/conversion-managed-view-before.log. The initial negative test incorrectly expected a returned report instead of the existing thrown-error contract; corrected the test to assert throws without changing that contract.

## Minimal fix

Recognize only canonical Builder-owned external-source views: resolve matching external metadata, generate expected SQL in an isolated in-memory SQLite connection using the existing createExternalReadView helper, compare exact SQLite-stored SQL, and close the temporary connection in finally. No source data or live SQL object is altered. Names alone never grant trust. Custom views, altered managed views, custom triggers and indexes remain blocked. This does not add general arbitrary SQL-view migration support.

Files: lib/column-conversion.ts; tests/conversion.test.cjs; tests/conversion-browser.cjs. Previously pending app-scope and Next upgrade changes are preserved.

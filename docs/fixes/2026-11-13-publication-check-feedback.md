# ปุ่มตรวจพร้อมเผยแพร่ไม่มีสถานะตอบกลับที่ชัดเจน

วันที่: 13 พฤศจิกายน 2569

## สาเหตุ

ปุ่มเรียก API ตรวจความพร้อมได้ แต่ไม่มีสถานะกำลังตรวจ และไม่ได้ป้องกันกดซ้ำระหว่างคำขอ เมื่อผลที่ได้ยังเป็นเงื่อนไขบล็อกชุดเดิม หน้าจอจึงดูเหมือนไม่เกิดอะไรขึ้น การซ้อมผ่านไม่ได้หมายความว่าเงื่อนไขเผยแพร่ทั้งหมดผ่านแล้ว

## สิ่งที่แก้

- เพิ่ม spinner และข้อความกำลังตรวจ พร้อมปิดปุ่มตรวจและปุ่มเผยแพร่ระหว่างรอ
- แสดงสรุปว่าเผยแพร่ยังไม่ได้และจำนวนเงื่อนไขที่ต้องจัดการ เหนือรายละเอียดเหตุผลเดิม
- ตรวจใหม่โดยไม่ใช้แคช คำขอใหม่ยกเลิกคำขอก่อนหน้า และไม่ให้ผลเก่าทับผลใหม่
- หากเครือข่าย/เซิร์ฟเวอร์ผิดพลาด ล้างผลพร้อมเผยแพร่เก่าและเปิดให้ลองตรวจอีกครั้ง
- จำกัดเวลาคำขอ 20 วินาที พร้อมข้อความเมื่อหมดเวลา และยกเลิกคำขอเมื่อออกจากหน้า
- คงข้อความยืนยันและการยอมรับเดิมเมื่อรหัสแผนไม่เปลี่ยน ไม่เปลี่ยนสิทธิ์หรือปลดบล็อกฝั่งเซิร์ฟเวอร์

ไฟล์หลัก: `app/components/DevelopmentPublicationPanel.tsx`

## หลักฐานทดสอบ

ชุดทดสอบใหม่ `tests/publication-check-feedback-browser.cjs` ทำซ้ำกับ Build ก่อนแก้แล้วล้มเหลว เพราะปุ่มยังเปิดให้กดระหว่างรอ หลักฐาน `.test-data/publication-feedback-red.log`

หลังแก้ Build ผ่าน และหน่วยทดสอบผ่าน 591 ข้อ ล้มเหลว 0 ข้อ ข้าม 7 ข้อสำหรับ POSIX หลักฐาน `.test-data/publication-feedback-build.log` และ `.test-data/publication-feedback-unit.log`

ชุดเบราว์เซอร์บน Production Build ผ่านกรณีโหลดช้า ผลบล็อกเดิม ผลที่ผ่าน เซิร์ฟเวอร์ตอบล้มเหลว ล้างสถานะพร้อมเผยแพร่เก่า และลองใหม่ หลักฐาน `.test-data/publication-feedback-browser.log` ชุดนี้จำลองคำตอบของ API ตรวจความพร้อมเฉพาะในเบราว์เซอร์ทดสอบ โดยใช้ Login และพื้นที่พัฒนาในฐานจำลองจริง ไม่เรียกเผยแพร่กับข้อมูลจริง

ทดสอบการเผยแพร่จริงในฐานจำลองแยกอีกชุด หลักฐาน `.test-data/publication-feedback-regression.log`

## ข้อจำกัด

การแก้ครั้งนี้ทำให้เห็นผลการตรวจชัดเจน ไม่ได้แก้เงื่อนไขที่บล็อกอยู่ บทบาทที่เปิดสิทธิ์อัตโนมัติยังคงถูกบล็อกตามนโยบายเดิม ไม่มีการปิดสิทธิ์ให้ผู้ใช้เองหรือเผยแพร่โดยอัตโนมัติ และไม่ได้ Deploy

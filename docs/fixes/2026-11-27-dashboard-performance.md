# ผลตรวจประสิทธิภาพหน้ารายการและแดชบอร์ด

ทดสอบบนเครื่องพัฒนา ด้วยฐานข้อมูลจำลองแยกจากข้อมูลใช้งานจริง

## ผลที่วัดได้

- ชุดทดสอบ performance ผ่านบนข้อมูล 100,000 แถว
- อ่านหน้าแรก 25 แถว พร้อมจำนวนรวม ใช้ 56 มิลลิวินาทีจากฝั่งไคลเอนต์
- อ่านรายการแบบจำกัด 500 แถว ใช้ 45 มิลลิวินาทีจากฝั่งไคลเอนต์
- พิมพ์คำค้นต่อเนื่องเกิดคำขอค้นหา 1 ครั้ง และล้างคำค้นแล้วคืนรายการ 25 แถวได้
- ชุดทดสอบ dashboardviewport ผ่านเรื่องการปรับขนาด เดสก์ท็อป แท็บเล็ต มือถือ และแท็บ

ตัวเลขเป็นการวัดครั้งเดียวในสภาพแวดล้อมพัฒนา ไม่ใช่ค่าเฉลี่ยหรือผลทดสอบบนเซิร์ฟเวอร์จริง

## การแก้ไข

- รวมการหน่วงคำค้นไว้ที่ Dashboard 250 มิลลิวินาที และเอาการหน่วงซ้ำของช่อง Table/List ภายในออก
- กราฟ แผนที่ และปฏิทินคงเนื้อหาเดิมระหว่างโหลดใหม่ เมื่อคำขอล้มเหลวยังคงล้างข้อมูลตามพฤติกรรมเดิม
- จำผลกรองของกราฟ แผนที่ และปฏิทินตามข้อมูลและคำค้น ลดการกรองซ้ำขณะ render จากเหตุอื่น
- ปรับ fixture ชุดทดสอบ performance ให้สร้าง View แบบรายการเองตามค่าเริ่มต้นระบบปัจจุบัน

## สิ่งที่ยังไม่ยืนยัน

- dashboardsearch ติดข้อคาดหวัง breadcrumb จึงยังไม่ผ่านครบเส้นทาง
- specialviews ติด selector ปุ่มกลับ หลังแก้ selector ปุ่มเปิดรายละเอียดแผนที่แล้ว
- ยังไม่ได้วัดจำนวนการโหลดและการกระพริบระหว่าง realtime ด้วยการทดสอบเฉพาะ
- ยังไม่ได้วัดสูตรข้ามตาราง รูปภาพจำนวนมาก หรือข้อมูลและอุปกรณ์ของผู้ใช้งานจริง
- ยังไม่ได้เผยแพร่ขึ้นเซิร์ฟเวอร์

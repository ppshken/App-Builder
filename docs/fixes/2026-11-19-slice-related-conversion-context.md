# แก้บริบท Related ในการตรวจ Slice และ Action ก่อนแปลงข้อมูล

## อาการและสาเหตุที่ยืนยัน

สูตร Slice ที่ใช้ `[Related_inspection][id]` ถูกแจ้งว่า Ref ไปตารางแม่หลายช่องระหว่างตรวจการแปลงข้อมูล แม้ช่อง Ref แต่ละช่องจะเชื่อมคนละตาราง

ตัวตรวจใน `lib/column-conversion.ts` เรียกตัวประเมินสูตร Slice และ Action โดยส่งข้อมูลแถวและ Ref แต่ไม่ได้ส่ง `tableName` ของเจ้าของสูตร ตัวอ่าน Related จึงไม่สามารถจำกัด Ref ตามตารางแม่ได้ ต่างจากการคำนวณคอลัมน์ที่ส่งบริบทตารางอยู่แล้ว

ข้อผิดพลาดนี้ไม่ใช่หลักฐานว่าข้อมูลที่กำลังแปลงผิด และการเปลี่ยน Slice เป็น TRUE เพียงทำให้ข้ามการประเมิน Related เท่านั้น

## การแก้ไข

เพิ่ม `tableName: item.table_name` ในบริบทที่ใช้ตรวจสูตร Slice และ Action เท่านั้น ไม่ข้ามการตรวจความปลอดภัย ไม่เปลี่ยนสูตรที่บันทึก ไม่เปลี่ยนข้อมูลจริง และไม่แก้ตัวประเมินสูตรส่วนกลาง

- เมื่อ Ref ใน inspection เชื่อมรถบัสและพนักงานขับรถคนละตาราง ระบบเลือกเฉพาะ Ref ที่ชี้ตารางเจ้าของ Slice
- หากมี Ref มากกว่าหนึ่งช่องชี้ตารางแม่เดียวกันจริง ยังต้องใช้ `[Related_inspection:ชื่อคอลัมน์Ref][id]`
- รองรับสูตร SELECT, ORDERBY, INDEX และ ISNOTBLANK ตามตัวอย่างผู้ใช้

## หลักฐานทดสอบ

- ก่อนแก้: Regression Test ไม่ผ่านหนึ่งข้อ ทั้ง Slice และ Action แจ้ง Ref หลายช่อง ตาม `.test-data/slice-conversion-context-red.log`
- หลังแก้: ชุดทดสอบทั้งหมดผ่าน 678 ข้อ ข้าม 7 ข้อที่ต้องใช้ Linux ไม่มีข้อที่ล้มเหลว ตาม `.test-data/slice-conversion-context-tests.log`
- ชุดเฉพาะการแปลง Related และ ORDERBY ผ่าน 44 ข้อ ตาม `.test-data/slice-conversion-context-targeted.log`
- Test ตรวจทั้งสูตรระบุ Ref และไม่ระบุ Ref เมื่อระบุตารางแม่ได้ชัดเจน พร้อมเรียกแปลงจริงในฐานข้อมูลจำลอง
- Test ยืนยันว่าสูตรกำกวมจริงจาก Ref สองช่องไปตารางแม่เดียวกันยังถูกปฏิเสธ
- ทดสอบหน้าเว็บและ API การแปลงด้วยฐานข้อมูลแยกผ่าน ตาม `.test-data/slice-conversion-context-api.log` ครอบคลุม Preview ไม่เปลี่ยนข้อมูล การยืนยัน สำรองข้อมูล Ref/รหัสเดิม ผลตรวจหมดอายุ การคัดลอกคอลัมน์ และข้อมูลไม่ถูกต้อง ชุดนี้รันด้วยเซิร์ฟเวอร์โหมดพัฒนา ไม่ใช่ Production Build

## ขอบเขตและข้อจำกัด

ยังตรวจ Slice และ Action ตามขอบเขตเดิม ไม่ได้เปลี่ยนให้ละเว้นปัญหาเดิมที่ไม่เกี่ยวข้อง ไม่ได้เปิดหรือแก้ฐานข้อมูล Production และยังไม่ได้ตรวจสูตรที่บันทึกจริงในแอปของผู้ใช้ งานนี้ไม่รวม Deploy

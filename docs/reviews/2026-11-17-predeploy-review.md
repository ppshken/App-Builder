# ตรวจงานวันที่ 17 พฤศจิกายน 2569 ก่อน Deploy

## ข้อสรุป

ฟีเจอร์ที่แก้วันนี้ผ่านการทดสอบบน Build สำหรับใช้งานจริง พบและแก้บัคฟอร์มรายการลูกค้างหลังออกจากหน้ารายละเอียดหนึ่งจุด พร้อมทดสอบป้องกันซ้ำ

**ยังไม่สรุปว่าผ่านครบทุกสภาพแวดล้อม** เพราะมีคำเตือนความปลอดภัยของ Next.js เดิมหนึ่งรายการ และเครื่องนี้ยังรัน Docker Engine ไม่ได้ จึงยังไม่ทดสอบสร้างและรัน Container จริง

การตรวจใช้ฐานข้อมูลจำลองแยกทั้งหมด ไม่ Deploy ไม่เปลี่ยนฐานข้อมูลจริง ไม่แก้ Credentials หรือ Docker Volumes ไม่อัปเกรด Dependency ระหว่างตรวจ

## บัคที่ยืนยันและแก้ระหว่างตรวจ

### PRE-DEPLOY-001 — คำขอเพิ่มรายการลูกตอบกลับหลังออกจากหน้าเดิม

- ระดับ: P2 · ยืนยันด้วยการจำลองเครือข่ายช้า
- จุดเกิด: `app/components/RuntimeTable.tsx` ฟังก์ชัน `addRelated`
- สาเหตุ: การตรวจเงื่อนไขก่อนเปิดฟอร์มเป็นคำขอแบบ asynchronous แต่เส้นทางเพิ่มรายการลูกยังไม่มีการยกเลิกคำขอหรือเช็กว่าผู้ใช้อยู่ในรายละเอียดเดิมหรือไม่
- วิธีทำซ้ำ: เปิดรายละเอียดแม่ → หน่วงคำขอ `create_check=1` ของตารางลูก → กดเพิ่ม → กลับหน้ารายการ → ปล่อยคำขอที่หน่วง
- คาดหวัง: ไม่สร้างฟอร์มลูกหลังออกจากรายละเอียดแล้ว
- ก่อนแก้: พบ `.runtime-child-screen` ค้าง 1 หน้า ขณะที่ URL กลับมาเป็นหน้ารายการแล้ว
- หลักฐาน: `.test-data/predeploy-2026-11-17-inline-race.log`
- แก้ไข: เพิ่ม AbortController เฉพาะคำขอรายการลูก ยกเลิกเมื่อเปลี่ยนแอป พื้นที่ทำงาน ตาราง View แถวแม่ หรือสถานะหน้าที่กำลังแสดง และตรวจบริบทซ้ำก่อนเปิดฟอร์มหรือแจ้งข้อผิดพลาด
- หลังแก้: ไม่พบฟอร์มค้าง และกลับเข้าไปเพิ่มรายการลูกตามปกติได้

- ไม่เปลี่ยนสูตร สิทธิ์ วิธีบันทึก หรือข้อมูลธุรกิจ

### การย้ายโครงสร้าง

จำลองฐานข้อมูลก่อนมี `create_if`, `create_error`, `request_json`, `duration_ms` แล้วเริ่มระบบด้วยโครงสร้างใหม่ ตรวจว่าช่องใหม่มีค่าเริ่มต้นที่ถูกต้อง แถวธุรกิจเดิมคงเดิม และเริ่มระบบซ้ำได้

ผล `integrity_check=ok`, `foreign_key_check=0` ไม่ได้ทดสอบ Migration บนสำเนาฐานข้อมูลจริงของ VPS

## ข้อควรจัดการก่อน Deploy

### SEC-DEPLOY-001 — Dependency มีประกาศความปลอดภัยเดิม

- `npm audit --omit=dev` พบ Next.js 16.4.3 ระดับปานกลาง 1 รายการ ไม่พบระดับสูงหรือวิกฤตในผลตรวจนี้
- GHSA-mfr8-8qww-v76h / CVE-2026-119790 เป็นกรณีข้อมูล Cache รั่วข้าม root params เมื่อใช้ฟังก์ชัน `'use cache'` ผ่าน `unstable_cache()` ในรูปแบบที่ประกาศระบุ
- ค้นใน `app`, `lib`, `next.config.mjs` ยังไม่พบ `unstable_cache`, `'use cache'`, `cacheComponents` หรือ `rootParams` จึง **ยังไม่ยืนยันว่าแอปนี้ถูกโจมตีผ่านช่องโหว่นี้ได้** แต่เวอร์ชัน Dependency อยู่ในช่วงที่ได้รับผลกระทบ
- ประกาศระบุรุ่นแก้อย่างน้อย 16.4.5 และผล npm audit แนะนำ 16.4.6
- แนะนำอัปเดตรุ่น Patch และทดสอบก่อนขึ้นจริง ยังไม่ได้เปลี่ยน package หรือ lockfile ในรอบตรวจนี้
- หลักฐาน: `.test-data/predeploy-2026-11-17-audit.json`
- แหล่งข้อมูลตรวจวันที่ 17 พฤศจิกายน 2569: [ประกาศ GitHub Advisory](https://github.com/advisories/GHSA-mfr8-8qww-v76h) เผยแพร่ 3 พฤศจิกายน และปรับปรุง 16 พฤศจิกายน 2569

### สภาพแวดล้อม Container — ยังไม่ได้ทดสอบจริง

เครื่องมี Docker CLI แต่เชื่อมต่อ Docker Engine ไม่ได้ จึงไม่สรุปว่า Image Build หรือการรันบน Linux ผ่าน

ตรวจไฟล์ Dockerfile แล้วว่ารวม `scripts/raw-data-worker.cjs` ซึ่งฟีเจอร์ส่งออกใหม่ต้องใช้ และตรวจ Compose ด้วยไฟล์ค่าตัวอย่างผ่าน ยังต้องตรวจ Container/Healthcheck/การส่งออกในสภาพแวดล้อมทดสอบ Linux ก่อนใช้งานจริง

### ไฟล์ใหม่ยังไม่ถูกติดตามใน Git

มีไฟล์ Source และ Worker ใหม่ที่ยังเป็น `untracked` ต้องรวมในชุดที่จะส่งขึ้นเซิร์ฟเวอร์ด้วย โดยเฉพาะ:

- `scripts/raw-data-worker.cjs`
- `lib/raw-data-jobs.ts`, `lib/raw-query.ts`
- `lib/table-create-guard.ts`, `lib/create-preflight.ts`, `lib/slice-preview.ts`
- `app/api/slices/preview/route.ts`, `app/api/tables/[name]/raw/jobs/route.ts`
- Component และ CSS ใหม่ของ Slices, ตัวช่วย Ref, เครื่องมือข้อมูลจริง และกลุ่มตารางตามแอป

ไม่ได้ Stage หรือ Commit ให้ระหว่างการตรวจ หาก Deploy ด้วย Git ต้องรวมไฟล์ใหม่เหล่านี้ก่อน มิฉะนั้นเซิร์ฟเวอร์อาจขาดไฟล์ที่ Source อ้างถึง

## ข้อจำกัดของผลตรวจ

- ไม่ได้ทดสอบบน iPhone จริง ใช้เบราว์เซอร์จำลองขนาดจอ
- ไม่ได้ทดสอบข้อมูลจริง สูตรเฉพาะแอป และปริมาณงานจริงทุกกรณี

- การข้ามข้อทดสอบ 7 ข้อในชุดพื้นฐานไม่ถูกนับว่าผ่าน

# การปรับประสิทธิภาพ

- รอหลังพิมพ์คำค้นประมาณ 200 มิลลิวินาที แล้วส่งคำขอเดียว ลดการอ่านข้อมูลระหว่างพิมพ์
- โหลดค่าเริ่มต้น สูตร และตัวเลือก Ref ของฟอร์มพร้อมกัน
- ตัวเลือก Ref ที่เรียงตาม id และไม่มีตัวกรอง/กฎสิทธิ์ระดับแถว อ่านและคำนวณเฉพาะ 500 แถวที่จะส่ง แทนอ่านทั้งตาราง กรณีมีเงื่อนไขยังตรวจครบก่อนจำกัดผล
- อ่านโครงสร้างตารางซ้ำครั้งเดียวภายในชุดการคำนวณสูตรของคำขอเดียว ไม่มีการแชร์ข้อมูลบัญชีระหว่างผู้ใช้
- ค้นหาตาราง Related เฉพาะตารางที่อ้างอิงจริง
- ใช้ตัวจัดรูปแบบวันที่ร่วมกัน แต่คำนวณ TODAY/NOW ใหม่ตามเวลาของแต่ละการประเมิน

## ผลทดสอบบนเครื่องพัฒนา

ข้อมูลจำลอง 100,000 แถว: อ่านหน้า 25 แถวประมาณ 22 ms; ตัวเลือก Ref 500 แถวประมาณ 20 ms หลังเตรียม API แล้ว ตัวเลขรวมคำขอ localhost บน dev server ไม่รวมการเปิดหน้าและการ compile ครั้งแรก

สูตร CONCATENATE ที่ใช้ TODAY/NOW รวม 3 ครั้ง ประเมิน 5,000 รอบ ค่ากลางจาก 3 ชุด: ก่อนปรับ 1,084 ms หลังปรับ 35 ms เฉพาะการคำนวณสูตรนี้ ไม่ใช่ความเร็วรวมทั้งแอป

ทดสอบข้อมูลจำลองแยกจาก data.db ด้วยคำสั่ง:

~~~powershell
npm test
node scripts/integration.cjs performance
node scripts/integration.cjs cache
node scripts/integration.cjs permissions
~~~

ความเร็วจริงขึ้นกับคอลัมน์ สูตร กฎสิทธิ์ ตัวกรอง และเครื่องที่ใช้งาน การค้นหาชื่อ Ref, เรียงช่องคำนวณ, Slice และกฎแถวบางรูปแบบยังต้องอ่านข้อมูลมากกว่าหน้าปัจจุบัน สูตรตัวเลือกข้ามตารางยังจำกัดที่ 10,000 แถวตามเดิม ผลแสนแถวข้างต้นเป็นตารางทั่วไปที่แบ่งหน้าด้วย SQL ไม่ครอบคลุมทุกกรณีดังกล่าว

ใช้งานประจำวันด้วย npm run build ตามด้วย npm start จะไม่เสียเวลา compile หน้าระหว่างใช้งานเหมือน npm run dev

# ตารางสรุปจุดที่ข้อมูลไม่ผ่านในผลซ้อมอัปเดต

วันที่: 13 พฤศจิกายน 2569

## การแสดงผล

เพิ่มตารางใต้ผลตรวจสูตรและเงื่อนไขข้อมูล แสดงชื่อตาราง/คอลัมน์ทั้งชื่อที่แสดงและชื่อในระบบ ประเภทปัญหา และจำนวนแถว เพื่อให้ผู้พัฒนารู้ว่าควรเปิดตรวจคอลัมน์ใด

ประเภทปัญหาประกอบด้วยคำนวณหรือประเมินสูตรไม่ผ่าน ไม่ผ่านเงื่อนไขบังคับกรอก ไม่ผ่านเงื่อนไขตรวจค่า และไม่สามารถระบุคอลัมน์ได้ ไม่มีการส่งค่าข้อมูล รหัสแถว ข้อความ Error จริง หรือข้อความ Invalid value error ที่ผู้พัฒนากำหนดเข้าไปในรายงาน

นับเฉพาะจุดแรกที่ไม่ผ่านของแต่ละแถวให้ตรงกับการตัดสินเดิม ผลรวมจำนวนแถวของกลุ่มที่แสดงบวกจำนวนแถวที่ไม่ได้แสดงตรงกับจำนวนแถวไม่ผ่าน เมื่อแก้จุดแรกแล้วซ้อมใหม่อาจพบปัญหาจุดถัดไปในแถวเดิม

จำกัดรายงานสูงสุด 200 กลุ่ม หากเกินจะแสดงจำนวนแถวในกลุ่มที่ยังไม่ได้แสดง เก็บเพียงตัวนับ ไม่เก็บรายการแถวทั้งหมดในหน่วยความจำ

## ความเข้ากันได้และขอบเขต

- ใช้ตัวคำนวณและเงื่อนไขเดิม ไม่ปลดบล็อกการเผยแพร่หรือแก้ข้อมูล/สิทธิ์อัตโนมัติ
- เปิดเก็บรายละเอียดเฉพาะงานซ้อม ไม่เพิ่มงานรวบรวมรายละเอียดในธุรกรรมเผยแพร่จริง
- เมื่อการคำนวณแบบเข้มงวดโยนข้อผิดพลาดก่อนคืนชื่อคอลัมน์ จะวิเคราะห์แถวนั้นซ้ำแบบทนข้อผิดพลาดเพื่อระบุตำแหน่งเท่านั้น ผลแบบทนข้อผิดพลาดไม่เคยทำให้แถวที่ล้มเหลวเปลี่ยนเป็นผ่าน
- ผลซ้อมเก่าไม่มีรายละเอียดเพิ่มย้อนหลัง UI จะแจ้งให้กดซ้อมใหม่ ไม่เดาจำนวนปัญหาหรือแก้ประวัติเดิม
- ต้องใช้ worker ที่ Build ใหม่ บน localhost ให้หยุดแล้วเปิด `npm run dev` ใหม่ก่อนกดซ้อม บนเซิร์ฟเวอร์ต้องใช้ image ที่ Build จากโค้ดล่าสุด

## จุดเชื่อม

| ไฟล์ | สิ่งที่เปลี่ยน |
|---|---|
| `lib/release-rehearsal.ts` | เก็บรายละเอียดแบบรวมกลุ่มตามตาราง คอลัมน์ และประเภทปัญหา |
| `lib/releases.ts` | บันทึก `rowIssues` และ `omittedIssueRows` ในผลซ้อม |
| `app/components/ReleaseRehearsalPanel.tsx` | ตารางสรุปและคำอธิบายสำหรับผลเก่า |
| `tests/release-rehearsal.test.cjs` | ตรวจประเภทปัญหา จำนวน และการไม่ส่งค่าข้อมูล/ข้อความส่วนตัว |
| `tests/release-rehearsal-browser.cjs` | ตรวจผล API และตารางบนหน้าจอมือถือ |

ข้อมูลใหม่อยู่ในผลซ้อมเดิมและผ่านการตรวจเจ้าของ/แอปของ API เดิม ไม่เพิ่ม endpoint อ่านข้อมูลผู้ใช้

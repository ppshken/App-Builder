# เวอร์ชั่นแอป ระยะ 2 — พื้นที่พัฒนาโครงสร้างแยก

วันที่: 12 พฤศจิกายน 2569

อัปเดต 13 พฤศจิกายน 2569: เพิ่มทางเผยแพร่โครงสร้างที่รองรับในระยะ 4 แล้ว ข้อจำกัดของรุ่นเดิมในเอกสารนี้ยังเป็นประวัติและขอบเขตทางเดิม ดู [การเผยแพร่โครงสร้างเพิ่ม](2026-11-13-additive-publication.md)

## สิ่งที่ใช้งานได้

เพิ่มตัวเลือกพื้นที่พัฒนาโครงสร้างในหน้าสร้างฉบับร่าง โดยคงฉบับร่างทั่วไปไว้ตามเดิม พื้นที่ชนิดใหม่ใช้ SQLite สำเนาแยกและผูกกับแอปต้นทางกับผู้สร้างอย่างชัดเจน

นักพัฒนาสามารถทดลองเพิ่มตาราง เพิ่ม/แก้ไข/เปลี่ยนชื่อ/ลบคอลัมน์ แปลงชนิดข้อมูล และทดลองแถวข้อมูลภายในสำเนาได้ โดยใช้ตัวจัดการตารางและ Action เดิม ไม่สร้างเครื่องมือเขียนข้อมูลหรือแปลงชนิดซ้ำอีกชุด

ยังไม่เปิดให้เผยแพร่พื้นที่ชนิดนี้ แม้แก้เพียงการตั้งค่า เพราะต้องพัฒนาการซ้อมและตัวนำแผนไปใช้ในระยะถัดไปก่อน ระบบปฏิเสธทั้งที่ปุ่มและ Backend

## วิธีใช้

1. ไปที่เวอร์ชั่นแอป ตั้งชื่อฉบับร่าง
2. ติ๊กพื้นที่พัฒนาโครงสร้าง · แยกข้อมูลจากแอปจริง
3. กดสร้างฉบับร่างจากเวอร์ชันจริง แล้วเปิดฉบับร่าง
4. ทดลองใน Data, View และเครื่องมือต่าง ๆ ที่รองรับ ป้ายบน Header ระบุพื้นที่พัฒนา กดเพื่อดูชื่อเต็ม จัดการเวอร์ชั่น หรือกลับเวอร์ชันจริง
5. ใช้ปุ่มตรวจและเผยแพร่เพื่ออ่านผลเปรียบเทียบเท่านั้น ปุ่มเผยแพร่ยังถูกปิดสำหรับพื้นที่พัฒนาโครงสร้าง
6. กลับเวอร์ชันจริงจะนำไปหน้า Data ของแอปเดิม ไม่ค้างที่ URL ตารางทดลองซึ่งไม่มีอยู่ในแอปจริง

ผู้ใช้คนอื่นยังทำงานกับแอปจริงตามเดิม พื้นที่พัฒนาผูกกับ Cookie ของผู้พัฒนา ไม่ได้สลับระบบทั้งแอปให้ผู้ใช้ทุกคน หน้า PWA ที่ระบุแอปอย่างชัดเจนยังใช้เส้นทางจริงตามกติกาเดิม

ฉบับร่างในเบราว์เซอร์เดียวกันยังใช้ Cookie ร่วมกันตามระบบเดิม ควรบันทึกงานก่อนสลับพื้นที่ คำขอที่ถือรหัสพื้นที่หรือรหัสแอปเก่าจะถูกปฏิเสธเพื่อไม่ให้เขียนผิดพื้นที่

## ขอบเขตการทดลอง

| การทำงาน | พฤติกรรมในพื้นที่พัฒนา |
|---|---|
| เพิ่มตารางของแอปเอง | สร้างในสำเนาและใช้ได้ในการโหลดหน้าถัดไป |
| เพิ่ม/แก้ไข/เปลี่ยนชื่อ/ลบคอลัมน์ | ใช้เงื่อนไขและตัวตรวจเดิม เปลี่ยนเฉพาะสำเนา |
| แปลงชนิดข้อมูล | ใช้ตัวตรวจและแปลงเดิม Token ผูกกับแอป ผู้กระทำ และไฟล์พื้นที่ ไม่สร้างสำรองของฐานข้อมูลจริง |
| เพิ่ม/แก้ไข/ลบและเคลียร์แถวทดลอง | ทำในสำเนา เงื่อนไข Ref และการตรวจข้อมูลเดิมยังทำงาน |
| Action เปลี่ยน/เพิ่ม/คัดลอก/ลบข้อมูล และชุด Action ภายใน | ทดลองกับแถวในพื้นที่ได้ โดยคง Engine เดิม |
| Action เปิด URL ส่งอีเมล หรือเรียก Automation | ไม่ให้ Execute จริงในพื้นที่พัฒนา ใช้การจำลองส่วนที่รองรับแทน |
| Automation อัตโนมัติจากการบันทึก | ไม่ทำงานและไม่สร้างคิวจากการทดลองบันทึก |
| สั่ง Run/Retry/Cancel งานจริง | ปฏิเสธในพื้นที่พัฒนา |
| API ภายนอกและ External Worker | ปิดการเรียกเครือข่ายจริงจากบริบทพื้นที่พัฒนา รวมการอ่าน Live API |
| Push | ไม่ส่งจริงและไม่ลงทะเบียนอุปกรณ์จากพื้นที่พัฒนา |
| ไฟล์/รูปใหม่และการสร้าง PDF จริง | ยังไม่เปิด อัปโหลดหรือเขียนไฟล์บน Server ไม่ได้ แต่ดูตัวอย่างแม่แบบ HTML และข้อมูลที่มีอยู่ได้ตามสิทธิ์ |
| ตารางร่วมที่คัดลอกมา | อ่านตามเพดานสิทธิ์ปัจจุบัน ทดลองเขียนหรือเปลี่ยนโครงสร้างผ่านแอปผู้เชื่อมไม่ได้ |
| จัดการสมาชิก สิทธิ์ส่วนกลาง บัญชี สำรอง หรือเชื่อม Data Source | ให้กลับเวอร์ชันจริงก่อน ไม่ใช้พื้นที่พัฒนาเป็นเครื่องมือเปลี่ยนส่วนกลาง |
| นำเข้า Excel หรือคำสั่งเขียนที่ยังไม่อยู่ในรายการอนุญาต | ปิดไว้ก่อนในรุ่นนี้ ไม่เดาว่าทุก Endpoint ปลอดภัยเมื่อใช้ฐานข้อมูลสำเนา |
| เผยแพร่โครงสร้างหรือการตั้งค่าจากพื้นที่ชนิดใหม่ | ยังไม่เปิดจนกว่าจะมีระยะซ้อมและนำแผนไปใช้ |

คำว่าปิดเครือข่ายหมายถึงการส่งงานจากฝั่ง Server ภายใต้บริบทพื้นที่พัฒนา ไม่ได้ปิดการโหลดแผนที่หรือรูป URL ภายนอกของเบราว์เซอร์ผู้ใช้ทั้งหมด

## โครงสร้างพื้นที่และอายุ

- Manifest เก็บ `workspace_mode=development`, `format_version=2`, `source_app_id` และ `expires_at`
- ฐานข้อมูลเก็บที่ `.app-releases/<รหัสพื้นที่>/workspace.db` สำหรับแอปหลัก หรือ `.app-releases/<รหัสแอป>/<รหัสพื้นที่>/workspace.db` สำหรับแอปอื่น
- แต่ละพื้นที่มีโฟลเดอร์ของตนเอง และพยายามใช้สิทธิ์ไฟล์แบบส่วนตัวเมื่อระบบปฏิบัติการรองรับ
- เมื่อเปิดพื้นที่ ต้องตรวจผู้สร้าง สถานะ อายุ แอปต้นทาง และรหัสที่ฝังอยู่ใน SQLite ให้ตรงกัน
- ใช้ได้ 14 วัน มีเพดานจำนวนฉบับร่างเดิม เมื่อหมดอายุจะเปิดไม่ได้ แต่ยังเก็บรายการเพื่อให้ผู้สร้างจัดการได้
- การเก็บฉบับร่างปิดการใช้งานพื้นที่นั้น ไม่ลบสำเนาบนดิสก์โดยอัตโนมัติ ยังต้องพัฒนาการจัดการอายุไฟล์และปุ่มลบพื้นที่พร้อมแสดงขนาดในอนาคต
- หากสร้างพื้นที่ไม่สำเร็จ จะพยายามล้างเฉพาะโฟลเดอร์ UUID ที่เพิ่งสร้างในคำขอนั้น ตรวจตำแหน่งที่ resolve แล้วก่อนลบ ไม่ลบฐานข้อมูลจริงหรือพื้นที่ที่มีอยู่ก่อน

## การระบุตัวตนของตารางและคอลัมน์

ใน SQLite สำเนามี `_development_workspace` และ `_development_objects` เท่านั้น ไม่เพิ่มสองตารางนี้ในฐานข้อมูลจริง

วัตถุเดิมมีรหัสกำเนิดและรหัสต้นทาง ส่วนวัตถุใหม่มีรหัสกำเนิดใหม่ที่ไม่ผูกกับเลขลำดับ metadata เพียงอย่างเดียว Trigger ของ SQLite บันทึกการเพิ่ม เปลี่ยนชื่อ และลบในธุรกรรมเดียวกับการแก้ metadata เดิม

- เปลี่ยนชื่อคอลัมน์เดิมยังเป็นวัตถุเดิม
- ลบแล้วสร้างชื่อเดิมหรือเลข metadata เดิม ไม่กลายเป็นวัตถุเดิมโดยผิดพลาด
- หากธุรกรรมการแก้โครงสร้างย้อนกลับ รายการรหัสกำเนิดจะย้อนพร้อมกัน
- ตัวเปรียบเทียบระยะ 1 อ่านรหัสกำเนิดของพื้นที่ชนิดใหม่ เพื่อแยกเพิ่ม/ลบได้แม้ชื่อหรือเลข metadata เหมือนเดิม

## การป้องกันผลข้างเคียง

เพิ่มบริบทพื้นที่พัฒนาด้วย AsyncLocalStorage แยกแต่ละคำขอ ไม่ใช้ตัวแปรเปิด/ปิดทั่วระบบ การระงับ Automation จึงไม่ระงับงานของผู้ใช้จริงอีกคำขอหนึ่ง

ป้องกันสองชั้น:

1. ชั้นคำขอ: อนุญาตเฉพาะเส้นทางเขียนภายในที่ตรวจแล้ว บล็อกไฟล์ Data Source Push และงานจริง พร้อมตรวจรหัสพื้นที่และแอปจากหน้าเดิม
2. จุดทำงานจริง: ตรวจอีกครั้งก่อนเรียก External HTTP, ส่ง Push, เข้าคิวงาน, เริ่ม Worker, เขียนรูป/ไฟล์ หรือสร้าง PDF จริง รวม Action ที่ไม่ใช่การเปลี่ยนข้อมูลภายใน

การตรวจสิทธิ์ Session, CSRF, สิทธิ์แถว และการตรวจข้อมูลเดิมยังอยู่ การเป็นพื้นที่พัฒนาไม่ได้ข้ามข้อจำกัดเหล่านี้

## สิ่งที่รักษาจากแอปจริง

พื้นที่พัฒนาสำเนาข้อมูล ณ เวลาสร้าง ไม่ตามข้อมูลจริงแบบ Realtime การเปลี่ยนแปลงของผู้ใช้หลังจากนั้นไม่ถูกนำมาทับสำเนา และข้อมูลทดลองไม่ถูกนำกลับแอปจริง

การสร้างสำเนายังใช้ `VACUUM INTO` ของ SQLite ไฟล์เดียวกับแพลตฟอร์ม จึงอาจมีข้อมูลหลายแอปอยู่ในไฟล์สำเนาทางกายภาพ ไม่ควรแจกจ่ายไฟล์นี้ให้ผู้ใช้หรือถือว่าเป็นไฟล์ส่งออกเฉพาะแอป ขอบเขตการเข้าถึงผ่านระบบยังตรวจตามแอปและสิทธิ์จริงปัจจุบัน

ล้างรหัสผ่านที่คัดลอกมา Session และข้อมูลลงทะเบียน Push ออกจากพื้นที่ชนิดใหม่ แต่ข้อมูลธุรกิจและข้อมูลส่วนบุคคลอื่นอาจยังอยู่ในสำเนา จึงต้องจำกัดสิทธิ์โฟลเดอร์และบริหารอายุไฟล์

การคัดลอกฐานข้อมูลใหญ่ยังอาจใช้เวลา CPU และพื้นที่ดิสก์ ไม่ได้ยืนยันว่าจะไม่มีผลต่อเวลาตอบสนองของ Production ทุกขนาดข้อมูล การวัดด้วยข้อมูลจริงขนาดใหญ่ยังเป็นงานต่อไป

## หลักฐานการทดสอบ

ชุดทดสอบใช้ฐานข้อมูลจำลองและโฟลเดอร์ที่ตัวรันทดสอบสร้างเท่านั้น ไม่ใช้ Production หรือฐานข้อมูลผู้ใช้จริง

- หน่วยทดสอบ `tests/development-workspace.test.cjs`: แยกบริบทพร้อมกัน รักษารหัสกำเนิด ย้อนธุรกรรม รักษาขอบเขตตารางร่วม ล้างข้อมูลยืนยันตัวตน และบล็อกจุดเครือข่าย/ไฟล์/คิวก่อนทำงานจริง
- เบราว์เซอร์/API `tests/development-workspace-browser.cjs`: สร้างผ่าน UI, ทดลองโครงสร้างและข้อมูล, แปลงชนิดและบล็อก Token ข้ามพื้นที่, ตรวจฐานข้อมูลจริงใน fixture ไม่เปลี่ยน, งานจริงของอีกคำขอยังทำงาน, แอปหลัก/แอปอื่น, ตารางร่วม, หมดอายุ/เก็บพื้นที่ และ Header มือถือ
- ตรวจซ้ำฉบับร่างทั่วไป การเผยแพร่เดิม สิทธิ์ผู้พัฒนา หลายแอป การแปลงข้อมูล PDF และโปรไฟล์ตามชุดที่เกี่ยวข้อง

ผลผ่านต้องอ้างอิง Log จบงาน ไม่ใช้เพียงการอ่านโค้ดหรือ Build แทนผลทดสอบ Runtime

## ยังไม่ได้ทำในระยะนี้

- ซ้อมแผนอัปเดตกับข้อมูลจริงล่าสุด
- เผยแพร่โครงสร้างและนำการตั้งค่าจากพื้นที่ชนิดใหม่ไปใช้จริง
- รวมพื้นที่พัฒนา Clone ใด ๆ กลับเข้าแอปจริงโดยอัตโนมัติ
- เขียนโครงสร้างของตารางร่วมและรวมผลกระทบหลายแอป
- อัปโหลดไฟล์ในพื้นที่พัฒนาและย้ายไฟล์ตอนเผยแพร่
- ลบไฟล์พื้นที่หมดอายุอัตโนมัติ หรือกู้คืนพื้นที่ทดลองที่ลบไปแล้ว
- วัดการสร้างสำเนา/เปลี่ยนโครงสร้างบนข้อมูลหนึ่งล้านแถวและหลาย Container

ยังไม่ได้ Deploy และไม่มีการเปลี่ยน Production Database ในงานนี้

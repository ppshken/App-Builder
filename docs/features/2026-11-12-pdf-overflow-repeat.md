# แก้หัวเรื่องซ้ำบนหน้าต่อของรายการลูกใน PDF

## สาเหตุ

ใน lib/pdf-design-html.ts ระบบสร้างหน้าต่อด้วยหมายเลขหน้าออกแบบเดิมและลำดับชุดรายการลูก แต่ตัวกรององค์ประกอบตรวจเพียงว่ามาจากหน้าออกแบบเดียวกัน จึงนำหัวเรื่อง ช่องข้อมูล และตารางทั่วไปมาซ้ำ แม้ repeat_all_pages จะปิดหรือไม่ได้ระบุไว้

## การแก้ไข

- องค์ประกอบทั่วไปแสดงเฉพาะชุดแรกของหน้าที่ออกแบบไว้
- หน้าที่เพิ่มเพราะรายการลูกเกินความจุแสดงตารางลูกต่อ พร้อมองค์ประกอบที่เปิด repeat_all_pages เท่านั้น
- หัวคอลัมน์ของตารางลูกยังควบคุมด้วย show_header แยกต่างหาก
- หน้าที่ออกแบบเพิ่มเองยังมีองค์ประกอบของหน้านั้นตามเดิม
- หน้าแรกคงตำแหน่งตามแบบ ส่วนหน้าต่อเลื่อนกลุ่มตารางลูกขึ้นด้านบน โดยเว้นองค์ประกอบหัวกระดาษที่แสดงทุกหน้าและซ้อนแนวนอนกับตาราง
- ปรับข้อความอธิบายในตัวออกแบบให้ตรงกับพฤติกรรมนี้
- ไม่เปลี่ยนข้อมูลแม่แบบหรือฐานข้อมูลจริง

## หลักฐานและการทดสอบ

- ก่อนแก้: .test-data/pdf-overflow-before.log พบหัวเรื่อง 5 ครั้ง แต่ควรมี 1 ครั้ง
- หลังแก้: .test-data/pdf-overflow-after.log ผ่าน 10 การทดสอบ รวมตาราง การ์ด ค่าปิด/เปิด/ไม่ระบุการซ้ำ หลายหน้าออกแบบ และแต่ละรายการลูกปรากฏครั้งเดียว
- เพิ่มการตรวจใน tests/pdf-tables-browser.cjs ว่าตารางหัวเรื่องแสดงครั้งเดียว และไม่มีหัวเรื่องในหน้าต่อ
- .test-data/pdf-overflow-pdftables.log ผ่านตัวออกแบบ การดูตัวอย่าง และการสร้างไฟล์ PDF จริงในฐานข้อมูลทดสอบ

## ข้อจำกัด

หน้าต่อคงขนาดกรอบ จำนวนแถวต่อหน้า และระยะสัมพันธ์ระหว่างตารางลูกหลายกรอบตามแบบ ไม่เพิ่มจำนวนแถวอัตโนมัติเพื่อเติมพื้นที่ทั้งหมด หัวและท้ายกระดาษคงตำแหน่งเดิม และยังไม่ได้ Deploy

## ผลตรวจ Production Build

- .test-data/pdf-overflow-build.log: Build และ TypeScript ผ่าน
- .test-data/pdf-overflow-pdftables-production.log: ผ่านการตรวจหัวเรื่องไม่ซ้ำในหน้าต่อ ตัวอย่างหลายหน้า และสร้างไฟล์ PDF จริง

## ปรับตำแหน่งตารางลูกบนหน้าต่อ

- สาเหตุเดิม: ทุกชุดรายการลูกใช้ค่า y เดียวกับหน้าแรก
- เลื่อนกลุ่มกรอบตารางลูกขึ้นพร้อมกันเพื่อรักษาระยะห่างภายในกลุ่ม
- หากไม่มีหัวกระดาษซ้ำ ตารางแรกเริ่มที่ y=0 ภายในพื้นที่พิมพ์ ซึ่งมีขอบกระดาษ 16 มม. อยู่แล้ว
- หากมีหัวกระดาษซ้ำที่อยู่เหนือกรอบและซ้อนกันในแนวนอน จะเริ่มถัดจากขอบล่างของหัวกระดาษ
- ท้ายกระดาษและหน้าออกแบบใหม่ไม่ถูกเลื่อน
- ก่อนแก้: .test-data/pdf-continuation-before.log ยืนยันตำแหน่งหน้าต่อยังอยู่กลางหน้า
- หลังแก้: .test-data/pdf-continuation-unit.log ผ่าน 11 การทดสอบ ครอบคลุมแนวตั้ง แนวนอน หลายกรอบ และหัว/ท้ายซ้ำ

- .test-data/pdf-continuation-browser.log: ผ่านการตรวจตำแหน่งหน้าต่อและสร้างไฟล์ PDF ในโหมดพัฒนา
- .test-data/pdf-continuation-build.log: Production Build ผ่าน
- .test-data/pdf-continuation-production.log: ผ่านการตรวจตำแหน่งหน้าต่อและสร้างไฟล์ PDF จริงบน Production Build

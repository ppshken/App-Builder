# เวอร์ชั่นแอป ระยะ 1 — เปรียบเทียบฉบับร่างและผลกระทบ

วันที่: 12 พฤศจิกายน 2569

## สิ่งที่เพิ่ม

หน้าเวอร์ชั่นแอป เมื่อกดตรวจและเผยแพร่ จะแสดงผลเปรียบเทียบฉบับร่างกับแอปจริง แยกจำนวนการเปลี่ยนโครงสร้าง การตั้งค่า ตารางร่วมเฉพาะแอป และข้อขัดแย้ง

แต่ละรายการแสดงชนิดการเปลี่ยน ชื่อตาราง/คอลัมน์ คุณสมบัติที่เปลี่ยน ความเสี่ยง ผลกระทบ และรายการที่ต้องตรวจก่อน โดยไม่เพิ่มตัวประมวลผล Migration หรือเปิดให้แก้โครงสร้างในฉบับร่าง

## วิธีใช้

1. สร้างฉบับร่างและแก้การตั้งค่าตามวิธีเดิม
2. ไปที่เวอร์ชั่นแอป แล้วกดตรวจและเผยแพร่ของฉบับร่างนั้น
3. อ่านส่วนผลเปรียบเทียบและผลกระทบ กดแต่ละรายการเพื่อดูรายละเอียด
4. หากมีการแก้ชนกันหรือโครงสร้างที่ยังไม่รองรับ ปุ่มเผยแพร่จะกดไม่ได้
5. การตั้งค่าที่โครงสร้างเดิมรองรับยังเผยแพร่ด้วยวิธีเดิม และยังต้องผ่านการตรวจสุขภาพ สิทธิ์ และการยืนยันเดิม

ไม่มีปุ่มซ้อมหรือเผยแพร่โครงสร้างในระยะนี้ การระบุว่าใช้เงื่อนไขเดิมไม่ได้ยืนยันว่าผ่านการตรวจทั้งหมดแล้ว

## หลักการเปรียบเทียบ

- ใช้ฐานตั้งต้นตอนสร้างร่าง การตั้งค่าจริงปัจจุบัน และการตั้งค่าในร่าง
- จับคู่คอลัมน์ด้วยชื่อตารางในระบบและรหัส metadata เดิมภายในฉบับร่าง ไม่เดาการเปลี่ยนชื่อจากชื่อแสดง
- ตารางเปลี่ยนชื่อหรือคอลัมน์ที่เปลี่ยนรหัสถูกแยกเป็นเพิ่ม/ลบ ไม่เดาว่าเป็นวัตถุเดียวกัน
- จัดเรียงชุด metadata และคุณสมบัติก่อนทำลายนิ้วมือ ไม่นับเวลาทำงานครั้งถัดไปของ Automation เป็นการเปลี่ยนแอป
- JSON ของการตั้งค่าที่สลับเฉพาะลำดับชื่อคุณสมบัติถือว่าเหมือนกัน แต่ลำดับสมาชิกในอาร์เรย์ยังมีความหมาย
- ตรวจการแก้คุณสมบัติเดียวกันต่างค่าทั้งสองฝั่ง รวมเพิ่มชื่อชนกันและลบฝั่งหนึ่งขณะแก้อีกฝั่ง
- ยังไม่รวมการแก้ไขสามชุดอัตโนมัติ แม้แก้คนละคุณสมบัติก็ยังเคารพข้อจำกัดการเผยแพร่เดิม
- การเพิ่มหรือแก้แถวธุรกิจไม่ได้ถูกส่งเข้าเครื่องมือเปรียบเทียบ จึงไม่เปลี่ยนลายนิ้วมือแผนเพราะแถวเหล่านั้น

## การเปลี่ยนที่แสดงได้แต่ยังเผยแพร่ไม่ได้

เพิ่ม/ลบตาราง เพิ่ม/ลบคอลัมน์ รวมคอลัมน์คำนวณ เปลี่ยนชนิด ชื่อในระบบ Key Unique Ref สถานะคอลัมน์จริง/คำนวณ เจ้าของตาราง หรือแหล่งข้อมูล

การเพิ่มคอลัมน์คำนวณอาจไม่ต้องแก้ SQL แต่ระบบเผยแพร่เดิมยังไม่รองรับการเพิ่ม metadata คอลัมน์ จึงระบุว่ายังไม่รองรับอย่างตรงไปตรงมา

แผนตรวจตารางที่แอปเป็นเจ้าของหรือมีสิทธิ์อ่านตามบริบทแอป และแจ้งผลกระทบหากตารางใช้ร่วมกับแอปอื่น การตั้งค่าเฉพาะแอปของตารางร่วมถูกแยกออกจากการเปลี่ยนโครงสร้างจริง

## จุดเชื่อมและไฟล์

| ไฟล์ | หน้าที่ |
|---|---|
| `lib/release-plan.ts` | ตัววิเคราะห์จาก metadata ที่ส่งเข้ามา ไม่มีการเปิดฐานข้อมูล เครือข่าย หรือประมวลผล SQL |
| `lib/releases.ts` | เพิ่มผล `plan` ในข้อมูลรีวิว โดยใช้ข้อมูลฐานตั้งต้น แอปจริง และร่างที่ระบบอ่านอยู่แล้ว |
| `app/components/ReleasePlanPanel.tsx` | แสดงสรุป ลำดับ ผลกระทบ และข้อขัดแย้ง |
| `app/components/release-plan.css` | รูปแบบที่ใช้สีธีมเดิม รองรับหน้าจอแคบและโหมดมืด |
| `app/releases/page.tsx` | แสดงแผนก่อนรายละเอียดเดิม และปิดปุ่มเมื่อแผนมีข้อบล็อก |
| `tests/release-plan.test.cjs` | ทดสอบตัวเปรียบเทียบ ลำดับ การรักษา input และขอบเขตข้อมูล |
| `tests/release-plan-browser.cjs` | ทดสอบ API เบราว์เซอร์ การเผยแพร่เดิม การรักษาข้อมูล และการปฏิเสธโครงสร้าง |
| `scripts/test.cjs`, `scripts/integration.cjs` | ลงทะเบียนชุดทดสอบ หน่วยทดสอบและโหมด `releaseplan` |

API ยังคงเป็น `GET /api/releases?id=...` โดยเพิ่ม `plan` ควบคู่กับ `manifest`, `review_hash`, `conflict`, `changes` และ `health` เดิม ไม่มี endpoint ที่รับ SQL หรือรันแผนใหม่

ผลแผนมีโหมดอ่านอย่างเดียว รุ่นรูปแบบ ลายนิ้วมือทั้งสามชุด รายการเปลี่ยน ข้อขัดแย้ง ข้อบล็อก ผลสรุป และขอบเขตการตรวจ รายการแผนแสดงชื่อคุณสมบัติที่เปลี่ยนโดยไม่ส่งค่าก่อน/หลังเพิ่มอีกชุด ส่วนรายละเอียดเดิมของระบบรีวิวยังคงเดิม

## การจัดลำดับ

ตารางใหม่อยู่ก่อนคอลัมน์ที่อาศัยตารางนั้น คอลัมน์ Ref รอตารางปลายทางใหม่ และรายการตั้งค่ารอรายการโครงสร้างก่อน เป็นลำดับตรวจแบบอนุรักษนิยม ไม่ใช่ SQL ที่พร้อมนำไปประมวลผล

การตรวจกราฟสูตรและความสัมพันธ์อย่างละเอียดคงใช้ผลตรวจสุขภาพเดิม ไม่อ้างว่าเครื่องมือระยะนี้สร้างแผนอัปเดตที่ประมวลผลได้ครบแล้ว

## การทดสอบและหลักฐาน

### หน่วยทดสอบ

ชุดใหม่ครอบคลุมผลคงที่ การไม่แก้ input JSON/ลำดับอาร์เรย์ ข้อขัดแย้ง ข้อมูลจริงเปลี่ยน โครงสร้างจริง/คำนวณ สิทธิ์เจ้าของ/แหล่งข้อมูล ลำดับตารางและ Ref ตารางร่วม ขอบเขตแอป การไม่รับแถวธุรกิจ และรหัสซ้ำหรือหาย

หลักฐาน: `.test-data/release-plan-unit.log` สำหรับการรันแยก และ `.test-data/release-plan-all-unit.log` สำหรับชุดรวม ต้องแยกจำนวนผ่านกับจำนวนข้ามตามผลจริง

### API และเบราว์เซอร์

ชุดใหม่ทดสอบด้วยฐานข้อมูลแยกที่ตัวรันสร้างเท่านั้น:

- ตรวจแผนซ้ำแล้วแถวจริง คอลัมน์ View และข้อมูลร่างไม่เปลี่ยน
- ผู้ใช้เพิ่มข้อมูลจริงหลังสร้างร่างแล้วแผนการตั้งค่ายังไม่หมดอายุจากการเพิ่มแถวนั้น
- กดเผยแพร่ผ่านหน้าจอแล้วข้อมูลจริงล่าสุดยังอยู่ และข้อมูลทดลองไม่มาทับ
- การแก้การตั้งค่าจริงชนกับร่างทำให้หน้าเว็บและ API เดิมปฏิเสธการเผยแพร่
- ใช้การปรับ metadata ในฐานข้อมูลร่างจำลองเพื่อทดสอบโครงสร้างในอนาคต ไม่ได้ปลดล็อก API แก้โครงสร้าง
- โครงสร้างที่ยังไม่รองรับแสดงผลได้ แต่ปุ่มเผยแพร่ปิด และการเรียกเผยแพร่ตรงยังถูกปฏิเสธ
- ผู้ใช้ที่ไม่มีสิทธิ์ Builder อ่านแผนไม่ได้
- หน้า Desktop/Mobile ไม่ล้นแนวนอน โหมดมืดใช้ธีม และไม่มีข้อผิดพลาด JavaScript

หลักฐานโหมดพัฒนา: `.test-data/release-plan-browser-dev.log`

## ข้อจำกัดที่คงไว้

- ยังไม่รองรับนำการเปลี่ยนจากแอป Clone ใดก็ได้มาใส่แอปเดิม ต้องพัฒนาสายกำเนิดและการจับคู่ก่อน
- ยังไม่เปิดเพิ่มโครงสร้างในพื้นที่พัฒนา ไม่มีการซ้อมโครงสร้าง และไม่มีงานเผยแพร่โครงสร้างจริง
- ไม่เปรียบเทียบหรือเปลี่ยนสมาชิก รหัสผ่าน และเพดานสิทธิ์จริง แต่แจ้งให้ตรวจสิทธิ์ตาราง/Action ใหม่
- ตัวเผยแพร่เดิมตรวจความเปลี่ยนแปลงระดับ catalog ซึ่งอาจกว้างกว่าขอบเขตแผนใหม่ ยังรักษาการบล็อกเดิมไว้ ไม่แก้การตั้งค่าจริงทับโดยเงียบ
- การล็อกฉบับร่างเดิมยังเป็นภายใน process ไม่ใช่ระบบจองงานข้าม Container
- ยังไม่วัดประสิทธิภาพการเผยแพร่โครงสร้างหนึ่งล้านแถว เพราะยังไม่มีตัวเผยแพร่โครงสร้างในระยะนี้
- การตรวจแผนไม่เท่ากับการรับประกันว่าการเปลี่ยนพฤติกรรมสูตรหรือ Automation ไม่มีผลกระทบ ผู้ดูแลต้องอ่านผลตรวจและทดสอบตามงาน
- ยังไม่ได้ Deploy หรือเปลี่ยนฐานข้อมูลจริง

## ลำดับถัดไป

ระยะ 2 ตามเอกสารแผน: เพิ่มสายกำเนิดและพื้นที่พัฒนาที่เปลี่ยนโครงสร้างได้แบบแยกจริง พร้อมป้องกันงานเบื้องหลัง ไฟล์ และการส่งออกจริง ก่อนพัฒนาการซ้อมและเผยแพร่โครงสร้าง

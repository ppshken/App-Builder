# ตารางช่วยดู ID และชื่อของ Ref ระหว่างแก้ไขข้อมูลจริง

วันที่: 17 พฤศจิกายน 2026

## วิธีใช้

1. เปิด Data → ตาราง → ข้อมูลจริงในฐานข้อมูล
2. เลือกแถว แล้วกดแก้ไขที่เลือก หรือกดแก้ไขรายแถว
3. ติ๊กคอลัมน์ที่เป็น Ref จะเห็นช่องค่าใหม่และตารางอ้างอิงด้านล่าง
4. ตารางแสดง ID และชื่อที่แสดงตาม Label ของตารางอ้างอิง พร้อมค้นหาและเปลี่ยนหน้า
5. กดแถวหรือปุ่มใช้ ID นี้ เพื่อเติม ID ลงช่องค่าใหม่ ยังไม่บันทึกข้อมูลในขั้นตอนนี้
6. กดบันทึกเมื่อพร้อม หากเลือกหลายแถว ค่าใหม่จะใช้กับทุกแถวที่เลือก โดยยังตรวจสิทธิ์และเงื่อนไขแยกแต่ละแถวเหมือน CRUD เดิม

พิมพ์ ID ในช่องค่าใหม่เองได้ ระบบจะตรวจชื่อของ ID นั้นแยกต่างหาก แม้อยู่นอกหน้าที่กำลังดู ถ้าไม่พบหรือไม่มีสิทธิ์อ่าน จะแจ้งโดยไม่คาดเดาชื่อรายการ ไม่เปลี่ยนค่าใหม่ให้อัตโนมัติ

NULL ยังทำงานตามเดิม การกดเลือกรายการอ้างอิงจะเติม ID และยกเลิก NULL ของช่องนั้น เพราะเป็นการเลือกค่าใหม่โดยผู้ใช้

## การโหลดข้อมูล

- แสดงเฉพาะคอลัมน์ Ref ที่ติ๊กแก้ไข ไม่โหลดตัวเลือกของทุกคอลัมน์ตั้งแต่เปิดหน้าต่าง
- ส่งรายการกลับมาครั้งละไม่เกิน 10 แถว และใช้ปุ่มก่อนหน้า/ถัดไป
- ใช้ cursor ของ ID ที่ตรวจล่าสุด ไม่ใช้หมายเลขลำดับแถวเป็นตัวระบุข้อมูล
- อ่านเกินหน้าปัจจุบันหนึ่งรายการเพื่อยืนยันว่ามีหน้าถัดไป จึงอาจอ่าน 11 แถวเพื่อส่งกลับ 10 แถว ไม่ได้ดึงทั้งตารางเข้าฝั่งผู้ใช้ก่อนตัดแบ่ง
- ไม่ขอรูปภาพหรือคำนวณคอลัมน์รูปประกอบที่ไม่ได้ใช้ ตารางย่อยแสดงเฉพาะ ID และ Label
- ค้นหาจาก Server โดยหน่วงการพิมพ์สั้น ๆ เพื่อลดคำขอ
- เมื่อเปิดโหมดค้น ID ถ้าพิมพ์เลขจำนวนเต็มบวกจะค้น ID ตรงตัวผ่านฐานข้อมูล แม้ Label เป็นคอลัมน์คำนวณ ส่วนข้อความอื่นค้นจากชื่อที่แสดง
- การพิมพ์ ID ในช่องค่าใหม่ขอเฉพาะแถวนั้น ไม่โหลดรายการก่อนหน้าทั้งหมดเพื่อหาชื่อ
- ปิดคอลัมน์ ปิดหน้าต่าง หรือเปลี่ยนคำค้น จะยกเลิกคำขอเก่าที่ไม่จำเป็น ป้องกันคำตอบเก่ามาแสดงทับข้อมูลใหม่
- การเลือก ID ไม่ย้ายลำดับรายการหรือสลับหน้าให้เอง

## สิทธิ์และความถูกต้อง

ต่อยอด API Ref เดิม ตรวจสิทธิ์แอป ตาราง และระดับแถว ทั้งตอนค้นรายการและตอนขอชื่อของ ID ที่พิมพ์ ไม่เปิด endpoint อ่านตารางโดยข้ามสิทธิ์

รายการช่วยเลือกแสดงข้อมูลที่มีสิทธิ์อ่าน ไม่ได้รับประกันว่าเลือกแล้วจะผ่าน Valid_If ของทุกแถว เพราะการแก้หลายแถวอาจมีเงื่อนไขต่างกัน ตอนบันทึกยังใช้ API CRUD เดิม พร้อมตรวจค่า ข้อมูลอ้างอิง รุ่นของแถว และรายงานสำเร็จ/ล้มเหลวตามเดิม

ในแอปที่เชื่อมตารางร่วม ใช้ชื่อและ Label ตามการตั้งค่าเฉพาะแอปที่มีอยู่ ส่วนการแก้ไขจริงยังเคารพสิทธิ์การเชื่อมตาราง

## ขอบเขตรุ่นนี้

- เพิ่มในหน้าต่างแก้ไขข้อมูลที่เลือกและแก้ไขรายแถวของหน้าข้อมูลจริงเท่านั้น ยังไม่ได้เพิ่มในหน้าสร้างหลายแถว
- ไม่เปลี่ยนชนิดข้อมูลที่บันทึก Ref ยังเป็น ID ตัวเลข
- ไม่เพิ่มปุ่มสร้างหรือแก้ไขแถวในตารางอ้างอิงจากตารางช่วยดู
- ไม่ดึงทั้งตารางมาเก็บในเบราว์เซอร์ และไม่เพิ่ม dependency
- หาก Label เป็นสูตรหรือสิทธิ์ระดับแถวคัดออกมาก ระบบใช้เพดานการตรวจเดิมที่ 2,000 แถวต่อคำขอ บางหน้าอาจมีน้อยกว่า 10 รายการ แต่ยังมีปุ่มถัดไปเพื่อค้นต่อ จึงไม่ตีความว่าข้อมูลสิ้นสุดจากหน้าที่ว่างเพียงอย่างเดียว
- เป็นข้อมูลขณะขออ่าน ไม่ใช่การติดตามแบบทันที หากข้อมูลหรือสิทธิ์เปลี่ยนภายหลัง จะตรวจใหม่ตอนบันทึก

## ไฟล์และจุดเชื่อมต่อ

| ไฟล์ | การเปลี่ยนแปลง |
|---|---|
| app/api/tables/[name]/raw/route.ts | ส่งชื่อตารางอ้างอิงและชื่อที่แสดงสำหรับคอลัมน์จริงชนิด Ref |
| app/t/[table]/raw/page.tsx | เปิดตัวช่วยเฉพาะ Ref ที่ติ๊กแก้ไข และรับ ID กลับไปยังค่าใหม่ |
| app/components/RawRefLookup.tsx | ตารางขนาดเล็ก ค้นหา เปลี่ยนหน้า ขอชื่อ ID และยกเลิกคำขอเก่า |
| app/components/raw-ref-lookup.css | รูปแบบตามธีมเดิมและขนาดมือถือ |
| lib/ref-options.ts | รองรับ pageSize 10/25, ค้น ID และปิดรูปภาพ โดยค่าตั้งต้นของฟอร์มเดิมยังเป็น 25 รายการ |
| tests/raw-ref-browser.cjs | ทดสอบ API/หน้าจอและการบันทึกจริงในฐานข้อมูลจำลอง |
| tests/ref-server-search-browser.cjs | ตรวจความเข้ากันได้กับ Ref เดิม และเพดาน 10 รายการ |

## บัคที่พบระหว่างตรวจรอบสุดท้าย

ทดสอบพบว่าเปิดตัวช่วยแล้วกดถัดไปเร็ว ตัวหน่วงช่องค้นหาครั้งแรกอาจรีเซ็ตกลับหน้าแรกทั้งที่ผู้ใช้ไม่ได้เปลี่ยนคำค้น แก้ให้ตั้งตัวหน่วงและรีเซ็ตหน้าเฉพาะเมื่อคำค้นที่พิมพ์ต่างจากคำค้นที่ใช้จริง หลักฐานก่อนแก้อยู่ใน .test-data/raw-ref-pagination-red.log และทดสอบซ้ำด้วยชุด rawref บน Build ล่าสุด

## ผลยืนยันหลังแก้จังหวะเปลี่ยนหน้า

Build จบด้วยรหัสออก 0 ทดสอบ rawref และ refserver ซ้ำกับชุด Build ล่าสุดผ่าน รวมถึงกดถัดไปทันทีหลังเปิดตัวช่วย และค้น ID ของตารางที่ใช้ Label คำนวณ ส่วน rawdata ทดสอบ CRUD เดิมผ่าน ใช้ฐานข้อมูลจำลองแยกทุกชุด ไม่มีการแก้ข้อมูลจริง

# ซ้อมข้อมูลแบบเร็ว

หน้าเวอร์ชันแอปเพิ่มช่องรูปแบบการซ้อม ค่าเริ่มต้นเป็น **ซ้อมเร็ว** อ่านตัวอย่างต้นและท้ายตารางไม่เกิน 100 แถวต่อตาราง รวมไม่เกิน 1,000 แถว เลือก **ซ้อมข้อมูลครบทุกแถว** ได้ตามเดิม API ที่ไม่ส่ง mode ยังคง full เพื่อรักษาพฤติกรรมเดิม

## ขอบเขตผล

- โหมดเร็วซ้อม schema/configuration บนสำเนาครบ เพื่อให้ Ref/SELECT และ dependency คำนวณจากข้อมูลจริงครบชุด ไม่ลบข้อมูลออกจากสำเนาเพื่อทำให้สูตรคืนยอดต่ำกว่าความจริง
- ตรวจสูตร/เงื่อนไขเฉพาะตัวอย่าง Hash การคงค่าข้อมูลครอบคลุมเฉพาะตัวอย่างและนับจำนวนแถวจริงทุกตาราง ไม่อ้างว่า Hash ครบทุกค่า ข้ามการตรวจ foreign_key_check ทั้งฐานข้อมูล
- ผลแสดง “ซ้อมตัวอย่างผ่าน” พร้อมตรวจจริง/ทั้งหมด มีจำนวนตรวจจริงรายตารางในรายละเอียด เมื่อมีหลายตารางจนชนงบ 1,000 แถว บางตารางอาจตรวจไม่ครบหรือไม่ได้ตรวจตามลำดับตาราง จึงไม่ใช้ผลนี้ยืนยันทุกแถว
- โหมดครบยังตรวจ hash ทุกแถว จำนวนแถว, FK และสูตร/เงื่อนไขครบตามงบเดิม
- ทั้งสองโหมดใช้ expressionContext ร่วมภายในตารางที่กำลังตรวจ แทนการสร้าง context แล้วอ่านข้อมูลอ้างอิงใหม่ทุกแถว การตรวจเป็น read-only บน snapshot จึงใช้ข้อมูลชุดเดียวกันได้ รวมการวิเคราะห์แถวที่ล้มเหลว
- ปุ่มเผยแพร่และเงื่อนไขการตรวจข้อมูลก่อนเผยแพร่ไม่ลดลง งาน validation ก่อนเผยแพร่ยังใช้ full และปฏิเสธผล sample หากถูกส่งมาแทน validation เต็มรูปแบบ

## คิวและขีดจำกัด

mode ถูกตรวจฝั่ง server และบันทึกในฐานข้อมูลคิว งานเก่ามีค่า full โดย migration ส่วนคิวใหม่จาก UI ใช้ sample ห้ามเปลี่ยน mode ของงานที่ยัง queued/running ผ่านการ submit ซ้ำ ต้องรอหรือยกเลิกก่อน

ตัว worker ใช้งบ sample 1,000 แถว/2 นาที ที่ตรวจตาม checkpoint ส่วน full คง 1,000,000 แถว/15 นาที กฎพื้นที่ 2 GB และการยกเลิก/fencing/cleanup ไม่เปลี่ยน ยังคงต้องสร้างสำเนาครบก่อนเริ่มตรวจ เวลาเริ่มงานจึงขึ้นกับขนาดฐานข้อมูล และสูตรของตัวอย่างยังอาจอ่านตารางอ้างอิงขนาดใหญ่ได้ ไม่รับประกันว่าจะจบในเวลาคงที่

เปลี่ยน RELEASE_EXECUTOR_VERSION เพื่อไม่ใช้ proof จากตัวตรวจรุ่นก่อนกับแผนใหม่

## ผลทดสอบจริง

SQLite แยก 20,000 แถว มี virtual COUNT(SELECT(...)) อ้างตารางตัวเอง:

| โหมด | ตรวจจริง | เวลาในตัวงาน |
| --- | ---: | ---: |
| ซ้อมเร็ว | 100 / 20,000 | 123 ms |
| ตรวจครบ | 20,000 / 20,000 | 1,420 ms |

เวลา durationMs รวมการสร้างสำเนา/ตรวจใน worker ไม่รวมรอคิว, polling และ compile ของเว็บ เป็นผลบนเครื่องทดสอบ ไม่ใช่การรับประกัน Production ฐานข้อมูลจริงของ fixture ยังมี 20,000 แถว และไม่มีคอลัมน์ที่ซ้อมเพิ่มหลุดไปที่ live

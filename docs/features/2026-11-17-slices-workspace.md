# ปรับหน้าจัดการ Slice และตัวอย่างข้อมูล

วันที่ 17 พฤศจิกายน 2569

## สิ่งที่เปลี่ยน

- แยกหน้าจัดการ Slice ออกจากตัวจัดการ Action โดยใช้ระบบบันทึก Slice และระบบสูตรเดิม
- ใช้พื้นที่เต็มหน้าทำงาน มีแถบรายการ Slice เพียงชุดเดียว แยกตามตาราง พร้อมจำนวนและช่องค้นหา
- ตั้งค่าเป็นสามขั้นตอน: ชื่อและตารางต้นทาง → เงื่อนไขเลือกแถว → คอลัมน์ที่จะนำไปใช้
- เพิ่มตัวช่วยสร้างเงื่อนไขแบบเลือกคอลัมน์ ตัวเปรียบเทียบ และค่า สามารถแทนสูตรเดิม หรือเชื่อมด้วย AND/OR ได้
- ใช้ช่องสูตรเดิมที่มีคำแนะนำระหว่างพิมพ์ และเปิดตัวช่วยเขียนสูตรได้
- เลือกทุกคอลัมน์ หรือกำหนดเองพร้อมค้นหา มีป้ายคอลัมน์คำนวณ และป้ายคอลัมน์ที่ View ใช้อยู่
- แสดง View ที่ใช้ Slice พร้อมลิงก์ไปตั้งค่า ป้องกันเปลี่ยนตาราง ตัดคอลัมน์ที่ถูกใช้ และลบ Slice ที่มี View อ้างอิง
- เพิ่มคัดลอก Slice ย้อนกลับการแก้ไข และแจ้งเตือนเมื่อออกจากหน้าขณะยังไม่บันทึก ปุ่มบันทึกกดได้เฉพาะมีการแก้ไขและข้อมูลเบื้องต้นถูกต้อง
- จอใหญ่แสดงการตั้งค่าและข้อมูลคู่กัน จอเล็กสลับแท็บได้ รองรับธีมสว่างและมืด

### ปรับตำแหน่งเมนูและแถบตารางเพิ่มเติม

- ย้ายทางเข้า Slices จากแถบเครื่องมือด้านซ้ายของ Data ไปเป็นปุ่มระหว่าง **ตารางข้อมูล → Slices → แผนผังตาราง**
- แถบตารางของหน้า Slices แสดงเฉพาะตารางที่มี Slice บันทึกอยู่ พร้อมจำนวน Slice
- ใช้รูปแบบใกล้เคียงหน้า Data: แถวตาราง ไอคอนฐานข้อมูล ลูกศรย่อ/ขยาย และรายการ Slice เยื้องด้านล่าง โดยขยายตารางที่กำลังเลือก
- การเพิ่ม Slice ใหม่ยังเลือกตารางต้นทางได้ทุกตารางตามสิทธิ์ ตารางจะปรากฏในแถบหลังบันทึก Slice แรก
- เพิ่มทางกลับตารางข้อมูลด้านล่างแถบรายการ
- ตรวจชนิดข้อมูลและทดสอบหน้าจอ/API ซ้ำ รวมลำดับปุ่ม ตารางที่ไม่มี Slice การย่อ/ขยาย และมือถือ หลักฐาน `.test-data/slices-nav-types.log`, `.test-data/slices-nav-browser-final.log`

## ความหมายของข้อมูล

Slice เป็นการเลือกข้อมูลจากตารางต้นทาง ไม่ใช่การสร้างตารางหรือสำเนาข้อมูล การแก้แถวผ่าน View ยังแก้ข้อมูลต้นทาง และต้องผ่านสิทธิ์กับเงื่อนไขเดิม

การเลือก **ทุกคอลัมน์** จัดเก็บเป็นรายการคอลัมน์ว่างตามสัญญาเดิม หมายถึงใช้ทุกคอลัมน์ รวมคอลัมน์ที่เพิ่มในอนาคต การเลือก **กำหนดเอง** ต้องมีอย่างน้อยหนึ่งคอลัมน์ เพื่อไม่ให้เผลอบันทึกรายการว่างแล้วกลายเป็นทุกคอลัมน์

การซ่อนคอลัมน์ใน Slice ไม่ใช่การกำหนดสิทธิ์เข้าถึงข้อมูล และไม่ได้ยกเลิกช่องบังคับของตารางต้นทาง

## ตัวอย่างข้อมูลก่อนบันทึก

1. ตั้งตาราง เงื่อนไข และคอลัมน์
2. กด **ดูตัวอย่างข้อมูล** ได้แม้ยังไม่บันทึก Slice
3. ระบบอ่านครั้งละ 10 แถว ใช้รหัสแถวในการเปลี่ยนหน้า ไม่โหลดทั้งตารางมาที่เบราว์เซอร์
4. แสดงชื่อ Ref พร้อม ID และค่าคอลัมน์คำนวณ เลือกดูค่าจริงได้
5. เลือกคอลัมน์ตัวอย่างได้ไม่เกิน 8 ช่อง โดยมี ID แยกต่างหาก การเลือกนี้ไม่เปลี่ยนคอลัมน์ของ Slice
6. หากแก้การตั้งค่า ผลเดิมจะถูกระบุว่าเก่า และต้องกดอ่านใหม่ก่อนเปลี่ยนหน้าข้อมูล

ตัวอย่างเป็นการอ่านอย่างเดียว ไม่มีการสร้าง Slice หรือแก้แถวข้อมูล ไม่มีการแจ้งว่าบันทึกสำเร็จระหว่างอ่านตัวอย่าง แสดงเพียงการคำนวณที่จำเป็นสำหรับเงื่อนไขและคอลัมน์ตัวอย่าง ไม่โหลดรูปหรือไฟล์จริง

ตัวอย่างใช้สิทธิ์บัญชีผู้พัฒนาที่กำลังเข้าสู่ระบบ ไม่ใช่การจำลองบทบาทอื่น ผลของผู้ใช้แต่ละคนอาจแตกต่างกัน โดยเฉพาะสูตร USERID()/USEREMAIL() และสิทธิ์ระดับแถว

## การประเมินสูตรและประสิทธิภาพ

- ใช้ตัวตรวจสูตรและตัวคำนวณเดิม ไม่สร้างเครื่องคำนวณใหม่
- เงื่อนไขที่ตัวแปลง SQL เดิมรองรับ เช่น `[status] = 3` ใช้คำสั่งพร้อมพารามิเตอร์ และแสดงจำนวนที่ตรงเงื่อนไข
- สูตรอื่นใช้ตัวประเมินเดิมแบบแบ่งช่วง รอบละไม่เกิน 500 แถว มีงบเวลาประเมินประมาณ 300 มิลลิวินาที แล้วส่งตำแหน่งถัดไป
- หากช่วงแรกไม่พบข้อมูล แต่ยังตรวจไม่ครบ ระบบให้กดถัดไปได้ ไม่สรุปว่าไม่มีข้อมูลทั้งตาราง
- จำนวนที่ตรงเงื่อนไขของสูตรแบบแบ่งช่วงแสดงเป็นไม่ทราบจำนวนทั้งหมด ไม่ใช้จำนวนตัวอย่างแทนจำนวนจริง
- เวลา 300 มิลลิวินาทีเป็นงบระหว่างแถว ไม่ใช่เวลาตัดคำสั่งฐานข้อมูลหรือสูตรรายแถวแบบบังคับ สูตรที่ค้นข้ามหลายตารางอาจใช้เวลามากกว่านี้
- ตัวอย่างเป็นผลขณะอ่าน ไม่ล็อกข้อมูลตลอดการเปลี่ยนหน้า หากมีผู้ใช้อื่นแก้ข้อมูล ควรกดดูตัวอย่างใหม่

## ความปลอดภัยและพื้นที่พัฒนา

- เพิ่ม `POST /api/slices/preview` ผ่านการยืนยันตัวตนและการตรวจขอบเขตแอปเดิม ผู้ใช้ทั่วไปที่มีสิทธิ์อ่านตารางอย่างเดียวเรียกไม่ได้
- ตรวจตาราง คอลัมน์ สูตร และตำแหน่งข้อมูลที่ฝั่งเซิร์ฟเวอร์ ไม่รับ SQL จากเบราว์เซอร์
- ส่งเฉพาะ ID คอลัมน์ที่เลือก ผลชื่อ Ref และข้อผิดพลาดการคำนวณของคอลัมน์ตัวอย่าง
- ใช้บริบทพื้นที่พัฒนาเดิม ตัวอย่างในฉบับร่างอ่านฐานข้อมูลฉบับร่าง ไม่ย้ายข้อมูลกลับเวอร์ชันจริง
- ไม่เพิ่มโครงสร้างฐานข้อมูล ไม่เปลี่ยนการทำงานของ Action, Automation หรือการบันทึก Slice เดิม

## หลักฐานการตรวจ

ใช้ฐานข้อมูลทดสอบแยกทุกกรณี ไม่เปลี่ยนฐานข้อมูลจริงและไม่ได้ Deploy

| การตรวจ | ผลและหลักฐาน |
|---|---|
| ตรวจชนิดข้อมูล TypeScript | ผ่าน `.test-data/slices-ux-types.log` และการตรวจใน Build |
| Build สำหรับใช้งานจริง | ผ่าน `.test-data/slices-ux-build.log` |
| ชุดทดสอบพื้นฐาน | ผ่าน 646 ข้อ ข้าม 7 ข้อ จากทั้งหมด 653 ข้อ `.test-data/slices-ux-unit-final.log` |
| API และหน้าจอใหม่ในโหมดใช้งานจริง | ผ่าน `.test-data/slices-ux-production.log` ข้อมูลจำลอง 1,200 แถว ทดสอบจำนวน 400 แถวที่ตรงเงื่อนไข การเปลี่ยนหน้า สูตรคำนวณ การคัดลอก ย้อนกลับ ลบ และคอลัมน์ที่ View ใช้ |
| สิทธิ์และพื้นที่พัฒนา | ผ่านในชุดเดียวกัน ปฏิเสธผู้ไม่เข้าสู่ระบบและผู้ใช้ทั่วไป ตรวจตารางเฉพาะฉบับร่างไม่ปรากฏในเวอร์ชันจริง |
| การทำงานเดิมของ Slice/Excel/สิทธิ์ระดับแถว | ผ่าน `.test-data/slices-ux-runtime.log` รวมตาราง 20,003 แถว และสูตรแบบคำนวณ |
| การทำงานเดิมร่วมกับหน้า Action และ View | ผ่าน `.test-data/slices-ux-automation.log` สร้าง Slice ตรวจสูตร แหล่งข้อมูล View ยืนยัน Action บันทึกจากมือถือ ธีมมืด และความคงที่ของขนาดพรีวิว |

ภาพตรวจหน้าจอ: `artifacts/slices-desktop.png`, `artifacts/slices-mobile.png`, `artifacts/slices-mobile-dark.png`

รอบแรกของชุดพื้นฐานมีข้อทดสอบเดิมของเครื่องมือสร้างกุญแจ Push ไม่ผ่านหนึ่งข้อ (`.test-data/slices-ux-unit.log`) รันเฉพาะชุด Push และรันชุดพื้นฐานใหม่ผ่านทั้งคู่ (`.test-data/slices-ux-push-recheck.log`, `.test-data/slices-ux-unit-final.log`) ไม่ได้แก้โมดูล Push ในงานนี้

เครื่องมือ Next.js แจ้งคำเตือนความปลอดภัยของ Framework เดิมระหว่างรัน การตรวจครั้งนี้ไม่ได้อัปเกรด Dependency

## ขอบเขตที่ยังไม่ได้ทดสอบ

- ไม่ได้ทดสอบข้อมูลจริงของทุกแอป หรือสูตรเฉพาะทางทุกแบบ
- ตัวอย่างข้อมูลไม่ได้เป็นหน้าจอ CRUD ใหม่ การเพิ่ม/แก้ไข/ลบข้อมูลใช้ View และสิทธิ์เดิม

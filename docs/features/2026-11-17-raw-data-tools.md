# ค้นหา กรอง ส่งออก และอ่าน SQL ในข้อมูลจริง

วันที่: 17 พฤศจิกายน 2026

## เข้าใช้งาน

เปิด Data → ตาราง → ข้อมูลจริงในฐานข้อมูล ส่วนนี้เป็นเครื่องมือของผู้พัฒนาแอปที่มีสิทธิ์อ่านตาราง ไม่ใช่หน้ารายการสำหรับผู้ใช้ทั่วไป การเพิ่ม แก้ไข และลบยังผ่านระบบ CRUD เดิม ไม่ได้เปิดให้ SQL เขียนข้อมูลโดยตรง

## ค้นหาและตัวกรอง

- ค้นหาค่าจริงทุกคอลัมน์จากทั้งตาราง ไม่จำกัดเฉพาะหน้าที่เปิด
- เพิ่มเงื่อนไขได้สูงสุด 12 ข้อ เลือกคอลัมน์ ตัวเปรียบเทียบ และค่า แล้วกดใช้ตัวกรอง
- รองรับเท่ากับ ไม่เท่ากับ มีข้อความ ขึ้นต้น ลงท้าย มากกว่า น้อยกว่า ช่วงข้อมูล NULL และข้อความว่าง
- เลือกตรงทุกข้อ หรืออย่างน้อยหนึ่งข้อ และกำหนดคอลัมน์/ทิศทางเรียงลำดับได้
- NULL แยกจากข้อความว่าง ตัวกรองวันที่ใช้ข้อความที่จัดเก็บจริง จึงควรระบุรูปแบบเดียวกับข้อมูลต้นทาง
- เมื่อใช้ตัวกรองใหม่ ระบบกลับหน้าแรกและล้างแถวที่เลือก ป้องกันการแก้ไขรายการที่ไม่ได้เห็นหลังกรอง ส่วนการเลือกข้ามหน้าตามปกติยังทำได้
- ฝั่งเซิร์ฟเวอร์ตรวจชื่อคอลัมน์และตัวดำเนินการ แล้วส่งค่าเป็นพารามิเตอร์แยก ไม่ต่อค่าที่ผู้ใช้พิมพ์เป็นคำสั่ง SQL

## ส่งออกข้อมูล

เลือกทั้งตาราง ตามตัวกรองที่ใช้ หรือแถวที่เลือก ทั้งตารางและตามตัวกรองหมายถึงทุกหน้า ไม่ใช่เฉพาะข้อมูลที่กำลังแสดง สามารถเลือกคอลัมน์จริงที่จะส่งออกได้

| รูปแบบ | รายละเอียด |
|---|---|
| JSON | ข้อมูลเป็นรายการแถว รักษา NULL แยกจากข้อความว่าง จำนวนเต็มที่เกินขอบเขตแม่นยำของ JavaScript ส่งเป็นข้อความเพื่อรักษาตัวเลข |
| CSV | มีชื่อคอลัมน์และเครื่องหมาย UTF-8 สำหรับโปรแกรมตาราง ช่อง NULL และข้อความว่างใช้ช่องว่างเหมือนกัน ข้อความที่อาจถูกตีความเป็นสูตรจะเติมอัญประกาศเดี่ยวด้านหน้า |
| SQL | ไวยากรณ์ SQLite เลือกโครงสร้างและข้อมูล ข้อมูลอย่างเดียว หรือโครงสร้างอย่างเดียวได้ โครงสร้างต้องเลือกทุกคอลัมน์ รวมคำสั่งสร้างดัชนีที่มีคำสั่ง SQL กำกับ |

ส่งออกเฉพาะค่าที่จัดเก็บจริง ใช้ชื่อคอลัมน์ในระบบ Ref เป็น ID ไม่คำนวณคอลัมน์เสมือน และไม่รวมตัวไฟล์หรือรูปภาพที่ลิงก์อ้างถึง

ไฟล์ SQL นี้ไม่ใช่ MySQL และไม่ใช่ไฟล์สำรองแอป ไม่รวมการตั้งค่า View, Action, Automation, บทบาท, Trigger หรือ SQL View และไม่ได้รวมตารางแม่/ลูกให้อัตโนมัติ การนำเข้า SQL ไปฐานข้อมูลอื่นต้องเตรียมตารางอ้างอิงและส่วนขยายที่โครงสร้างใช้ให้เหมาะสม ระบบนี้ยังไม่มีปุ่มนำเข้า SQL เข้าแอปจริง

ใช้สิทธิ์ส่งออกเดิมของตาราง ซึ่งบางหน้าตั้งค่าใช้ชื่อ Excel โดยไม่เพิ่มสิทธิ์ชุดใหม่ เมื่อถอนสิทธิ์แล้วจะดาวน์โหลดงานที่สร้างไว้ไม่ได้ด้วย

## SQL สำหรับอ่านข้อมูล

กด SQL · อ่านข้อมูล จากตารางที่ต้องการ ตัวอย่าง:

```sql
SELECT status, COUNT(*) AS total
FROM t_inspection
GROUP BY status
ORDER BY total DESC
```

- SQL ทำงานในฐานข้อมูลสำเนาที่มีเพียงตารางปัจจุบัน ไม่มีบัญชีผู้ใช้ การตั้งค่าระบบ หรือตารางจากแอปอื่น
- เปิดฐานข้อมูลสำหรับอ่านอย่างเดียว และตรวจว่าคำสั่งเป็นคำสั่งอ่านข้อมูลก่อนประมวลผล
- รองรับ SELECT และ WITH แบบไม่วนซ้ำ พร้อมฟังก์ชันพื้นฐาน เช่น COUNT, SUM, AVG, MIN, MAX, ROUND, COALESCE และฟังก์ชันวันที่/ข้อความบางรายการ
- ไม่รองรับการเชื่อมข้ามตาราง คำสั่งเปลี่ยนข้อมูล/โครงสร้าง คำสั่ง PRAGMA หรือโหลดส่วนขยาย และจำกัดฟังก์ชันที่อาจสร้างข้อมูลขนาดใหญ่
- แสดงสูงสุด 500 แถว พร้อมแจ้งเมื่อมีข้อมูลเพิ่มเติม ผลลัพธ์รวมไม่เกิน 8 MB และชื่อคอลัมน์ผลลัพธ์ต้องไม่ซ้ำ ให้ตั้ง AS เมื่อต้องการแยกชื่อ
- ขั้นประมวลผล SQL ใช้โปรเซสแยก กำหนดเวลา 5 วินาทีแล้วหยุดโปรเซสได้จริง แม้ SQLite กำลังคำนวณใน native code และจำกัดหน่วยความจำ SQLite ของโปรเซส SQL ไว้ที่ 128 MB
- แสดงระยะเวลารวมหลังเตรียมสำเนา และมีประวัติ 5 คำสั่งล่าสุดเฉพาะหน้า ไม่เก็บข้อความ SQL ในประวัติส่วนกลางหรือพื้นที่เก็บถาวร
- ผู้มีสิทธิ์ส่งออกดาวน์โหลดผลลัพธ์ที่แสดงเป็น JSON ได้ ซึ่งมีเพดาน 500 แถวเช่นเดียวกับหน้าจอ หากต้องการทั้งตารางให้ใช้ส่งออกข้อมูล

## งานเบื้องหลังและขอบเขต

1. ตรวจสิทธิ์แอป ตาราง ผู้พัฒนา และสิทธิ์ส่งออกตามการทำงาน
2. ตรวจตัวกรอง คอลัมน์ รูปแบบไฟล์ ขนาดฐานข้อมูล พื้นที่ดิสก์ และจำนวนงาน
3. ใช้ SQLite backup สร้างสำเนาที่สอดคล้องกัน การเตรียมสำเนาเป็นงานแบบรอผลก่อนส่งหมายเลขงานกลับ เพื่อให้ฐานข้อมูลของพื้นที่พัฒนายังเปิดอยู่จนสำเนาเสร็จ
4. โปรเซสเบื้องหลังอ่านสำเนาและสร้างไฟล์ทีละแถว ไม่สร้างข้อมูลทั้งตารางเป็นอาร์เรย์ในหน่วยความจำของเว็บ สำหรับ SQL จัดเตรียมฐานข้อมูลอีกชุดที่มีเฉพาะตารางที่อนุญาตก่อนรันข้อความจากผู้ใช้
5. หน้าจอติดตามสถานะและจำนวนแถว เมื่อสำเร็จจึงเปิดดาวน์โหลด
6. งานผูกกับผู้สร้าง แอป ตาราง และพื้นที่พัฒนา ตรวจสิทธิ์ซ้ำตอนดูผลและดาวน์โหลด
7. ลบสำเนาฐานข้อมูลและคำสั่งชั่วคราวเมื่อจบงาน ไฟล์ผลลัพธ์หมดอายุภายใน 30 นาที และมีตัวตรวจล้างทุก 5 นาที รวมถึงหลังเริ่มเซิร์ฟเวอร์ใหม่

จำกัดพร้อมกันสูงสุด 4 งานทั้งโปรเซสเว็บ และ 2 งานต่อบัญชี เก็บงานต่อบัญชีไม่เกิน 20 งานในช่วงอายุไฟล์ งานรวมไม่เกิน 15 นาที ตารางไม่เกิน 1,000,000 แถว ไฟล์ส่งออกไม่เกิน 1 GB และฐานข้อมูลต้นทางไม่เกิน 2 GB ตรวจพื้นที่เผื่อก่อนเริ่มงาน

สถานะงานอยู่ในหน่วยความจำของโปรเซสเว็บ หากรีสตาร์ตเว็บ งานเดิมจะเปิดจากหน้าจอไม่ได้ ให้สร้างงานใหม่ ไฟล์ค้างยังถูกตรวจล้างตามอายุ ระบบนี้รองรับเซิร์ฟเวอร์เว็บหนึ่งโปรเซส หากจะขยายหลายเครื่องหรือหลายโปรเซส ต้องย้ายสถานะงานและคิวไปที่จัดเก็บร่วมกันก่อน

สำเนาภายในเริ่มจากทั้งฐานข้อมูล แม้ส่งออกเฉพาะตาราง จึงมีต้นทุนพื้นที่และเวลาตามขนาดฐานข้อมูลรวม สำเนาอยู่ในโฟลเดอร์ส่วนตัวนอก public ไม่มี API ดาวน์โหลดสำเนาหรือกำหนดชื่อไฟล์ตามผู้ใช้ ขั้นต่อไปที่อาจปรับปรุงได้คือสำเนาเฉพาะตาราง เพื่อลดต้นทุนเมื่อฐานข้อมูลรวมโตขึ้น

ผลลัพธ์เป็นข้อมูลจากสำเนา ไม่รวมการแก้ไขที่เกิดภายหลัง หน้าแสดงเวลาที่เตรียมสำเนาเสร็จ มีบันทึกการเริ่มส่งออกและอ่าน SQL ระบุเฉพาะการทำงาน/ตาราง ไม่บันทึกข้อความ SQL หรือค่าของข้อมูล

## จุดเชื่อมต่อในโค้ด

| ไฟล์ | หน้าที่ |
|---|---|
| lib/raw-query.ts | ตรวจและสร้างเงื่อนไข/ลำดับด้วยพารามิเตอร์ และตรวจขอบเขต SQL |
| lib/raw-data-jobs.ts | สิทธิ์ สำเนา ควบคุมงาน อายุไฟล์ และตรวจดาวน์โหลด |
| scripts/raw-data-worker.cjs | ส่งออกแบบอ่านทีละแถว และโปรเซส SQL ที่แยกจากเว็บ |
| app/api/tables/[name]/raw/route.ts | แสดงข้อมูลแบ่งหน้าตามตัวกรอง |
| app/api/tables/[name]/raw/jobs/route.ts | เริ่มงาน ดูสถานะ ดาวน์โหลด |
| app/components/RawDataTools.tsx | ตัวกรอง หน้าส่งออก และ SQL console |
| app/t/[table]/raw/page.tsx | เชื่อมกับการเลือกแถวและ CRUD เดิม |
| lib/auth-api.ts | แยกงานอ่าน/ส่งออกออกจากคำสั่งแก้โครงสร้าง เพื่อให้ตารางที่เชื่อมแบบอ่านอย่างเดียวใช้งานเครื่องมือได้ตามสิทธิ์ |
| instrumentation.ts | เริ่มตัวล้างไฟล์หมดอายุ |
| Dockerfile | รวมสคริปต์ worker ในอิมเมจใช้งานจริง |

ยังไม่ได้ทดสอบกับข้อมูลจริงบน production, Docker บน Linux, iPhone เครื่องจริง, ฐานข้อมูลเต็ม 2 GB หรือหนึ่งล้านแถว และยังไม่ได้ทดสอบเพดานพื้นที่/อายุไฟล์ด้วยการรอครบ 30 นาทีจริง ไม่ได้เปลี่ยนฐานข้อมูลจริง ติดตั้ง dependency หรือ Deploy

## ผลตรวจสุดท้ายและข้อสังเกตก่อนเผยแพร่

Build จบด้วยรหัสออก 0 และทดสอบ rawtools/rawdata ซ้ำกับชุด Build ล่าสุดผ่านทั้งสองชุด โดยใช้ฐานข้อมูลทดสอบคนละชุด ไม่ใช้ฐานข้อมูลจริง ตรวจภาพหน้าจอเดสก์ท็อปและมือถือจำลองหลังปรับพื้นที่ตารางแล้ว

ระหว่าง Build เครื่องมือ Next.js แจ้งเตือนความปลอดภัยของเวอร์ชันที่ติดตั้งเดิม รายงานนี้ไม่ได้ตรวจยืนยันรายละเอียดช่องโหว่หรืออัปเกรด dependency ควรแยกตรวจคำเตือนนี้ก่อน Deploy หลักฐานอยู่ใน .test-data/raw-tools-build.log

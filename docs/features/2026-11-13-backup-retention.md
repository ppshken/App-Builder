# การเก็บและล้างไฟล์สำรอง

## เป้าหมาย
ลดการสะสมของไฟล์สำรองทั้งระบบก่อนแก้โครงสร้าง โดยยังรักษาจุดกู้คืนสำคัญ ไม่แก้ข้อมูลจริงและไม่หยุดการสร้างสำรองเดิม

## วิธีใช้งาน
1. เปิด แอปของฉัน → การจัดการข้อมูลส่วนกลาง → สำรองทั้งระบบ
2. ดูจำนวนไฟล์และพื้นที่รวมในส่วน การเก็บไฟล์สำรอง
3. ค่าเริ่มต้น: ย้อนหลัง 7 วัน เก็บล่าสุดอย่างน้อย 3 ชุด และยังปิดการล้างอัตโนมัติ
4. หากต้องการทำครั้งเดียว กด ตรวจรายการที่จะล้าง ตรวจจำนวน/พื้นที่/ชื่อไฟล์ แล้วพิมพ์ “ล้างไฟล์สำรอง” เพื่อยืนยัน
5. หากต้องการทำต่อเนื่อง ติ๊กเปิดล้างอัตโนมัติแล้วบันทึกนโยบาย ระบบตรวจทุก 5 นาทีขณะเซิร์ฟเวอร์แอปทำงาน การบันทึกไม่ลบทันที
6. จำกัดจำนวนหรือพื้นที่ของไฟล์อัตโนมัติเพิ่มได้ ค่า 0 คือไม่จำกัด เพดานนี้อาจล้างไฟล์ที่ยังไม่ครบจำนวนวัน แต่ไม่ข้ามการป้องกันด้านล่าง

## ไฟล์ที่รักษาไว้
- ไฟล์สำรองด้วยตนเอง และไฟล์เดิมที่ระบุที่มาไม่ได้
- ชุดอัตโนมัติล่าสุดตามจำนวนที่ตั้ง อย่างน้อยหนึ่งชุด
- ชุดล่าสุดของแต่ละประเภท: ก่อนแก้โครงสร้าง ก่อนกู้คืน และก่อนอัปเดต
- ไฟล์ใน 10 นาทีล่าสุด เพื่อหลีกเลี่ยงไฟล์ที่กำลังสร้าง
- ระหว่างมีงานเผยแพร่โครงสร้าง ระบบพักการล้างทั้งรอบ

เพดานจำนวน/พื้นที่เป็นเพดานแบบยืดหยุ่น: หากเหลือเฉพาะไฟล์ที่ต้องรักษา ระบบจะแจ้งว่ายังเกินเพดานและไม่ฝืนลบ

## ขอบเขตและความปลอดภัย
- จัดการเฉพาะไฟล์ฐานข้อมูลสำรองที่ระบบรู้จักในโฟลเดอร์ backups ข้างฐานข้อมูล ไม่รวมไฟล์อัปโหลด สำรองแยกแอป พื้นที่พัฒนา แฟ้มกู้คืนชั่วคราว หรือสำรองจากสคริปต์ภายนอก
- ใช้สิทธิ์เจ้าของ Builder ตามระบบเดิม ตรวจการเข้าสู่ระบบและแหล่งที่มาของคำขอทุกครั้ง การเขียนจากฉบับร่างถูกปิดโดยกลไกเดิม
- ผู้ใช้ส่งเพียงรหัสตรวจรายการ ไม่ส่งเส้นทางไฟล์ที่ต้องการลบ
- รหัสยืนยันผูกผู้ใช้ หมดอายุใน 10 นาที ตรวจรายการและนโยบายซ้ำก่อนลบ หากเปลี่ยนต้องตรวจใหม่
- ตรวจว่าเป็นไฟล์จริง ไม่เป็นทางลัด และตรวจตัวระบุไฟล์ ขนาด และเวลาซ้ำก่อนลบ
- คำขอซ้ำด้วยรหัสเดิมคืนผลเดิม ไม่ลบซ้ำ บันทึกผลรายรอบและจำนวนไฟล์ที่ล้มเหลว/ข้าม
- การลบไฟล์ย้อนกลับไม่ได้ ไม่ใช้ธุรกรรมฐานข้อมูลมาอ้างว่าย้อนคืนไฟล์ที่ลบแล้วได้ หากลบบางไฟล์ไม่ได้จะรายงานผลบางส่วน

## การเก็บค่าตั้ง
นโยบาย รหัสตรวจรายการ และประวัติรอบล้างอยู่ใน .backup-management/retention.db ข้างฐานข้อมูล ไม่บรรจุใน Git หรืออิมเมจ Docker ต้องเก็บโฟลเดอร์ข้อมูลในโวลุ่มถาวรตาม Compose เดิม การกู้คืนฐานข้อมูลผ่านแอปไม่ย้อนนโยบายนี้ ส่วนการกู้คืนทั้งโวลุ่มอาจย้อนค่าด้วย

## ข้อจำกัด
- เมื่อแอปหยุดจะไม่มีรอบล้าง พอเริ่มใหม่จะเริ่มตรวจในรอบ 5 นาทีถัดไป
- ไม่ลดความถี่การสำรองเดิมและไม่รับประกันว่าจะไม่เต็มดิสก์: ไฟล์ที่ป้องกัน สำรองด้วยตนเอง และไฟล์นอกขอบเขตยังเพิ่มได้ ควรเฝ้าดูพื้นที่ว่างและสำรองนอกเครื่องด้วย
- รายการประวัติเผยแพร่เดิมอาจยังระบุชื่อสำรองที่หมดอายุแล้ว หลังล้างจะใช้ไฟล์นั้นกู้คืนไม่ได้
- การทดสอบใช้ข้อมูลและไฟล์จำลองแยกเท่านั้น ไม่ล้างสำรองจริงและไม่เปิดนโยบายจริงให้ผู้ใช้

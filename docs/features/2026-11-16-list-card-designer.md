# ออกแบบการ์ดรายการและแม่แบบใช้ซ้ำ

วันที่: 16 พฤศจิกายน 2026

## ขอบเขตระยะ 1–2

เพิ่มตัวออกแบบสำหรับการ์ดหนึ่งรายการใน View รูปแบบรายการ แล้วนำรูปแบบเดียวกันมาแสดงซ้ำกับข้อมูลแต่ละแถว ใช้ตัวออกแบบ Row, Column, Grid, กล่อง ข้อความ ตัวชี้วัด รูปภาพ ปุ่ม เส้นแบ่ง และช่องว่างของระบบเดิม

แม่แบบเป็นสำเนาแยกอิสระ เมื่อแก้การ์ดของ View หนึ่งจะไม่เปลี่ยน View อื่น ไม่มีการเชื่อมแม่แบบเพื่ออัปเดตทุก View พร้อมกันในรุ่นนี้

## วิธีใช้

1. เข้า View เลือกหน้าที่เป็นรายการ แล้วเปิดแท็บรูปแบบหน้าจอ
2. ในหัวข้อออกแบบการ์ดรายการ กดเปิดตัวออกแบบการ์ดรายการ
3. เลือกองค์ประกอบและเลือกข้อมูลจากคอลัมน์ หรือเขียนสูตรค่าที่แสดง กำหนดตำแหน่งด้วย Row/Column/Grid และลากย้ายองค์ประกอบระหว่างกล่อง
4. ปรับรูปแบบรูปภาพ ความสูง สัดส่วน ระยะห่าง สี ขอบ ตัวอักษร จำนวนบรรทัด และการจัดวางตามขนาดหน้าจอได้
5. เลือกข้อมูลตัวอย่างและกดดูตัวอย่างการ์ดจริง ข้อมูลตัวอย่างอ่านด้วยสิทธิ์บัญชีปัจจุบัน โหลดแบบแบ่งหน้าและใช้ไม่เกิน 5 แถว หากไม่มีข้อมูลจะแสดงข้อมูลจำลอง
6. กดใช้รูปแบบนี้ แล้วกดบันทึก View อีกครั้ง การยกเลิกหน้าตัวออกแบบไม่เปลี่ยนรูปแบบของ View

สลับกลับรูปแบบมาตรฐานได้ โดยเก็บรูปแบบการ์ดเดิมไว้เพื่อกลับมาใช้ใหม่ เมื่อเปลี่ยนชนิด View ออกจากรายการหรือย้ายเป็น Inline ตัวแก้ไขจะนำการตั้งค่าการ์ดออกจากฉบับที่กำลังแก้ เพื่อไม่ให้เกิดการตั้งค่าที่ใช้ไม่ได้

## ข้อมูลและปุ่ม

- สูตรอ้างอิงแถวที่กำลังแสดง เช่น [amount] หรือ IF([status] = "Open", "รอดำเนินการ", "เสร็จแล้ว")
- การเลือกคอลัมน์ตรง ๆ ใช้ตัวแสดงค่าของรายการเดิม เช่น วันที่ ทศนิยม Ref ผู้ใช้ และการตกแต่งข้อมูล
- เลือกแสดงรูปแบบเต็มกรอบหรือเต็มรูป และสัดส่วนภาพได้ รูปในรายการจริงใช้ตัวดูภาพเดิม รวมขอบเขตแอปของ PWA
- ปุ่มเปิดรายละเอียดใช้แถวปัจจุบัน ปุ่มเรียก Action ต้องเลือก Action ที่มีอยู่ในตารางเดียวกัน
- การเรียก Action ใช้เส้นทางเดิม รวมเงื่อนไข การยืนยัน สิทธิ์ตาราง สิทธิ์แถว การบันทึก และการรีเฟรชข้อมูล ไม่สร้างตัวประมวลผล Action ใหม่
- ปุ่มที่เรียก Action ไม่ได้จะถูกปิดใช้งาน การคลิกปุ่มไม่ทำให้เปิดรายละเอียดซ้ำ
- ปุ่มแก้ไขหรือการทำงานอื่นใช้ Action ที่มีอยู่ของตาราง หรือเปิดรายละเอียดแล้วใช้ปุ่มเดิมตามสิทธิ์
- การค้นหา Filter แท็บ Group By และ Pagination ยังเป็นของ View เดิม

## แม่แบบ

ในตัวออกแบบ ระบุชื่อแล้วกดบันทึกเป็นแม่แบบ คลังเก็บแยกตามแอป สูงสุด 20 แบบ ขนาดรวมไม่เกิน 300 KB แต่ละการ์ดไม่เกิน 40 องค์ประกอบและ 20 KB

เมื่อเลือกแม่แบบ ให้จับคู่คอลัมน์ต้นฉบับกับคอลัมน์ของตารางปลายทางก่อนใช้ สูตรจะเปลี่ยนเฉพาะชื่อคอลัมน์จริง ไม่เปลี่ยนข้อความที่อยู่ในเครื่องหมายคำพูด การสลับชื่อสองคอลัมน์ไม่ทับค่ากัน

Action เดิมจะถูกล้างเมื่อใช้แม่แบบ เพื่อให้เลือก Action ของตารางปลายทางใหม่ การลบแม่แบบมีหน้าต่างยืนยันและไม่ลบสำเนาที่ใช้ใน View ไปแล้ว

## โครงสร้างและการเชื่อมต่อ

- lib/list-card.ts: ตรวจรูปแบบการ์ด คอลัมน์ สูตร Action และจับคู่คอลัมน์
- lib/view-display.ts: เพิ่ม list_card และ list_card_enabled ในการตั้งค่า View รวมการติดตามการเปลี่ยนชื่อ/ลบคอลัมน์
- lib/view-projection.ts: รวมคอลัมน์ที่การ์ดและเงื่อนไขต้องใช้ในชุดโหลดข้อมูลเดิม ไม่เรียก API แยกต่อองค์ประกอบ
- app/components/CustomPageDesigner.tsx: เพิ่มโหมดการ์ดและตัวเลือกคอลัมน์บนตัวออกแบบเดิม
- app/components/CustomPage.tsx: แสดงค่าแถวและการตัดบรรทัด โดยคงโหมดหน้ากำหนดเองเดิม
- app/components/ListCard.tsx: แสดงการ์ดแต่ละแถวและส่งกลับการเรียก Action เดิม
- app/components/ListCardEditor.tsx: ออกแบบ พรีวิว คลังแม่แบบ และจับคู่คอลัมน์
- app/components/RuntimeTable.tsx: เลือกใช้การ์ดกำหนดเองเฉพาะ View รายการที่เปิดใช้
- app/api/list-card-templates/route.ts: อ่าน บันทึก คัดลอก และลบแม่แบบเฉพาะผู้พัฒนาแอป
- lib/schema.ts และ lib/settings-server.ts: เก็บคลังในคอลัมน์ list_card_templates_json ของการตั้งค่าแอป โดยไม่ส่งคลังทั้งหมดในข้อมูลตั้งค่าปกติ
- lib/draft-request.ts: อนุญาตคำสั่งแม่แบบในพื้นที่พัฒนาโดยยังเขียนลงฐานข้อมูลแยก
- lib/view-api.ts, lib/readiness.ts และ app/api/actions/route.ts: ตรวจการอ้างอิง Action และป้องกันการลบ/ย้าย Action ที่ View ใช้อยู่

การเก็บในค่าตั้งแอปและ display_json ของ View ใช้กลไกแยกแอป สำรอง กู้คืน และเวอร์ชันเดิม ไม่มีบริการใหม่หรือส่วนเสริมภายนอก การเริ่มระบบจะเพิ่มคอลัมน์การตั้งค่าผ่านกลไกอัปเกรดและสำรองเดิม พื้นที่ฉบับร่างเก่าที่ไม่มีคอลัมน์นี้จะอ่านคลังว่าง และเพิ่มคอลัมน์เฉพาะฐานข้อมูลฉบับร่างเมื่อบันทึกแม่แบบ

## ข้อจำกัดที่ตั้งใจไว้

- ยังไม่เปิดใช้กับ Inline ตามระยะถัดไป
- จัดวางด้วยกล่องและ Grid ที่ปรับตามจอ ยังไม่เป็นการวางพิกัดอิสระแบบกระดาษ PDF
- สูตรการ์ดใช้ข้อมูลแถวปัจจุบัน หากต้องดึงข้ามตารางหรือ Ref หลายชั้น ให้สร้างคอลัมน์คำนวณแล้วเลือกมาแสดง เพื่อใช้การโหลดและตรวจสิทธิ์เดิม ไม่เพิ่มการอ่านข้อมูลทีละการ์ด
- คลังยังแยกตามแอป ไม่มีแม่แบบส่วนกลางข้ามแอป และไม่มีแม่แบบเชื่อมที่เปลี่ยนทุก View พร้อมกัน
- ข้อมูลตัวอย่างเป็นภาพข้อมูลขณะเปิดตัวออกแบบ ไม่ใช่การติดตามการเปลี่ยนแปลงแบบสดภายในตัวออกแบบ

## การตรวจสอบ

- ก่อนพัฒนา: .test-data/list-card-red.log พบว่าการตั้งค่าการ์ดยังไม่ตรวจชนิดองค์ประกอบและคอลัมน์
- ทดสอบหน่วย: .test-data/list-card-unit.log รวม 644 ข้อ ผ่าน 637 ข้อ ข้าม 7 ข้อ ไม่มีข้อที่ล้มเหลว
- สร้างชุดเผยแพร่: .test-data/list-card-build.log ใช้ฐานข้อมูลทดสอบแยก
- ทดสอบการใช้งานจริง: tests/list-card-browser.cjs ครอบคลุมตัวออกแบบ พรีวิว บันทึก โหลดคอลัมน์ที่ใช้ Action รายแถว รูปแนวตั้ง เปิดรายละเอียด มือถือ สำเนาและจับคู่คอลัมน์ คลังแยกแอป สิทธิ์ผู้ใช้ และพื้นที่พัฒนา
- ทดสอบหน้ากำหนดเองและรูปแบบ View เดิมร่วมด้วย

ยังไม่ได้เผยแพร่ขึ้นเซิร์ฟเวอร์ ไม่แก้ฐานข้อมูลจริง และการทดสอบมือถือเป็นหน้าจอจำลอง ไม่ใช่ iPhone เครื่องจริง

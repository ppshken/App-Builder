# JSON คำขอและระยะเวลาในประวัติใช้งานแอป

วันที่: 17 พฤศจิกายน 2026

## การใช้งาน

เปิด แอปของฉัน → จัดการข้อมูลส่วนกลาง → ประวัติใช้งานแอป

- เพิ่มคอลัมน์ระยะเวลา แสดงเป็น ms หรือวินาทีตามขนาด
- เพิ่มคอลัมน์ JSON ที่ส่ง กดดู JSON เพื่อเปิดรายละเอียดแบบจัดย่อหน้า
- ใน JSON แสดงวิธีเรียก เช่น POST, พารามิเตอร์ใน URL และเนื้อหา JSON ของคำขอ
- คำขอที่สำเร็จและคำขอที่เกิดข้อผิดพลาดใช้การเก็บรายละเอียดแบบเดียวกัน ส่วนรายละเอียด Error เดิมยังแสดงแยกตามปกติ
- ประวัติเก่าไม่มีข้อมูลนี้ย้อนหลัง ระยะเวลาแสดงขีด และช่อง JSON แสดงว่าไม่มีข้อมูลเดิม

## ความหมายของเวลา

วัดด้วยนาฬิกาแบบเพิ่มต่อเนื่องของโปรเซสเซิร์ฟเวอร์ ตั้งแต่เริ่มจัดการคำขอจนได้ Response ในเส้นทางที่เก็บประวัติ ไม่ใช่เวลาเครือข่ายทั้งหมด ไม่รวมเวลาที่เบราว์เซอร์วาดหน้าจอหรือเวลาส่งไฟล์ให้ผู้ใช้จนเสร็จ

ถ้าคำขอเพียงส่งงาน Automation หรือส่งออกข้อมูลเข้าคิว เวลานี้เป็นเวลาของคำขอนั้น ไม่ใช่เวลาที่งานเบื้องหลังทำจนเสร็จ ให้ดูเวลางานจากประวัติ Automation หรือหน้าส่งออกประกอบ

รายการที่บันทึกจากงานภายในซึ่งไม่มีบริบทคำขอจะไม่มีค่าเวลาและ JSON แทนการสร้างค่า 0 ที่อาจทำให้เข้าใจผิด เมื่อใช้ฐานข้อมูลชั่วคราวที่ปิดไปก่อนจบคำขอ อาจคงเวลาที่จุดบันทึกประวัติไว้ การอัปเดตเวลาต้องผูกกับฐานข้อมูลที่บันทึกจริง ไม่ย้อนกลับไปเขียนอีกเวอร์ชัน

## การปิดบังและจำกัดข้อมูล

- ปิดบังชื่อฟิลด์ที่ระบุรหัสผ่าน โทเคน คีย์ลับ ข้อมูลรับรอง อีเมล โทรศัพท์ ลายเซ็น และ SQL
- ปิดบัง Bearer token, JWT บางรูปแบบ, อีเมลในข้อความ, ข้อมูลรับรองใน URL และพารามิเตอร์ลับที่รู้จัก
- ไม่อ่านหรือเก็บเนื้อหา multipart, รูปภาพ ไฟล์อัปโหลด หรือคำขอที่ไม่ใช่ JSON
- ไม่เก็บ HTTP headers, Cookie หรือ Authorization ของคำขอ
- อ่านสำเนา JSON เพื่อทำประวัติไม่เกิน 32 KB และรออ่านไม่เกิน 200 ms โดยไม่กิน body ที่ API เดิมต้องใช้
- ข้อมูลที่เก็บจริงหลังปิดบังไม่เกิน 8 KB ต่อรายการ ข้อความยาว รายการจำนวนมาก และข้อมูลซ้อนลึกจะถูกจำกัด พร้อมข้อความแจ้งเมื่อไม่เก็บเนื้อหา
- การปิดบังอาศัยชื่อฟิลด์และรูปแบบข้อมูลที่รู้จัก ไม่ควรส่งรหัสผ่านหรือข้อมูลลับผ่านชื่อคอลัมน์ทั่วไป เช่น หมายเหตุ เพราะไม่สามารถจำแนกข้อมูลลับทุกรูปแบบได้

ใช้สิทธิ์เจ้าของ Builder สำหรับหน้าและ API ประวัติส่วนกลางเหมือนเดิม ผู้ใช้ทั่วไปและผู้พัฒนาแอปที่ไม่มีสิทธิ์ส่วนกลางไม่สามารถเปิดดูรายละเอียดนี้ได้

ยังใช้ช่วงเก็บประวัติเดิมจาก NOCODE_USAGE_RETENTION_DAYS ซึ่งค่าตั้งต้น 180 วัน การเก็บ JSON เพิ่มขนาดฐานข้อมูลตามจำนวนคำขอ ควรกำหนดระยะเวลาเก็บตามนโยบายและปริมาณการใช้งาน

## ขอบเขตประวัติ

เพิ่มรายละเอียดให้เหตุการณ์ที่ระบบมีการบันทึกอยู่แล้ว เช่น เพิ่ม/แก้ไข/ลบข้อมูล เรียก Action นำเข้า/ส่งออก อัปโหลด เข้าสู่ระบบ ออกจากระบบ และเหตุการณ์ภายในที่บันทึกผ่านตัวช่วยประวัติ ไม่ได้เปลี่ยนให้ทุก HTTP request กลายเป็นประวัติใหม่

รายการที่ถูกปฏิเสธก่อนเข้าสู่จุดบันทึกประวัติเดิมอาจไม่มีรายการใหม่ ไม่ได้เพิ่มระบบ access log ของ reverse proxy ในงานนี้

## โครงสร้างและการอัปเกรด

- เพิ่ม request_json ในตารางประวัติ โดยค่าตั้งต้นเป็นข้อความว่าง
- เพิ่ม duration_ms โดยค่าตั้งต้นเป็น NULL
- ใช้กลไกสำรองและอัปเกรดโครงสร้างเดิมก่อนเพิ่มคอลัมน์เมื่อเริ่มระบบรุ่นใหม่ ไม่ลบหรือคำนวณข้อมูลประวัติเก่าย้อนหลัง
- เพิ่มบริบทคำขอแบบแยกกันต่อคำขอ เพื่อไม่ให้ JSON หรือเวลาปะปนระหว่างผู้ใช้
- ใช้ prepared statement ที่ผูกกับฐานข้อมูลต้นทางในการปรับเวลา ป้องกันฐานข้อมูลฉบับร่างถูกสลับไปใช้เวอร์ชันจริงหลังจบขอบเขตคำขอ
- หากเก็บรายละเอียดไม่ได้ ให้คำขอเดิมทำงานต่อ ไม่ทำให้การทำงานหลักล้มเหลวเพราะอ่านสำเนา body ไม่ได้

## ไฟล์ที่เกี่ยวข้อง

| ไฟล์ | หน้าที่ |
|---|---|
| lib/app-usage.ts | อ่านสำเนาคำขอ ปิดบัง จำกัดขนาด บริบทคำขอ และบันทึกเวลา |
| lib/auth-api.ts | ครอบ API ที่มีสิทธิ์ด้วยบริบทประวัติ |
| app/api/auth/login/route.ts และ logout/route.ts | เพิ่มบริบทให้เส้นทางเข้าสู่ระบบและออกจากระบบ |
| lib/audit-schema.ts, lib/schema.ts และ lib/db.ts | โครงสร้างใหม่ การตรวจอัปเกรด และรุ่นโครงสร้าง |
| app/apps/AppOperationsManager.tsx และ usage-history.css | คอลัมน์เวลาและรายละเอียด JSON |
| tests/app-operations.test.cjs | ทดสอบปิดบัง ขนาด การอ่าน body เวลา อัปเกรด และแยกฐานข้อมูล |
| tests/usage-request-browser.cjs | ทดสอบ API และหน้าจอจริงกับฐานข้อมูลจำลอง |

# งานซ้อมอัปเดตเบื้องหลังและการจัดการงานค้าง

วันที่: 12 พฤศจิกายน 2569

อัปเดต 13 พฤศจิกายน 2569: เพิ่มทางเผยแพร่โครงสร้างที่รองรับในระยะ 4 แล้ว ข้อจำกัดของรุ่นเดิมในเอกสารนี้ยังเป็นประวัติและขอบเขตทางเดิม ดู [การเผยแพร่โครงสร้างเพิ่ม](2026-11-13-additive-publication.md)

## สิ่งที่เปลี่ยน

ปุ่มซ้อมอัปเดตในหน้าเวอร์ชั่นแอปใช้คิวถาวรและ process แยกจากเว็บแล้ว จึงไม่รอคำนวณทุกแถวภายในคำขอ HTTP และไม่ใช้ worker ของ Automation มารันงาน SQLite ที่อาจกั้นการตอบสนองของเว็บ

ยังใช้ตัวซ้อมเดิม ตัวตรวจสูตร ตัวตรวจเงื่อนไขข้อมูล และตัวนำการตั้งค่าเดิม การเปลี่ยนครั้งนี้ไม่เปิดเผยแพร่โครงสร้างจริง

## การใช้งาน

1. เปิดเวอร์ชั่นแอปและตรวจพื้นที่พัฒนาโครงสร้าง
2. กดซ้อมอัปเดต ระบบคืนสถานะรอคิวโดยไม่รอทั้งงาน
3. หน้าจอแสดงขั้นตอน จำนวนที่ประมวลผล และความคืบหน้า พร้อมปุ่มยกเลิก
4. ปิดหน้าแล้วกลับมาดูงานล่าสุดได้ งานไม่ผูกกับการเปิดแท็บค้างไว้
5. งานที่ถูกยกเลิกหรือหยุดกลางทางไม่ถือว่าผ่าน ให้ตรวจแผนและเริ่มใหม่

เมื่อเปลี่ยนพื้นที่ หน้าจอหยุดติดตามพื้นที่เก่า การดึงสถานะที่มีปัญหาเครือข่ายจะลองใหม่ ส่วนงานที่จบแล้วหยุดดึงสถานะต่อเนื่อง

## ขีดจำกัดรุ่นนี้

| รายการ | ค่าที่กำหนด |
|---|---|
| งานที่รันพร้อมกัน | หนึ่งงานต่อไฟล์คิวของฐานต้นทาง |
| คิวรวมที่ยังไม่จบ | ไม่เกิน 20 งาน |
| งานซ้ำของพื้นที่และผู้สั่งเดียวกัน | คืนงานเดิมขณะรอหรือกำลังทำ ถ้าแผนต่างกันให้รอหรือยกเลิกก่อน |
| จำนวนแถวตรวจรวม | สูงสุด 1,000,000 แถวของตารางภายในที่แอปอ่านได้ |
| งบเวลางาน | 15 นาที ตรวจตามขั้นตอนและระหว่างแถว |
| เวลาที่ supervisor อนุญาตให้ child อยู่ | ประมาณ 16 นาที ก่อนสั่งหยุดเมื่อสังเกตพบ |
| ขนาดฐานต้นทาง | ไม่เกิน 2 GB ตรวจจากจำนวนหน้า SQLite |
| พื้นที่ว่างก่อนเริ่ม | อย่างน้อยสองเท่าของขนาดฐานต้นทาง บวก 64 MB |
| หน่วยความจำส่วน JavaScript ของ child | กำหนดเพดาน heap 512 MB ไม่รวมหน่วยความจำ native ทั้งหมด |
| งานรอคิวหมดอายุ | หนึ่งชั่วโมง |
| สิทธิ์ถือครองงาน | 90 วินาที ต่ออายุโดย supervisor ระหว่างที่ควบคุม child |

หนึ่งล้านแถวเป็นเพดานป้องกันทรัพยากร ไม่ใช่ผลรับรองความเร็วบนข้อมูลหนึ่งล้านแถวหรือทุกความซับซ้อนของสูตร การตรวจสูตรข้ามตารางอาจใช้เวลาหรือหน่วยความจำจนงานหยุดได้ โดยแยกผลกระทบออกจาก process เว็บ

## โครงสร้างและจุดเชื่อม

- `lib/rehearsal-jobs.ts`: สถานะคิว SQLite แยก การจองงานแบบธุรกรรม การกันงานซ้ำ การยกเลิก และการเก็บกวาด
- `lib/rehearsal-supervisor.ts`: เริ่ม child ติดตามการยกเลิก ต่ออายุสิทธิ์ถือครอง และสรุปงานที่ child หยุดผิดปกติ
- `lib/rehearsal-worker-entry.ts`: ตรวจบัญชีและสิทธิ์ผู้พัฒนาใหม่ก่อนรัน เปิดฐานต้นทางแบบอ่านอย่างเดียว และเรียกตัวซ้อมเดิม
- `lib/rehearsal-job-api.ts`: เชื่อมคิวกับบริบทแอปและเจ้าของพื้นที่
- `lib/releases.ts`, `lib/release-rehearsal.ts`: เพิ่มตัวควบคุมงาน การรายงานความคืบหน้า และงบแถว/เวลาที่กำหนดจากเซิร์ฟเวอร์
- `app/components/ReleaseRehearsalJobsPanel.tsx`: ติดตามสถานะและยกเลิกงานจากหน้าจอ
- `app/api/releases/route.ts`: ใช้ระบบยืนยันตัวตน สิทธิ์ และ CSRF เดิม

เพิ่มคำสั่ง `queue_rehearsal`, `cancel_rehearsal` และการอ่าน `GET /api/releases?id=…&job=1` ไม่รับ SQL ค่าแถว หรือเส้นทางไฟล์จาก Client

เก็บคิวที่ `.app-releases/rehearsal-jobs.db` ใกล้ฐานต้นทาง ไม่เพิ่มตารางคิวลงฐานข้อมูลแอปจริง ไฟล์อยู่ในพื้นที่ข้อมูลเดียวกับสำเนา จึงต้องคงพื้นที่นี้เมื่อสร้าง Container ใหม่

## การยกเลิกและงานหยุดกลางทาง

- ยกเลิกงานรอคิวได้ทันที
- งานที่เริ่มแล้วตรวจคำสั่งหยุดตามจุดตรวจ รวมถึงระหว่างการสำเนาแบบแบ่งหน้า
- หาก child อยู่ในคำสั่งต่อเนื่อง supervisor สามารถสั่งหยุด process ได้ และรอ child จบก่อนจัดการไฟล์ที่ยังเปิดอยู่
- สถานะยกเลิกมีผลเหนือผลสำเร็จที่ส่งกลับพร้อมกัน ไม่บันทึกผลสำเร็จแทนการยกเลิก
- เมื่อ child หยุดผิดปกติ ระบบบันทึกสถานะหยุดกลางทางและเก็บกวาดสำเนาของงานนั้น
- เมื่อ supervisor หายไป คิวไม่ถูกลืม หลังสิทธิ์ถือครองหมดอายุ supervisor ที่กลับมาทำงานจะตรวจงานค้างเป็นหยุดกลางทาง ไม่มีการนับว่าเสร็จและไม่ต่อการทำงานจากครึ่งทางโดยอัตโนมัติ
- รหัสถือครองแต่ละรอบป้องกัน worker เก่าส่งผลทับสถานะงานที่ถูกเปลี่ยนไปแล้ว
- การลบไฟล์ตรวจรหัสแอป รหัสพื้นที่ และรหัสงานก่อน ลบได้เฉพาะโฟลเดอร์ `rehearsal-<รหัสงาน>` ไม่ขยายไปลบพื้นที่พัฒนาหรือฐานต้นทาง ถ้าลบไม่ได้เก็บสถานะไว้เพื่อลองใหม่

## ความปลอดภัยและความหมายของผล

ฐานต้นทางเปิดด้วย `readonly` และ `fileMustExist` ใน child จึงไม่เรียกการย้ายโครงสร้างฐานจริงจากตัวเปิดฐานข้อมูลปกติ การใช้การตั้งค่าและ DDL เกิดในฐานซ้อมที่ยืนยันแล้วเท่านั้น พร้อมข้อจำกัดเครือข่าย ไฟล์ และงานจริงจากพื้นที่พัฒนาเดิม

สถานะที่คืนให้ Client ไม่มีรหัสถือครอง PID หรือค่าข้อมูลแถว ผลมีเฉพาะรายละเอียดงาน ชื่อตาราง จำนวน และรหัสตรวจ เงื่อนไขเริ่มงานตรวจแผนอีกครั้งใน worker และตรวจสิทธิ์ใหม่ ไม่ใช้สิทธิ์ที่ Client ส่งมา

**ผลเป็นของสำเนาในช่วงที่สร้างสำเนา ไม่ยืนยันว่าข้อมูลจริงยังเหมือนเดิมขณะอ่านรายงาน** หน้าจอระบุข้อจำกัดนี้ชัดเจน และแจ้งผลเก่าเมื่อแผนเปลี่ยนหรือผลหมดอายุ ไม่ย้ายการสแกนข้อมูลหนึ่งล้านแถวกลับไปอยู่ในคำขออ่านสถานะ ขั้นเผยแพร่จริงในระยะ 4 ยังต้องตรวจข้อมูลล่าสุดและสิทธิ์อีกครั้งก่อน commit

คำสั่งซ้อมแบบเดิมยังคงอยู่เพื่อความเข้ากันได้และการทดสอบย้อนหลัง โดยยังจำกัด 2,000 แถว/งบเวลาเดิม ส่วนปุ่มปกติใช้คิวใหม่

## การ Build และ Docker

`npm run build` และ `npm run dev` สร้าง JavaScript ของ worker ด้วย TypeScript ที่มีในโครงการอยู่แล้ว ไม่ติดตั้ง dependency ใหม่ ไฟล์ที่สร้างอยู่ใน `.rehearsal-worker` และไม่รวมใน Git

Dockerfile คัดลอกผล Build ของ worker ไป runtime ก่อนตัด dependency สำหรับพัฒนา จึงไม่ต้องมี TypeScript compiler ขณะรันงานจริง หากไม่พบ worker ที่ Build แล้ว API จะปฏิเสธการเริ่มงานแทนการแอบรันบน process เว็บ

รอบนี้ตรวจ Production Build บนเครื่องพัฒนาแล้ว แต่ยังไม่ได้สร้างหรือรัน Docker image บน Linux/VPS

## สิ่งที่ยังไม่ทดสอบหรือยังไม่รองรับ

- ยังไม่ได้วัดการตรวจครบหนึ่งล้านแถว สูตรหนักทุกแบบ หรือเพดาน 2 GB
- ยังไม่ได้ทดสอบปิดเครื่องหรือ restart Docker จริง กรณีงานกำพร้าเป็น fixture และการหยุด process เป็นการหยุด child ในการทดสอบ
- ยังไม่ได้ทดสอบหลาย Container ที่ใช้ PID namespace ต่างกัน หรือระบบไฟล์เครือข่าย คิวรุ่นนี้ใช้ SQLite และ process บน host เดียว
- ยังไม่มีการเก็บกวาดประวัติรายงานเก่าอัตโนมัติ การเก็บกวาดในรุ่นนี้เน้นฐานซ้อมที่มีข้อมูลธุรกิจ
- ไม่รับรองการหยุดทุก native operation ในเวลาแน่นอน supervisor ต้องมีโอกาสทำงานจึงจะสั่งหยุดและจัดการไฟล์ได้
- ยังไม่ได้ทดสอบการถอนสิทธิ์กลางงานร่วมกับการกู้ทั้งระบบ สิทธิ์เริ่มงานและสิทธิ์เรียก API ใช้กลไกเดิม ส่วนการเผยแพร่จริงยังปิดอยู่

## ลำดับถัดไป

ระยะ 4: เพิ่มตัวเผยแพร่จริงสำหรับการเพิ่มโครงสร้างที่รองรับ พร้อมสำรอง ล็อกและบันทึกสถานะข้าม process ตรวจข้อมูลล่าสุดก่อน commit และป้องกันการเผยแพร่ซ้ำ งานนี้ยังไม่เปิดส่วนดังกล่าว

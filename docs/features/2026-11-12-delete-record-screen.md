# แก้หน้ารายการแสดงซ้อนหลังลบข้อมูล

## สาเหตุที่ยืนยันได้

- การเปิดแถวด้วย View ตารางและพารามิเตอร์ row ทำให้เป็นหน้ารายละเอียดได้ แต่เงื่อนไขย้อนกลับหลังลบเดิมตรวจเฉพาะชนิด View detail และ form จึงไม่ย้อนกลับสำหรับกรณีนี้
- เมื่ออ่านแถวที่ไม่มีแล้ว ระบบล้างรายละเอียดและแสดงข้อผิดพลาด แต่ส่วนรายการในคอมโพเนนต์เดียวกันกลับแสดงขึ้นมาได้ หากมีรายการพื้นหลังอยู่จึงเห็นซ้ำ
- เส้นทาง Action ลบเดิมล้างรายละเอียดและแจ้งรีเฟรชก่อนย้อนกลับ ต่างจากปุ่มลบมาตรฐาน

## การแก้ไข

- หลังลบสำเร็จ หน้าที่ระบุ row จะตั้งสถานะออกจากหน้า แจ้งข้อมูลเปลี่ยน แล้วกลับก่อน ไม่ล้างรายละเอียดเป็นหน้ารายการระหว่างรอ
- ใช้วิธีเดียวกันกับ Action ที่ตอบว่าลบแถวแล้ว พร้อมยกเลิกแคชแถวนั้น
- เมื่อเปิดลิงก์แถวที่ไม่มีแล้ว แสดงข้อผิดพลาดในกรอบหน้ารายละเอียดพร้อมปุ่มกลับ ไม่แสดงรายการอีกชุด
- ไม่เปลี่ยน API การลบ สิทธิ์ เงื่อนไขลบตาม Ref หรือฐานข้อมูลจริง

## หลักฐานก่อนแก้

- .test-data/delete-layout-before.log: กรณี View ตารางพร้อม row ลบแล้ว URL ยังมี row=3 แทนที่จะกลับรายการ
- .test-data/delete-layout-missing-before.log: เปิดแถวที่ไม่มีแล้วไม่พบกรอบหน้ารายละเอียด

## ชุดทดสอบ

ไฟล์ tests/delete-layout-browser.cjs และโหมด deletelayout ใน scripts/integration.cjs ใช้ฐานข้อมูลจำลองแยก ตรวจลบแถวสุดท้ายด้วยปุ่มมาตรฐาน, Action ลบ, View ตารางพร้อม row และเปิดลิงก์แถวที่ไม่มี ตรวจจำนวนแถบค้นหา การกลับ URL และข้อมูลคงเหลือใน API

## ข้อจำกัด

ทดสอบบน Edge อัตโนมัติ ไม่ใช่การทดสอบบน iPhone จริง และยังไม่ได้ Deploy

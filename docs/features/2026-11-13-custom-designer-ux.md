# ปรับพื้นที่ออกแบบและพรีวิวหน้ากำหนดเอง

## ปัญหาที่ตรวจพบ
1. โครงสร้างอยู่ท้ายรายการองค์ประกอบและแผงแคบ ทำให้ค้นหาองค์ประกอบซ้อนยาก
2. แผงตั้งค่ารวมทุกอย่างไว้ยาวโดยไม่แบ่งหมวด
3. เนื้อหาหน้ากำหนดเองจำกัดกว้าง 1,200 พิกเซลและจัดกึ่งกลาง จอใหญ่จึงมีช่องว่างซ้าย–ขวา
4. ปุ่มพรีวิวเดิมปิดตัวออกแบบกลับไปพื้นที่พรีวิวตามขนาดเดิม ทำให้ไม่ได้เห็นผลแบบเต็มจอทันที
5. บนมือถือ กฎจัดวางแผงองค์ประกอบทับกฎซ่อนแท็บ ทำให้แผงแสดงค้างขณะเลือกแท็บตั้งค่า

## สิ่งที่ปรับ
- ย้ายโครงสร้างขึ้นด้านบน แยกพื้นที่เลื่อนจากคลังองค์ประกอบ ขยายแผงซ้ายเป็น 260 พิกเซลและแผงตั้งค่าเป็น 320 พิกเซลบนจอใหญ่
- แบ่งตั้งค่าหน้าจอเป็นหมวดขนาดและระยะห่าง การจัดเรียง และพื้นหลัง ยุบแต่ละหมวดได้
- เพิ่มขนาดพื้นที่ออกแบบ “เต็มพื้นที่ · ตามขนาดหน้าต่าง” คำนวณตามพื้นที่ทำงานที่เหลือหลังหักแผงตั้งค่า ไม่ใช่การบันทึกขนาดหน้าจอผู้พัฒนาลงแอป
- เพิ่มความกว้างเนื้อหา “เต็มพื้นที่หน้าจอ” หรือ “จำกัดความกว้าง” ทั้งในตัวออกแบบและแท็บรูปแบบหน้าจอ
- หน้าใหม่จากค่าเริ่มต้นใช้เต็มพื้นที่ ส่วนหน้าที่บันทึกเดิมยังรักษาข้อจำกัดความกว้างเดิมจนกว่าจะเลือกเปลี่ยน
- เมื่อเปลี่ยนกลับเป็นจำกัดความกว้าง ค่าความกว้างเดิมยังอยู่
- พรีวิวจากตัวออกแบบเปิดเต็มจอตามขนาดหน้าต่างจริงทั้งมือถือและคอมพิวเตอร์ ใช้ข้อมูลฉบับร่างผ่านพรีวิวเดิม และมีปุ่มกลับไปออกแบบ ไม่เปิดระบบพรีวิวหรือระบบข้อมูลใหม่
- มือถือแสดงเฉพาะแผงของแท็บที่เลือก

พื้นที่สีเทารอบกรอบมือถือในตัวออกแบบเป็นพื้นที่เลื่อนและซูม ไม่ใช่ระยะขอบของแอปจริง หากต้องการชิดขอบในเนื้อหา ให้เลือกเต็มพื้นที่และตั้งระยะขอบเป็น 0

## จุดเชื่อมต่อ
- lib/custom-page.ts: รายการชนิดองค์ประกอบ แบบข้อมูล และการตรวจค่าของหน้ากำหนดเอง
- app/components/CustomPage.tsx: ตัวแสดงหน้าร่วมกันระหว่างออกแบบและใช้งานจริง
- app/components/CustomPageDesigner.tsx: โครงสร้าง คลังองค์ประกอบ พื้นที่เลื่อน/ซูม และแผงตั้งค่า
- app/components/CustomPageDisplayEditor.tsx: การตั้งค่ารูปแบบหน้าจอภายนอกตัวออกแบบ
- app/components/DesignerPreview.tsx และ app/views/page.tsx: เปิดพรีวิวเต็มจอและกลับไปออกแบบ
- app/components/custom-page.css: การจัดวางหน้าจอและแผงตามขนาดอุปกรณ์

## ตรวจองค์ประกอบที่มีอยู่จริง
รายการองค์ประกอบปัจจุบัน 11 ชนิด: ข้อมูลจาก View, ฟอร์ม, ตัวชี้วัด, แนวตั้ง, แนวนอน, กล่อง, ข้อความ, รูปภาพ, ปุ่ม, เส้นแบ่ง และช่องว่าง

ข้อมูลจาก View ฝังตาราง รายการ กราฟ แผนที่ และปฏิทินได้อยู่แล้ว จึงไม่จำเป็นต้องสร้างองค์ประกอบซ้ำแยกสำหรับทุกประเภท ฟอร์มปัจจุบันเป็นปุ่มเปิดฟอร์มจริงพร้อมค่าตั้งต้น ไม่ใช่การวางช่องกรอกอิสระภายในหน้ากำหนดเอง

องค์ประกอบรองรับสูตรแสดงค่า เงื่อนไขแสดง การจัดตามอุปกรณ์ และปุ่มเรียกการทำงานเดิมตามชนิดที่กำหนด การดึงสูตรและการเปิดข้อมูลยังใช้สิทธิ์ระบบเดิม

## องค์ประกอบที่เพิ่มได้และลำดับเสนอ
| องค์ประกอบ | แนวทางใช้โครงสร้างเดิม | ข้อควรตรวจ | ลำดับ |
|---|---|---|---|
| ไอคอนเดี่ยว | ใช้ตัวเลือกไอคอนและตัวแสดงไอคอนเดิม เพิ่มขนาด สี และพื้นหลัง | ตรวจชื่อไอคอนจากรายการที่ระบบรองรับ | 1 |
| ป้ายสถานะ | ใช้ข้อความหรือสูตรเดิม เพิ่มรูปแบบชิปและสีสถานะ | แสดงข้อความเป็นข้อความธรรมดาและตรวจสี | 1 |
| แถบความคืบหน้า | ใช้การผูกสูตรเดิมสำหรับค่าและค่าสูงสุด | ตรวจตัวเลข ค่าว่าง และค่าสูงสุดเป็นศูนย์ พร้อมชื่อสำหรับโปรแกรมอ่านหน้าจอ | 1 |
| ส่วนพับ/ขยาย | ต่อจากกล่องและองค์ประกอบลูก เก็บสถานะเปิดเฉพาะหน้าจอ | ตรวจชนิดที่รับลูกและแป้นพิมพ์ ไม่เปลี่ยนสิทธิ์ข้อมูล | 2 |
| แท็บเนื้อหา | ต่อจากกล่องลูกและตัวควบคุมแท็บธีมเดิม | ต้องกำหนดแท็บเริ่มต้น การย้ายลูก และการโหลดเฉพาะส่วนที่จำเป็น | 2 |
| รายการซ้ำจากข้อมูล | ใช้แหล่งข้อมูลและตัวแสดงแถวเดิมพร้อมรูปแบบรายการ | ต้องแบ่งหน้า จำกัดจำนวน ตรวจสิทธิ์ระดับแถว และผูกสูตรกับบริบทแต่ละแถว | 3 |

ทั้งหมดนี้เป็นข้อเสนอ ยังไม่เพิ่มชนิดองค์ประกอบใหม่ในรอบนี้ องค์ประกอบใหม่ต้องเพิ่มให้ครบทั้งรายการชนิด แบบข้อมูล การตรวจค่าฝั่งเซิร์ฟเวอร์ แผงตั้งค่า ตัวแสดงผล และการทดสอบ ไม่ใช่เพิ่มปุ่มในคลังอย่างเดียว

ยังไม่แนะนำองค์ประกอบที่รับโค้ดสคริปต์หรือ HTML อิสระ เพราะต้องออกแบบการแยกสิทธิ์และการป้องกันโค้ดอันตรายเพิ่มเติม

## ผลทดสอบรอบสุดท้าย
- ชุดทดสอบหลัก: ผ่าน 601 ข้อ ล้มเหลว 0 ข้อ ข้าม 7 ข้อ รวม 608 ข้อ
- การสร้างรุ่นใช้งานจริงและตรวจชนิดข้อมูลผ่าน
- การทดสอบหน้าจอที่ปรับ การพรีวิวฉบับร่างโดยไม่บันทึก และพรีวิวตามขนาดหน้าต่างจริงผ่าน ทั้งคอมพิวเตอร์และมือถือ
- การทดสอบซูม เลื่อนพื้นที่ โครงสร้าง ประวัติแก้ไข และการบันทึกผ่าน
- การทดสอบรูปแบบหน้าจอ พรีวิว การรีเซ็ตและรักษาเนื้อหาเดิมผ่าน
- ชุดรุ่นสองเดิมยังไม่ผ่านจากการตรวจสีที่ระบุข้างต้น ไม่รวมเป็นผลผ่านและไม่ได้เปลี่ยนค่าคาดหวัง
- ไม่ได้ทดสอบ Safari บนเครื่อง iPhone จริงในรอบนี้ การทดสอบมือถือใช้เบราว์เซอร์ที่ปรับขนาดหน้าต่าง

## แก้กรอบเลือกองค์ประกอบบนกระดาษ
อาการ: คลิกกล่องบนกระดาษแล้วเลือกได้ แต่ไม่เห็นกรอบ

สาเหตุที่ยืนยัน: กล่องเป็นองค์ประกอบที่รับโฟกัสได้ เมื่อคลิกจะติดสถานะเลือกและรับโฟกัสพร้อมกัน แต่กฎกลางใน app/globals.css ซ่อน outline ของตัวควบคุมด้วย !important ทำให้ outline ของสถานะเลือกหายไป ผลทดสอบก่อนแก้แสดงว่าเลือกกล่องแล้วจริง แต่ค่า outline-style ขณะรับโฟกัสเป็น none

ปรับเฉพาะกรอบเลือกใน app/components/custom-page.css เป็นเส้นด้านในด้วยองค์ประกอบตกแต่ง ::after แยกจาก outline ของโฟกัส เส้นอยู่เหนือเนื้อหา ไม่ดันขนาดกล่อง ไม่ขวางการคลิกหรือลาก และไม่ถูกตัดออกเมื่อกล่องชิดขอบกระดาษ

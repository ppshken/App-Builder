# Automation Designer

ปรับหน้า `/workflows` ให้จัดการ Automation ผ่านแผนผังขั้นตอนและแผงตั้งค่า โดยใช้สี ฟอนต์ และช่องกรอกของ Builder เดิม รองรับหน้าจอเล็กและโหมดมืด

## การใช้งาน

1. เลือก Automation จากกลุ่มตารางด้านซ้าย
2. เลือกโหนด **เมื่อไหร่** แล้วกดปุ่มเหตุการณ์ที่มีไอคอนและชื่อ: สั่งทำงานเอง เพิ่ม แก้ไข ลบ หรือตามเวลา
3. เหตุการณ์แก้ไขข้อมูลแสดง **คอลัมน์ที่เฝ้าดู** เป็นรายการแนวตั้ง เลือกได้หลายคอลัมน์ โดยไม่รวมคอลัมน์เสมือน
4. เลือกโหนด **ถ้า · เงื่อนไข** เพื่อกำหนดสูตรก่อนเริ่มขั้นตอน
5. เพิ่มขั้นตอน Action, Webhook/API หรือ PDF จากแถบใต้แผนผัง เลือกโหนดเพื่อตั้งค่า เลื่อนลำดับ หรือลบขั้นตอน
6. กดช่องสูตรเพื่อเปิดตัวช่วยเขียนสูตรเดิม มีคอลัมน์ ตารางอ้างอิง จัดรูปแบบ ตรวจสูตร และลองคำนวณ กดยกเลิกจะไม่เปลี่ยนสูตร กดใช้สูตรจะเปลี่ยนฉบับร่างก่อนกดบันทึก Automation

เดสก์ท็อปแสดงแผนผังและแผงตั้งค่าคู่กัน หน้าจอแคบวางแผงตั้งค่าใต้แผนผัง การเลื่อนแนวนอนจำกัดอยู่ในแผนผัง

## ขอบเขตและความเข้ากันได้

- ยังคงเป็นลำดับเชิงเส้น: เหตุการณ์ → เงื่อนไข → ขั้นตอนตามลำดับ สูงสุด 10 ขั้นตอน
- ยังไม่มีการลากเส้นสร้างแขนง การวนซ้ำ หรือการรันแบบกราฟ DAG
- ใช้ Workflow schema, API, execution mode, permission checks, simulation และระบบบันทึกเดิม ไม่เปลี่ยนฐานข้อมูล
- การเลือกโหนดไม่ทำให้ฉบับร่างมีการแก้ไข การสลับ Automation ยังคงใช้การยืนยันก่อนทิ้งการแก้ไข
- ตัวช่วยสูตรเพิ่ม `resultType="any"` เฉพาะสูตรทั่วไป เช่น Webhook payload เพื่อแสดงผล array/number ได้ การตรวจชนิดของผู้เรียกเดิมยังใช้ค่าเริ่มต้น `column`
- ไม่เปลี่ยนงาน AUD-002 และ AUD-003 ที่พักไว้

## ไฟล์หลัก

- `app/workflows/page.tsx`: เชื่อมฉบับร่าง การเลือกโหนด และแบบฟอร์มตั้งค่าเดิม
- `app/workflows/workflows.css`: รูปแบบที่จำกัดขอบเขตเฉพาะหน้า Automation
- `app/components/WorkflowCanvas.tsx`: โหนด เส้นเชื่อม และปุ่มเพิ่มขั้นตอน
- `app/components/WorkflowFormula.tsx`: ช่องเปิด modal สูตร
- `app/components/ExpressionAssistant.tsx`: ตัวเลือกผลลัพธ์สูตรทั่วไปแบบ opt-in
- `tests/workflow-designer-browser.cjs`: ทดสอบหน้าใหม่ผ่านเบราว์เซอร์และตรวจค่าที่บันทึกจริง

## การตรวจสอบ

ใช้ฐานข้อมูล SQLite จำลองใหม่ทุกครั้งผ่าน `node scripts/integration.cjs <mode>` ไม่ใช้ฐานข้อมูลจริงและไม่เรียก Webhook ภายนอกจริง

| Mode | ผล | ขอบเขต |
| --- | --- | --- |
| `workflowdesigner` | Passed | ปุ่มเหตุการณ์ รายการคอลัมน์แนวตั้ง modal ยกเลิก/ใช้/ตรวจสูตร ผลลัพธ์ array เพิ่ม/ย้าย/ลบขั้นตอน บันทึกและโหลดใหม่ หน้าจอ 390px โหมดมืด |
| `workflowgroups` | Passed | กลุ่มตาราง จำนวน สถานะ เปิด/ปิดกลุ่ม และเลือกรายการ |
| `parentaction` | Passed | ตั้งค่าและเรียก Action ที่เกี่ยวกับข้อมูลแม่ รวมตัวเลือกใน UI |
| `workflows` | Passed | Workflow API/เบราว์เซอร์, PDF, Webhook จำลอง, events, queued actions, resume/idempotency และสิทธิ์ |
| `formulaeditor` | Failed — ปัญหาเดิม | assertion ความสูง editor `<150px` ได้ 152px ทั้งสำเนาก่อนปรับและหลังปรับ ไม่ได้แก้ assertion หรือ CSS ส่วนกลางเพื่อให้ผ่าน |

หลักฐาน log อยู่ใน `.test-data/workflow-designer/`: `browser-verified.log`, `groups.log`, `parent-action.log`, `workflows.log`, `formula-editor.log`, `formula-baseline.log` ส่วนภาพหน้าจออยู่ใน `artifacts/workflow-designer-*.png`

สำเนา baseline ใช้โค้ดก่อนแก้ `page.tsx` และ `ExpressionAssistant.tsx` พร้อม CSS เดิม ไม่มีการคัดลอกไฟล์ environment หรือฐานข้อมูลจริง ผล geometry ของสูตรเดิม: line-height 18.85px, editor height 152px

### ข้อจำกัดที่ยังไม่ได้ทดสอบ

- ไม่ได้ทดสอบบน iPhone/Safari เครื่องจริง การตรวจหน้าจอเล็กใช้ Chromium ที่ความกว้าง 390px
- ไม่ได้ทดสอบ workflow production หรือ credentials ของบริการภายนอก
- สูตรที่ยาวมากยังใช้พฤติกรรมความสูงของ FormulaEditor เดิม ประเด็นนี้แยกจากการปรับ Automation

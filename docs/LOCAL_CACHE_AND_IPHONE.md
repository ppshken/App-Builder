# แคชในเครื่องและการตรวจ iPhone

เพิ่ม IndexedDB สำหรับผลอ่านผ่าน runtimeJSON เท่านั้น ไม่เก็บคำขอเขียนหรือส่งบันทึกซ้ำอัตโนมัติ ข้อมูลมีอายุสูงสุด 15 วินาที จำกัด 100 รายการและไม่เก็บรายการที่ใหญ่กว่า 250,000 ตัวอักษร แยกตาม session ของแท็บ ผู้ใช้ สิทธิ์ การตั้งค่าผู้ใช้ บัญชี Preview และ workspace

เมื่อบันทึก จะล้าง IndexedDB ก่อนส่งคำขอ เมื่อโหลดใหม่ด้วยปุ่มรีโหลด ออกจากระบบ หรือ metadata เปลี่ยน จะล้างแคชด้วย คำขอที่เริ่มก่อนการล้างจะไม่เขียนผลเก่ากลับเข้าแคช หาก storage ถูกปิดหรือเต็มจะกลับไปใช้เครือข่าย ข้อผิดพลาด 401/403 ไม่ใช้ข้อมูลหมดอายุแทน

ขอบเขต: เป็นแคชอ่านที่มีอายุสั้น ไม่ใช่ offline/sync เต็มระบบ ฟอร์มและการบันทึกยังตรวจจากเซิร์ฟเวอร์ ตารางที่โหลดโดยตรงยังแบ่งหน้าจากเซิร์ฟเวอร์เหมือนเดิม

## ผลทดสอบอัตโนมัติ

- IndexedDB จริงใน Chromium: ใช้แคชข้ามการสร้าง memory cache ใหม่ แยกผู้ใช้และฉบับร่าง ล้างแคช หมดอายุ การปฏิเสธสิทธิ์ จำกัดขนาด และ fallback เมื่อไม่มี IndexedDB
- Mobile touch emulation: เปิดรายละเอียดขณะ API ค้าง กดปิดและ Back คง pagination และตำแหน่งเลื่อน ตรวจตำแหน่ง header ทุกเฟรมที่เก็บได้
- ผลวัด navigation: artifacts/mobile-navigation-check.json เป็นสภาพแวดล้อมทดสอบ ไม่ใช่ FPS จาก iPhone จริง

## ยังต้องตรวจบน iPhone จริง

1. Chrome และ Safari: เปิด/ปิดรายละเอียดซ้ำ 20 ครั้ง ทั้งรายการสั้นและรายการที่มีรูปภาพ ตรวจ header และ pagination
2. เลื่อนรายการลงลึก เปิดรายละเอียด ปิดกลับ ตรวจตำแหน่งเดิมและการตอบสนองการสัมผัส
3. เพิ่ม/แก้ไข/ลบรายการลูก ตรวจรายการแม่ Ref และการอัปเดต Automation
4. เน็ตช้า/หลุดระหว่างบันทึก: ค่าฟอร์มต้องอยู่ ไม่ส่งซ้ำเอง และเตือนว่าต้องตรวจผลก่อนลองใหม่
5. ออกจากระบบแล้วเข้าบัญชีอื่น รวมถึง Preview และฉบับร่าง ต้องไม่เห็นข้อมูลบัญชีก่อนหน้า
6. Private Browsing/พื้นที่เก็บข้อมูลจำกัด: แอพต้องทำงานผ่านเครือข่ายต่อได้

สถานะ iPhone จริง: ยังไม่ได้ทดสอบ และเครื่องพัฒนาไม่มี WebKit runtime ติดตั้งอยู่
